01

从科学计算 Python 到模型基础设施

Would a company trust open-source software with business-critical work? When Paige Bailey began doing machine learning around 2009–2010, that was still a live question. Her contributions to NumPy, SciPy, Matplotlib, and scikit-learn connected scientific computing to practical engineering. With a background spanning geophysics, applied mathematics, computer science, and carbonate geology, she worked at Chevron on velocity modeling, drilling optimization, and large-scale computation using Cloudera and Spark.

Geoscience also gave her experience with CUDA before she began contributing to TensorFlow. Bailey recalls work separating CPU, GPU, and TPU execution paths, including single-node and distributed computation. Her recollection that the initial public release supported only CPUs conflicts with the TensorFlow launch announcement, which already described desktop GPU training. Open-source work led to Google, followed by a period at GitHub working on VS Code and early Copilot user-experience testing, then a return to the original PaLM 2, Gemini, and Gemma teams.

Public contributions serve two purposes: they let an engineer discover whether a team is worth joining, and they make the engineer’s work discoverable. An audience member’s project, with 700 GitHub stars, supplies a small example of that second effect.

02

哪些约束能熬过下一代模型？

A harder product question follows: what happens when a model absorbs the capability around which an application was built? Bailey points to early 8,000- and 16,000-token context windows as a reason developers rushed toward vector databases. Longer contexts changed that constraint; broader multilingual support similarly reduced some demand for language-specific fine-tunes. She predicts that models may absorb more agent-framework behavior, describes a shift toward Markdown-based skills, and imagines activity listeners that create those skills automatically. These are expectations about where the platform is going, rather than reasons to assume retrieval, frameworks, or MCP have ceased to matter.

An audience member challenges that view with bioinformatics: specialized work may remain outside a general model provider’s priorities. Bailey responds with MedLM and Med-PaLM, saying that some users who previously needed medical fine-tunes now use Gemini with retrieval or custom prompts, and attributes that transition to medical training material entering the general model. The audience then raises reproducibility. 用显式引用取代隐式的图像历史

Vernade asks for dark fantasy, with black-and-white backgrounds and colored characters. These constraints address an earlier tendency to turn portrait illustrations into book covers. An adult-only instruction left over from an earlier regional restriction is now obsolete. A separate image chat generates Mole, Water Rat, Toad, and Badger, then illustrates chapter scenes: a riverside picnic, a road scene, and a forest. In the forest illustration, Toad no longer matches the earlier portrait.

The repair changes the data contract. Each chapter now includes a name, a prompt, and an explicit list of characters. The application uses that list to attach only the relevant character reference images. The Python structure below expresses that selection step: the chapter record determines the image inputs, rather than leaving the model to locate them in an expanding conversation.

```python from pathlib import Path from pydantic import BaseModel

class Chapter(BaseModel): name: str prompt: str characters: list[str]

def select_references( chapter: Chapter, portraits: dict[str, Path], ) -> list[Path]: missing = set(chapter.characters) - portraits.keys() if missing: raise ValueError(f"Missing character portraits: {sorted(missing)}") return [portraits[name] for name in dict.fromkeys(chapter.characters)] ```

This makes missing references visible before generation and avoids repeatedly sending unrelated portraits. Vernade argues that relying on complete history becomes increasingly fragile as the cast grows. For a larger production, he would create front, back, and side views and select the view needed for each scene. In the revised demonstration, Toad matches the intended character.

The E2B and E4B models target phones, Raspberry Pis, and Jetson-class devices. Their effective size reflects per-layer embeddings that can remain on flash and be paged in when needed. Ballantyne describes roughly 2B and 4B effective cores, versus roughly 5B and 8B when the embeddings are included in RAM. The larger options are 26B A4B, a mixture-of-experts model, and a 31B dense model. Active parameters describe computation per token; they do not mean only the active weights need storage. Precision, quantization, context allocation, and available memory determine whether a larger model fits a laptop, desktop, or single GPU.

Thinking is configurable, and the workshop lineup supports image and video understanding; audio input is limited to the two effective models. Ballantyne describes performance in the range of models ten times larger, but supplies no task, comparator, or benchmark for that claim. His more concrete comparison is the capability mix: Gemma 2 emphasized creative writing, while Gemma 3 and Gemma 4 broadened coding, function calling, and action selection.
