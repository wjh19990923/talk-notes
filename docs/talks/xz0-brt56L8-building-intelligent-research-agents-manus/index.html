用 Manus 构建智能研究智能体

Ivan Leo 一步步构建了一个由 Manus 驱动的 Slack 机器人，把异步任务、上传的文件、webhook 和对话状态，与一个以 Notion 中的报销政策为依据的收据工作流连接起来。

具备基础 Python、HTTP 请求、环境变量和 webhook 概念，有助于理解集成示例。

01

一个通用智能体实际上做些什么？

What does Manus actually do when its product description spans answers, applications and automated workflows? The practical test in Ivan Leo’s workshop is to reproduce its Slack bot: receive a request where someone already works, let an agent execute it, and bring the result back into the conversation.

That requires more than a model call. Leo reports that Manus handles millions of conversations daily, bringing infrastructure, sandboxes and reliability into the foreground. The interface is only the entry point to that machinery.

The available entry points include web and mobile applications, Slack, an API, a browser operator and Mail Manus. Leo also introduces a recently launched Microsoft 365 integration, while describing the envisioned Word, PowerPoint and Excel workflows partly as future capabilities. Four demonstrations establish what these surfaces can do before the workshop turns to Python.

02

一本边写边教你法语的日记

Leo has been learning French and wants a way to practice throughout the day. He asks Manus to build a phone-friendly journal where an ordinary thought—such as being stressed about the workshop—becomes language practice. The application identifies mistakes inline, supplies a complete corrected version, and lets him ask about an unfamiliar word such as défi.

The application combines model calls with an interface designed around the task. Leo describes built-in support for structured outputs, transcription with Whisper, and the model calls behind the corrections and vocabulary tutor. The displayed journal keeps the original writing, corrections and explanation together, so the learner can inspect the change without leaving the entry.

External providers can join the same application. Leo adds ElevenLabs for speech and plays a French rendering of the idea that life is lived forward but understood backward. As he uses the app, it also builds a learner profile: an agent builder at Manus, comfortable tackling abstract ideas but struggling with expressions involving distance and time. He built the application with Manus 1.5 by prompting it between conference talks.

An audience question establishes where that profile comes from: Leo explicitly requested it in the application prompt. It is application behavior, rather than a demonstrated account-wide memory setting. Personal facts and grammatical gender help the app handle French agreement and suggest relevant daily writing topics.

03

通过邮件和一个已登录的浏览器进行委派

Mail Manus offers another way to hand off work: forward or reply to an email from the phone. The live example stalls because screen sharing appears to disable keyboard input, so Leo moves to the browser operator. He asks for a simple coffee near the New York venue after his journey from Singapore, specifying that an Americano would do.

The browser’s existing session is part of the useful context. A browser on the user’s computer may already be signed into LinkedIn, Instagram or other services that a separate sandbox browser cannot immediately access. The initial coffee request does not choose the intended browser, so Leo explicitly asks Manus to use his browser. After a delay, a Google Maps tab appears on his computer.

Leo suggests extending this pattern to parallel browser instances or a scheduled daily task on a dedicated Mac mini. These are automation possibilities arising from the demonstration; browser selection and authorization through the API receive a more specific qualification in the closing questions.

04

把会议页面变成个人日程

The next application starts with a discovery problem: a conference has many events, and Leo wants to understand which ones to attend. He asks Manus to open individual event pages, scrape their contents, save the results as JSON, and load that data into a new website. Its brutalist styling takes inspiration from Chroma’s website.

Opening the event “2026, the year the IDE died” reveals its scraped description, a Google Calendar action and related events, including MCode and AGI: The Path Forward. Leo supplies a Chroma API key and an OpenAI key for embeddings to support similar-event discovery. Starring events builds a personal daily timeline, which he uses to find talks by Will Brown and Applied Compute. The workflow joins data collection, retrieval and a purpose-built interface.

The runtime matters when that interface needs backend behavior. Leo describes a full Docker image in which packages can be installed, including Redis with BullMQ for queued work. The Stripe integration configures webhooks that the application can receive and test. Autoscaling and warm deployments are future work in this presentation.

This reduces the number of separate assembly steps in a small application: writing the site, setting up Chroma, connecting a coding tool such as Claude Code, and selecting a deployment destination. The general agent can work across those steps while the developer supplies the desired behavior and external credentials.

05

建立 API 连接

The API exposes an agent with its own per-chat sandbox, access to configured services such as Notion, and custom MCP integrations. Manus uses it for its public Slack bot, Zapier and n8n integrations, and internal support workflows that inspect conversations in a browser and produce reports with screenshots. Leo says the same query costs the same through the API and web chat under the account’s billing.

The workshop proceeds through five notebooks, with README screenshots for obtaining Slack credentials. Copy the required values from .env.example into .env: a Manus API key, a Slack bot token and a Slack signing secret. The first check lists uploaded files. On the fresh account, an empty list confirms that the authenticated request succeeds without requiring a task to run.

Leo says Files API uploads are automatically deleted after 48 hours. He also discusses explicit deletion and says the session must be deleted for the file to be gone. That explanation does not establish a complete deletion policy for conversations and derived artifacts; uploaded-file expiration and session deletion need to be treated as separate lifecycle concerns.

06

创建一个任务并保留它的身份

Leo uses direct Python HTTP requests and mentions support for the OpenAI Responses SDK. The recording uses the historical v1 API; the current Manus documentation identifies v2 as its successor and v1 as deprecated. The task states and request behavior below follow the workshop rather than substituting today’s API contract.

The first prompt asks for a brief answer to two plus two. Creation returns a task ID, a task title and a task URL. The ID is the durable handle for the conversation: when Manus needs clarification, or the user wants to revise the result, a follow-up can target the same task.
