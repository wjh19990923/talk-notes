用浏览器管理的本地模型做评论摘要

Leplus next moves AI from developer tooling into the application itself. Rather than sending every feature request to a remote provider, browser-native AI APIs can expose a model running locally on the user’s machine. The demonstrated family includes summarization, writing, rewriting, and general prompting, but support is experimental and depends on the browser and its configuration. 23:24 23:45 23:55 24:06

The first application feature condenses Seine’s customer reviews using the Chrome Summarizer API. Its setup has several independent choices:

- Availability: Check whether this browser exposes Summarizer before creating a session. 24:19 24:35 24:43 24:54 - Shape and length: Choose key points, a short overview, a teaser, or a headline, and set the desired length. 25:09 25:20 - Language and context: Specify expected input and output languages, then explain that the supplied data contains product reviews. 25:30 25:38

A download monitor tracks whether the underlying model must first be installed. Leplus says the demonstrated model occupies approximately four gigabytes, is downloaded once and shared across websites, and can be removed by Chrome if device storage becomes constrained. Local inference therefore avoids a remote inference request in this example, but it still depends on browser support, an initial model download, adequate device storage, and local compute. 26:04 26:13 26:27

After setup, the application passes the review data to the summarizer and renders the returned summary. Because the model is already present on Leplus’s machine, the download indicator jumps immediately from zero to complete, and the interface produces a summary mentioning the headphones’ sound quality and battery life. 26:35 26:48 27:00 27:14

The demonstrated setup also requires enabling relevant Chrome flags for the Gemini-backed APIs. Chrome’s on-device internals provide a separate inspection surface for loading models, experimenting with image or audio inputs, adjusting generation settings such as top-k and temperature, reviewing event logs, and inspecting token usage associated with individual API calls. Can Seine generate a product-review title and description directly from an uploaded photograph? Lasorsa turns to the general-purpose Chrome Prompt API, rather than the preceding task-specific summarizer and proofreader. He creates a browser language-model session configured for text and images, then prepares instructions asking the model to describe the product’s condition and imagine how its recipient felt. 30:17 30:35 30:48 31:02 31:16

The written instructions and uploaded image are combined in a single user message passed to session.prompt. To make the response usable by the application, Lasorsa constrains it with a plain JSON Schema describing an object with two string-valued properties: 31:30 31:41 31:56 32:08 32:23

``json { "type": "object", "properties": { "title": { "type": "string" }, "description": { "type": "string" } } } ``

Those structured values can populate the review form directly. 32:37

Lasorsa uploads a headphone photograph and initially says the headphones appear to be in good shape. A warning then indicates that he has not specified the request language. Nevertheless, the model returns JSON describing a devastatingly damaged, broken headset and a disappointed recipient, and Seine fills its review fields with that generated assessment. The contradiction matters: the returned text is the model’s interpretation, not verified evidence that the headphones were actually damaged. 32:50 33:04 33:27 33:39 33:50

The demonstrated inference runs locally on the client inside the browser, without an external model request for each call.
