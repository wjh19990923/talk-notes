AX 才是唯一重要的体验

智能体工具需要的不只是易读的文档和 API：它们还需要能让智能体准备资源、运行实验、完成任务，而无需人来修补工作流的环境。

熟悉 API、Docker 镜像和隔离的代码执行环境，有助于理解基础设施示例。

01

当人离开循环时会发生什么？

如果智能体成了开发者工具最大的用户群，这些工具应该是什么样子？Ivan Burazin 开场抛出一个有意带点猜想色彩的预测：智能体的数量，可能相当于人类数量的 N 次方。N 是多少，他也不知道。这个比喻背后有一个实际的观察：人们已经在同时使用好几个智能体，而智能体还能再启动更多智能体。

Burazin 引用了两个数字：25% 的 YC 创业公司说，AI 写了他们 95% 的代码；当时最新一期 YC 中，有 37% 的公司在把智能体当作产品来做。这两个数字都注明了出处，但演讲没有交代调查方法，也没有经过独立核实的样本。后一个数字说明的变化很关键：智能体正在自己成为产品，而不只是嵌在现有软件里的自动补全和 copilot。

这就带来一个具体的工具问题。有人在旁边处理那些别扭的步骤时，工作流看上去是完整的；人一走开，它就断了。如果操作这些工具的开发者变成了智能体，产品就必须把智能体当作直接用户来支持。只为屏幕后的人做设计，对人的这层依赖就始终解决不了。

02

访问、理解和操作

智能体体验（agent experience，简称 AX）把人们熟悉的用户体验、客户体验和开发者体验延伸到了智能体身上。Burazin 说这个词是 Netlify 联合创始人 Matt 提出的，而他采用的定义出自 Netlify 的 Sean。Netlify 关于 AX 的讨论给出了更完整的背景：为了完成用户设定的目标，智能体访问、理解并操作数字环境，到底有多容易？

第一道障碍是身份认证。智能体去完成一项任务，可能卡在登录页面上；可把用户密码直接交给它，也不是好办法。Burazin 用 Arcade 说明一种交接方式：智能体请求授权，用户登录，智能体接着往下做。他举的 Delta 和 Booking.com 只是示例，不代表已经有确定的集成。授权也可以在任务开始前就准备好。值得借鉴的做法是把用户授权和智能体执行分开；不过保留下来的授权仍然可能过期，用户也可能撤销。

再往上一层是文档。Burazin 以 Stripe 为例：在文档 URL 后面加上 .md，就能拿到干净的 Markdown。去掉页面排版上的杂乱内容，智能体更容易读懂底层的说明。他还推荐了 llms.txt 提案，并以这次大会的网站为例。目的很简单：让智能体需要的信息好找、好读。

说明写得再清楚，对应的操作调不了也没用。API 优先设计通过机器接口开放功能，让智能体能高效调用。MCP 前景如何，Burazin 没有下定论；他的观点是，底层操作无论如何都需要 API。他点名了 Neon、Netlify 和 Supabase，据他所知，这几个服务都开放了智能体所需的关键功能。

03

缺失的那个词是“自主地”

支持身份认证、文档易读、提供 API，这些都让访问变得更顺畅。但定义就此完整了吗？Burazin 在每一部分前面都加了一个词：智能体应该自主地访问、理解并操作它所在的环境。设计问题随之变了：不再是智能体能不能完成单个操作，而是它能不能把任务做完。

认证交接正好说明了边界在哪里。它能让智能体继续往下走，但一个反复回头找人的工作流，仍然离不开有人在场。设想一下，没人去点下一个按钮，也没人去调试报错。这些中断点，正是工具开发者还有活要干的地方。

Burazin 借 swyx 的一个质疑来讲清这个区别：swyx 认为 AX 不过是给开发者体验换了个包装。如果产品只是让熟悉的开发者操作更好调用，这个批评就站得住。他给出的区别在于自主完成任务：环境还得处理那些原本需要开发者介入的步骤。

04

一个给智能体用的计算环境

基础设施方面的例子，来自 Burazin 亲历的几代开发者工具。他最早做的是实体数据中心和机房：装服务器、布线、用光盘安装 Windows Server。2009 年，他做出了据他说是第一个基于浏览器的 IDE。那是个早期尝试，编排和隔离都得自己定制。后来，他在 Infobip 负责开发者体验，这家通信平台通过 API 提供邮件、短信和语音服务。

在 Daytona，他又和以前公司的老同事聚到了一起，还顺带建议创始人尽量和信得过的前同事共事。新产品的定位是运行 AI 生成代码的安全、弹性基础设施：一个围绕沙箱构建的智能体运行时。

这些沙箱提供计算环境，可以用来执行代码、做数据分析、做强化学习、做 computer use，甚至让智能体玩 Counter-Strike 这样的游戏。可以拿笔记本电脑来类比：人用笔记本干活，智能体用运行时干活。要搭出这样的环境，就得把 AX 原则落实成具体的基础设施行为。

05

快速启动和无头工具

第一个要求是速度。人通过 Claude 或 ChatGPT 和智能体交互时，工具启动的时间就算进了他的等待时间。Burazin 称 Daytona 运行时的启动时间约为 27 毫秒，但没有给出基准测试条件。有了 API，智能体还能自己启动、停止、克隆和删除机器。

机器跑起来之后，智能体还需要在里面有趁手的操作。Daytona 预装了一批无界面（headless）工具：文件浏览器、Git 客户端、语言服务器协议工具和终端。这样智能体就不必每做一步都去解读终端输出。启动快、操作可调用，最初的 AX 定义基本就满足了。

剩下的缺口，是客户的工作流暴露出来的：智能体会走到某一步，没有人帮忙就进行不下去。由此做出的功能，是在示范怎样发现缺失的能力，而不是每个工具都该照抄的通用清单。每个功能都始于一项智能体差一点就能完成的任务。

06

让智能体申请它需要的环境

Daytona 沙箱可以从现有的 Docker 镜像启动。智能体如果还需要别的依赖，可以通过终端 API 安装。比如加一个 Python 数据分析包，只需要一行：

``bash python -m pip install pandas ``

这能解决某一个运行中环境缺包的问题。可如果依赖很多、环境一个接一个地开，每次都重复这一套，就既费时间又费资源。

传统的补救办法会引入另一套工作流：人来构建镜像，发布到容器镜像仓库，再提供给智能体。让智能体自己管理整套构建和发布流程，可以去掉显式的人工交接，但 Burazin 说这样做又慢又脆弱。环境配置的问题依然存在。

声明式镜像构建器把这些工作藏到了一个更简单的请求背后。智能体说明自己需要什么，基础设施负责构建并启动：

1. 选一个基础镜像。 2. 声明要安装的依赖和要运行的命令。 3. 让 Daytona 构建镜像，并基于它打开一个沙箱。

拿前面装包的例子来说，pandas 成了所请求环境的一部分，不再是每次启动后都要重做的补救。智能体想要新东西，直接申请就能拿到可用的环境，不必等别人在外面把镜像准备好。

07

数据集上传一次，在需要的地方挂载

开发者在笔记本上跑几个容器，它们共享同一个本地上下文。笔记本上的一个大数据集，可以同时提供给多个环境。远程、相互隔离的智能体沙箱，天然就没有这种共享存储。Burazin 提到，有客户需要在每台机器里都放大约 100 GB 的数据。每个环境都从 S3 下载一遍，或往 S3 上传一遍，传输的活就得一遍遍重干。

Daytona Volumes 补上了缺失的共享存储。智能体创建一个卷，把数据集上传一次，再把它作为网络驱动器挂载到每台需要访问的机器上。

| 方案 | 数据准备 | 另一个沙箱如何访问 | |---|---|---| | 每个沙箱单独一份 | 重复传输 | 再传一份 | | 共享卷 | 上传一次 | 挂载同一个卷 |

变的是共享上下文放在哪里：放在各个沙箱都能访问的卷里，而不是某个人的笔记本上。Burazin 说卷的大小可以灵活调整，但这并不等于容量无限。

08

分叉环境以探索替代方案

并行执行改变的是工作本身的形态。人通常专注于一台机器，最多两台。智能体则可以同时尝试多种方案，不必一遍遍地试一个方法、否掉结果、回到起点、再试一次。

运行时提供的操作是分叉（fork）一台机器，在各个分叉里尝试不同方案，再根据它们的结果得出最终产出。Burazin 提到 5 个、10 个，甚至 10 万个分叉，这些只是举例说明规模，并非实测吞吐量。核心能力在于：从同一个起始环境出发，并行探索。和镜像构建、共享卷一样，这个功能也是从客户希望智能体做到的事情里长出来的。

09

选择完整的工作流，而不是终端上的打磨

未来的 AX 功能还在摸索中。Burazin 并不声称自己知道下一步是什么；做智能体的团队现在才刚刚发现自己的工具缺了什么。凡是需要人介入的地方，都值得拿来排查工作流哪里还没打通。他之所以关注这一点，是因为他预测智能体会成为最大的用户群，而不是认为人类会消失。

Daytona 自己的优先级也随之调整。团队起初在开发者体验上投入很大，包括终端界面。小公司资源有限，问题慢慢从“这个界面能打磨得多精致”变成了“智能体能不能端到端地完成任务”。好的 CLI 依然有价值，但它补不上缺失的操作，省不掉需要手动准备的环境，也救不了做到一半就卡住的任务。

Burazin 最后有意说了一句绝对化的警告：智能体用不了的产品，最终将没有用户。与其把它当成定论式的预测，不如当成设计上的优先级来读：它提醒大家关注到底是谁在操作产品。他当时邀请大家去看 Daytona 的公开仓库，那时这是一个开源项目；如今仓库页面写明，核心开发已于 2026 年 6 月转为私有，公开维护也已停止。真正长久的产品问题是：智能体能不能把用户的任务从头到尾做完。
