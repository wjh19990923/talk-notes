有界自主：在自由意志与决定论之间

广告智能体需要速度，但有用的自主性取决于精选的上下文、简单的工作流，以及让工作保持可理解的表示方式。

01

必须在真实世界中奏效的广告

智能体的产出要直接交到真实客户手里时，该给它多大的自由度？这个问题夹在自动化与定制化、监督与自主、可能与约束之间。Angus J. McLean 从自己在广告行业设计智能体的经验出发来回答。他给的不是标准答案，而是一份实用指南：写给被快速变化弄得手足无措的新手，也写给想换个角度看问题的老手。

McLean 自我介绍是 OLIVER 的 AI 总监。OLIVER 是一家广告公司，业务已经大幅转向生成式 AI。据他介绍，公司在 46 个国家共有 3,000 名员工。Johnnie Walker 的项目是个具体的切入点：观众看到一则 AI 生成的广告，可能根本看不出它是怎么做出来的。所以业务上的难题不只是生成一张惊艳的图片，这张图还得真能当广告用。

McLean 说，他们每天为 200 多个品牌产出约 4,000 个素材，媒体投放预算从两万到几百万不等，他没说是哪种货币。付费投放让这些素材进入市场，效果看得见。真实曝光带回效果数据，团队据此迭代，逐步摸清什么管用。生成之所以有用，靠的是反馈闭环。

02

先求速度，再求规模

要理解广告公司，与其想起《广告狂人》里那副熟悉的形象，不如看它怎么分工。客户部维护客户关系，推动项目按计划走。创意部把想法变成广告和内容。策略部为这些工作提供洞察、受众定位和方向。McLean 说，历史上客户部约占广告公司的 50%，创意和策略各占 20%。这只是粗略的划分：几个数字说的时期不一致，剩下的部分也没有交代。

智能体越来越多地在创意和策略两块承担知识工作：

- 创意：构思、文案写作和内容制作。 - 策略：受众洞察、趋势分析、竞品分析和效果优化。

McLean 做的是策略这一块。这些应用直接面向客户，快本身就带着风险：内容一旦规模化，反响不好会被放大，成功的营销活动也一样会被放大。

用智能体首先图的是快，其次才是规模。创意团队要快速生成、测试和修改内容。策略团队要扩大调研范围，更贴近地了解消费者，为最终转化铺路。营销活动的个性化把这些任务串了起来：先确定相关的用户画像或区域，再逐一调研，然后用调研结果指导创作。比如为纽约和迈阿密分别做本地化广告，不是把同一个素材多复制几份就行，而是要真正了解每个地方。目标是用更少的资源做出更有效的广告。由此引出 McLean 第一条反直觉的建议：慢下来。

03

放慢到足以看清什么会持续存在

工具层出不穷，让人觉得什么都得跟上。McLean 反问：“如果你一眨眼就错过了，它真的那么重要吗？”他的核心观点是：比起昙花一现的工具，那些长期存在的局限更值得关注。他认为 LLM 的基础至少可以追溯到 1990 年代，还提到 Emma Strubell 会追溯得更早。他也提醒，看起来很精巧不等于真的理解。这些是他设计智能体的认知前提。

有两个局限对智能体设计尤其关键。数据效率指学会一件事需要多少经验：人看几个例子就能学会，模型却离不开大规模数据集。持续学习指系统能不能一边学新东西，一边不忘旧东西。McLean 拿人的学习和模型对比：模型训练出来的知识，在使用时是封闭的。他把近期的一部分进展归功于暴力堆算力，援引了《The Bitter Lesson》，还提到之前一场演讲里拿图像生成比作“跑 400 场马拉松”。不过这里既没说明是多大的工作量，也没给换算方式，靠这个类比算不出实际的算力成本。

面对这些长期约束，工具可能只是临时补丁。McLean 的判断标准是：它是不是短命、流于表面、只掩盖症状，或者只解决了一部分问题。真正值得问的工程问题是：外围系统到底修好了什么，又有哪些局限只是被藏得不那么显眼了。

04

一个闭源模型需要能用的上下文

McLean 用一个简化模型来理解 LLM：一个封闭的知识盒子，一个能做“语义运算”的灵活数据库。他设计时不指望它会自己学会新东西、长出新能力。广告行业让这个局限变得很具体：一个真正的新趋势，模型的知识里可能根本没有，而这恰恰是策略人员最需要弄懂它的时候。

上下文窗口变大，智能体在执行任务时就能处理更多信息。McLean 认为，长时间运行的智能体之所以进步明显，很大程度要归功于此：窗口能同时装下操作历史、工具输出、任务安排、目标和计划。上下文相当于短期存储和检索，智能体可以回看自己做过什么，再决定下一步。相关信息一旦被挤出窗口，多步骤工作流就可能断线。McLean 提到一起没具体说明的邮件删除事件，用来警示上下文耗尽的风险，但他给的细节不足以判断事件的真正原因。

演讲中，McLean 拿 GPT-2 和一个他口头称为 Gemini 3.5 Pro 的模型做对比，又回忆起当年 512 大小的窗口。这些细节撑不起可靠的容量对比：GPT-2 的实现默认是 n_ctx=1024，他口头说的 Gemini 型号也不确定。按主办方日程，这场演讲早于 Google 的发布公告，而那份公告里 3.5 Pro 仍是“即将推出”。更值得关注的设计要点是：工作空间是有限的。McLean 认为需求永远会超过它，还引了“世界知识每 12 小时翻一番”这个没有依据的说法来佐证。其实实际问题不需要这个增速来支撑：窗口再大，也得决定哪些东西该放进去。

05

约束证据，再排除噪声

上下文是一种软约束。智能体拿到什么信息、信息怎么排布，都会引导它的行为，但不会强行设下硬边界。McLean 举的日常例子是：不让智能体随便上网，而是给它高质量的文档。这两者的区别很关键：限制访问是在划定能力边界；挑选文档，则是在边界之内决定它能看到哪些证据。

竞品调研最能暴露这种失败模式。智能体本想找消费者洞察，结果可能把竞品自己的宣传话术照单全收。一个来源在搜索里排得靠前，不代表它能代表消费者的声音。McLean 发现，模型容易被 SEO 牵着走，也不擅长识别推广内容。知识一旦要靠工具检索，结果就不只取决于模型知道什么，还取决于智能体怎么用这个工具。所以挑选信息来源，本身就是控制任务的一部分。

早些年窗口还小的时候，McLean 用 TF-IDF 给聚类打标签。做法是：先给文本语料聚类，从每个簇里提取最有代表性的词，再用这些词生成标签。TF-IDF 不是简单数哪些词出现最多，而是按一个词在不同文档间的区分度，给词频加权。Top-K 筛选也是类似的思路，限制进入上下文的材料量。窗口变大后，上下文可以组装得更灵活，但问题也变了：把信息放进去更容易了，把无关信息挡在外面却更重要了。要的是有用的上下文，不是塞满的上下文窗口。

06

用更少的东西练习

如果模型明天就停止进步，你还能做出什么？这个问题把资源稀缺变成了一道设计练习题。别问模型能装多少上下文，要问完成任务最少需要多少上下文。McLean 开玩笑说自己还算不上“token 亿万富翁”，接着拿早期计算机和 Model Railroad Club 做类比。他提到 Spacewar! 只用 4,000 个字（word）就做了出来，不过演讲没说清这个数字指的是程序大小还是可用内存。

下一个类比是《古惑狼》（Crash Bandicoot）的内存优化。McLean 说的是 PS2，但从 Andy Gavin 的开发回忆可以确认，那其实是初代 PlayStation。这个例子的意义在于内存有限时的工程思路：决定哪些内容必须常驻，哪些可以用到时再载入。McLean 把这种精神带进了他建议的几项实验，并明确说这些不是生产环境的建议。

这几项练习一步步深入系统的内部机制：

1. 试试更老或更小的模型，或者更简单的框架，让局限更容易暴露出来。 2. 自己搭一个框架，实现记忆和压缩，把留什么、丢什么变成显式的决策。 3. 钻研预处理和归档；看看文件系统和知识图谱怎么组织信息，方便以后取用。

这样做的好处是更懂数据，写提示词、控制模型也就更得心应手。McLean 用一张图结束这一部分，说图里是 Rosenblatt 在从感知机上拔线，并把它和 dropout 联系起来。这只是一个关于“去掉连接”的启发性类比，并非确凿的历史渊源。

07

缩短与现实之间的反馈循环

有时候，最有用的约束是砍掉你以为自己需要的那个应用。McLean 讲到，他曾做过一个复杂的简历应用，能用，但效果还不如直接让模型输出 HTML。他估计，改用 HTML 后，简历这件事的效果提升了 10 倍以上，甚至可能有 100 倍，不过他没说用什么指标衡量。真正值得比较的是实现方式：直接用一种文档格式，比外面套的那一堆机制更好地解决了他的问题。

有了模型，造出不必要的复杂度变得很容易。McLean 说模型话多，还爱推荐复杂方案，结果开发者烧掉更多 token，也背上更多维护工作。先做一个能用的简单版本。智能体吸引人的地方在于反馈闭环短，做产品也该如此：尽快让想法接触现实，看看多加的那些机制到底有没有用。

08

选择服务于任务的表示方式

接着，McLean 把 AI 看作一种翻译。Attention Is All You Need 就是从翻译出发的：论文研究机器翻译，做了英译德和英译法两组实验。这个类比不只适用于语言之间：文字可以变成图像，图像可以变成音频，音频可以变成视频。在他看来，知识生产也是一种摘要：这场演讲本身，就是把多年经验压缩成一小份能用的知识。

落到实处，就是在不同表示形式之间转换。非结构化输入可以变成结构化输出，结构化输入也可以变成文章或其他更松散的形式。McLean 把这个思路和 MCP，以及长时间运行的智能体之间的交接联系起来。但不要把这个类比和协议本身的范围混为一谈：后来的 Model Context Protocol 文档把它定义为 AI 应用与外部数据、工具和工作流之间的连接方式，而不是通用的模型间交接机制。

既然信息可以在不同形式之间流转，怎样组织才有用，部分取决于看的人要拿它做什么。做幻灯片就是个直观的例子：有些内容适合画成图，有些需要文字说明，有些最好口头讲。只认一种格式，就会把这些差别掩盖掉。选什么表示形式，本身就是解决任务的一部分。

由此引出几种互补的结构：

| 表示形式 | 适用场景 | | --- | --- | | Markdown 或大纲 | 层级清晰，便于阅读和写作 | | 图谱 | 关系和引用 | | 聚类 | 大量或非结构化的文本集合 | | 文件夹 | 按已知位置快速检索 | | 时间线 | 顺序很重要的问题 |

比如，一份 Markdown 格式的调研笔记可以把“发现”和“证据”明确分开：

```markdown # 受众调研

发现

写明消费者洞察。

支撑证据

记录来源和相关观察。

启示

说明这会给创意简报带来哪些改变。 ```

这只是一个写作框架，不是完整的分析。同一份底层材料，也可以放进关系图谱、相似观察的聚类或时间线里。有了多种表示形式，不同任务就能共用同一份信息，不必全都挤进同一种格式。

09

从实验到一份可用的情报报告

这种理解有一部分来自用心的“玩”。McLean 说他现在参加黑客松比以前多，因为能做工作中没法尝试的实验。工作有它必要的边界；在边界之外做实验，才有空间学到新技术，日后再反哺本职工作。

最后一个问题是：职场里的智能体需要多少结构？McLean 回溯到 Adam Smith 的制针工厂：工作可以拆成一个个小而可重复的任务。在他的经验里，工作流往往更有效。这意味着，想把自动化做得有用，先得懂这个领域。他的原则很直接：“自己不会做的活，就别去自动化。”懂这份工作，才知道该怎么拆，也才能判断产出有没有用。

最后的演示回到 McLean 之前做社交媒体情报的老本行。他展示了一份由 LLM 生成、关于 OpenClaw 的报告，用的大约是过去一年的数据。模型先对材料做了聚类，再拼出一份广告公司会用的那种报告。

McLean 说，这份 OpenClaw 分析对 5 万条推文做了聚类，并整理成若干策略。他形容报告几乎是瞬间生成的，但没给出实测耗时。报告里还有几条亮眼的推文，以及对各项洞察的拆解。报告最终交给创意或策略团队：海量的社交讨论，被整理成大家能拿来决定下一步做什么的材料。收尾的演示把智能体的价值落在这里：把原始素材变成有用的产出。

延伸阅读
