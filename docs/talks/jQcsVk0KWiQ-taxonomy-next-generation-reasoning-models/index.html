下一代推理模型的分类法

推理模型可以检索到冷僻的参考资料，却难以规划出可靠的工作。技能、投入程度的校准、策略和抽象，指出了训练更自主智能体时各不相同的问题。

01

找到那个你叫不出名字的例子

会解基准测试题，和找回一篇想不起名字的参考资料，是两回事。到 2025 年 6 月，o1 和 DeepSeek 掀起的推理模型浪潮，已经让训练时的强化学习和推理时的额外计算形成了良性配合。讨论大多围绕可验证奖励强化学习（RLVR）：答案能检验对错，就给奖励。Nathan Lambert 想知道，除了更高的基准分数和动辄 10,000 token 的回答，下一步是什么。

他举的日常例子，研究者都不陌生。他记得一个奖励过度优化的案例，却总想不起那个游戏叫 CoastRunners。每次搜过度优化，他都得反复试着找回这条参考资料。据他说，他去问 o3，o3 直接给出了下载链接。他不用先想起名字，模型就明白他要找什么。

这类训练最初跟数学和代码绑在一起，却在这里派上了意想不到的用场。Lambert 查信息时最常用的模型已经是 o3。这次检索成功说明，推理训练也许能让模型做好更多有用的事。这只是一个使用中的小故事，不是对照实验，但它让研究问题变得具体：还要补上哪些能力，零星的成功才能变成靠得住的产品？

02

推理成为一种产品能力

Deep Research 把这种潜力带进了更可控的工作流。Lambert 说，他会让它检查自己网站上的错别字，或者只研究该网站上发布的内容。有用的不只是它能写出一份报告，而是它能按更窄的范围去调查。

Claude Code 提供了另一种交互方式。Lambert 用它帮忙搭建自己在线书籍的网站，把它当成做好玩实验的工具。不过他的热情有个前提：他没拿高难度的软件工程任务来检验它。

Codex 在自主执行上又往前走了一步。Lambert 认为这种产品形态显然很有前景，但它的运行环境对机器学习任务限制太多。据他说，演讲时 Codex 还没有 GPU，也才刚能联网。用开源模型干活，常常要去查 Hugging Face 上的配置。所以这些环境限制本身就很关键，跟模型推理能力强不强无关。

他预测，接下来六个月里，这些产品会成为日常工具。这是他对推理模型新兴应用的判断；它们能不能真正派上用场，仍要看任务需要的工具和资源能不能拿到。

03

更长的任务需要有意识地建设能力

一张任务时长图，把这些应用放进了更长的发展脉络里。Lambert 认为，GPT-4o 前后那段时间出现了饱和迹象，之后更新的 Sonnet 模型和 o1 又把前沿往前推了。他把纵轴粗略地解释为“模型能完成多长的任务”，并把后来的提升归功于推理训练。

> 编者注： 在 METR 2025 年 3 月的原始分析中，任务时长指的是：智能体以指定概率完成的任务，人类专家需要花多长时间。它衡量的不是智能体自己的运行时间。

要让曲线继续往上走，得先找出还缺哪些能力，再针对性地训练。 趋势线不会让下一次提升自动到来。Lambert 提出的下一步，是从单项推理技能走向规划：研究计划要教会模型什么，它才能自主完成一项有分量的任务？

04

技能、校准、策略与抽象

Lambert 的初步分类区分了四种特质。判断一个模型擅不擅长推理时，这四点很容易混为一谈：

| 特质 | 模型要做到什么 | 关键区别 | | --- | --- | --- | | 技能 | 解决数学、代码等领域的问题。 | 能解好单个问题只是起点。 | | 校准 | 让输出 token 的消耗和问题难度相匹配。 | 这里的校准指花多少力气，不是报出的概率准不准。 | | 策略 | 选一个有希望的方向，并看到其他可行思路。 | 在一种思路里回溯，和放弃这条路、换个方案重来，是两回事。 | | 抽象 | 把大任务拆成能处理的子任务。 | 模型要判断哪些自己能解、哪里该用工具、什么时候该调用更大的模型。 |

技能已经是推理训练最明确的成果。每个任务耗的计算越多，校准就越要紧。策略和抽象是 Lambert 对规划的细分：先选方向，再把方向变成真正能落地的工作。

如今，这种拆解往往还得靠人来做。训练模型解数学题，并不会明确教它怎样把一个开放式任务分给自身能力、工具和其他模型。在 Lambert 的研究议程里，这些行为本身就得成为训练目标。

05

现有的训练循环教了什么

RLVR 的基本循环很简单：

1. 给模型一个提示词。 2. 让它生成一段补全。 3. 用现有的验证方法给这段补全打分。 4. 用打过分的补全更新模型权重。

Lambert 描述的示意图是单轮循环。多轮交互和工具调用会让问题的形式更复杂，但核心机制不变：先生成，再反馈，最后更新权重。

从 GPT-4o 到 o1 再到 o3，能看出这类额外训练让高难度评测上的表现变了多少。Lambert 拿 Humanity’s Last Exam 和 AIME 举例，主张规划也需要同等力度的能力建设。现有推理任务上分数更高，并不说明模型能可靠地组织更长的工作。

单项技能的版图也在扩大。Lambert 特别提到新版 DeepSeek 和 Qwen 模型的工具使用能力；在他看来，o3 好用，是因为它把工具和推理、数学、代码结合在了一起。

工具使用之上的那一层，就更难说清了。Claude 以智能体能力强著称，但 Lambert 强调，目前还没有同样成熟的办法，能在不同模型之间衡量或说清这种能力。工具调没调成功，一眼就能看出来；模型能不能把整个任务指挥好，需要更全面的评测。

06

加法需要多少思考？

演讲时，产品大多把精力校准交给用户。ChatGPT 让用户选模型；Claude 提供扩展思考开关；Gemini 也有类似的选项；API 则提供推理强度设置。每个开关都要用户自己预判：下一个任务值得投入多少推理。

如果模型能自己做这个决定，用户就不用费心挑选，也能少花冤枉 token。可用的推理预算越大，这个问题的代价就越高。

以 2 + 3 为例。Lambert 讲到，有推理模型为一道加法题用掉几百到大约一千个 token，而答案本来一个 token 就够。幻灯片上另有一张序列长度对比图，把标准指令模型和 QwQ 思考模型放在一起比较。在他讨论的几组对比里，切换到推理模式可能让 token 消耗增加 10–100 倍；但这个倍数并不适用于所有任务和模型。

多出来的 token 意味着基础设施负载、成本和等待时间。遇到简单问题，用户不该干等几分钟，也不该为了躲开不必要的思考而换一家服务商。校准，就是把力气花在能改变结果的地方。

07

在花预算之前先选定方向

精力校准引出了第二个问题：模型花的这些力气，方向对不对？Lambert 从 Epoch AI 的 FrontierMath 材料里拿了一道例题，用 DeepSeek-R1-0528 试了试，想看看模型会不会先规划再动手。

据他描述，模型一上来就开始构造多项式，既没有先梳理问题，也没有比较几种可能的思路。这只是用一道题做的试探，但它说明了“开始推理”和“选择策略”是两回事。

Lambert 预计答案会有 10,000–40,000 个 token。他接着设想把预算再放大十倍：方向一旦错了，可能烧掉好几美元、等上很久，却毫无实质进展。这些是他的预估和假想推演，不是试探中实测的结果。

他说，这里讨论的应用，延迟大致在一到三十分钟之间。整体策略不对，或者在某个子问题上耗得太久，都可能把这段时间用光。在用户看来，两种失败的结果可能一样：任务还没跑完，就只能放弃。

在 Lambert 看来，Deep Research 和 Claude Code 这类产品，似乎是靠提示词让模型一开始先做规划。他的提议是通过训练，把这种行为变成模型的原生能力，这样选择思路就不必完全依赖应用给的指令。

08

让计划可执行

有了计划，记忆和执行上的实际问题就来了。Lambert 讲到，Claude Code 会在上下文窗口填满时压缩记忆，但他并不认为这对所有应用都是最好的记忆策略。智能体还得避免重复犯错——他把这一点和此前关于玩 Pokémon 的讨论联系了起来。记住之前的尝试，只有在这些信息能改变智能体下一步做法时才有意义。

抽象还意味着把任务拆成可管理的几块，并给难的部分多分配一些思考。这可能要把部分工作交给另一个模型，或者并行调用多个模型。

Lambert 举了个让人印象深刻的例子，也就是手动版的做法：有人打开 tmux，在十个窗口里同时跑 Claude Code。理想的模型能力不只是多开几个进程，而是能判断什么时候并行有用、该怎么拆分任务，并选出合适的处理方式。

09

用专家示范引导规划

Lambert 梳理了从 Q* 到 Strawberry 再到 o1 的路径，强调建立新行为要下大力气。按他的说法，OpenAI 花了十二到十八个月打磨最初的推理 trace，靠人工数据让回溯和验证变得可靠。这是他对推理模型发展历程的解读，他借此论证规划也需要同等投入，而不是把它当成已公开的训练配方。

对专家来说，规划示范可能更容易写。要写一段令人信服、带回溯的 10,000 token 推理 trace，很别扭；写一份五到十步的好计划，或者检查模型生成的计划，就顺手得多。

所以他提出的训练路径很具体：先收集初始的规划示范，用监督微调（SFT）教会模型这些行为，再研究在更大的任务上做强化学习，能不能强化有用的规划风格。最后一步仍是个研究问题。模型可能学会了输出计划，却不一定学会哪些计划能真正执行成功。

Lambert 还建议给输出序列加更多结构。推理模型已经把思考和回答分开了；一种设想中的扩展是 plan → think → answer，目的是在投入大量推理预算之前，先选定思路。这是他提议的训练结构，不是已经上线的 API。

10

找到一个事实与可靠的研究是两回事

CoastRunners 的例子展示的是一项很强的单项技能：用户想不起合适的搜索词，模型也能找回冷门信息。但研究任务要的，不止是一次检索成功。

Lambert 对比了 Deep Research 的出色结果和令人失望的结果，认为这种不稳定部分源于规划能力不足。拿电子产品选购建议来说，差距一目了然。模型也许很会找事实，却仍可能没收集到对的信息，或者没把各个备选方案查透，撑不起最后的推荐。

要做到可靠的覆盖，既要决定查什么，也要决定每部分花多少力气。 搜索负责提供信息；规划负责判断收集到的信息够不够完成任务。

策略、抽象和上下文管理之间的界线，不必划得太死。Lambert 的目的是把训练问题拆开：先找出缺了什么行为，再问什么数据或算法能教会它。这套分类的价值，就在于让这些研究选择变得更具体。

11

用并行算力换取稳健性

Lambert 拿 o1 Pro 举例谈稳健性，当时他还在期待 o3 Pro。他把额外计算可能带来的好处分成两种：一是让原本解不出的任务变得可解；二是让已有的能力更可靠，或者产出打磨得更好的答案。

他的理解是，强化学习能鼓励探索，额外的并行计算则有助于充分利用模型已有的思路。这是他对“计算如何改善结果”的直觉，不是在描述这些产品的内部架构。看重稳健性时，并行工作很有价值，但它解决不了所有局限，也替代不了新能力。

12

从合适的数据和稳定的 RL 开始

持续学习带来了一个更大的可能：通过长周期任务反复更新模型，也许能减少它对预训练的依赖。Lambert 认为，这里还卡着一个没解决的算法瓶颈。在他看来，继续扩大强化学习的规模，是更近在眼前、也更好下手的方向。

在 Allen Institute for AI（Ai2）的工作中，他把推理模型的实际研究计划浓缩成了几个优先事项。

1. 收集带已验证答案的问题。 尽量覆盖多个领域，同时也要承认，现有数据大多是数学和代码。 2. 按相对基础模型的难度筛选。 Lambert 举了两个极端：100 次尝试一次都没解出，或者 100 次全部解出。他认为这两类题都浪费计算，还会让 RL 更新的噪声更大。有用的训练集，取决于这个起点模型哪些题有时能解、但不是每次都能解。 3. 跑出一次稳定的 RL 训练。 用能支撑持续提升的基础设施，在选好的问题上训练。合适的数据加上可靠的训练，是这套方法的根基。

这些基础都跑通之后，Lambert 才会考虑各种改进，比如过长样本过滤、调整裁剪方式、重置参考模型。在他看来，这些手段只是在一次可用的训练上再多拿几个百分点，替代不了好数据和稳定的基础设施。实际的判断原则是：先把数据和训练循环修好，别指望调一调算法就能救回一次失败的训练。

13

当后训练成为一大笔算力预算

结尾他抛出一个引人深思的问题：后训练是不是干脆就该叫训练？Lambert 给了一个有前提的估算：假设 o1 后训练的算力是预训练的 1%，再套用他提到的 o3 增加 10 倍的数字。按这个假设的基线，结果大约是 10%，还远没到持平。要让预训练和后训练的 GPU 小时数相当，还得继续增长。

这个设想想说明的，是投入规模在变。一个曾被当作小小补充的阶段，可能会变成训练预算里的一大块。

谈到 DeepSeek-V3，Lambert 引用的数字是：后训练只占 GPU 小时算力的 0.18%；他还说预训练大约用了两个月。

> 编者注： DeepSeek-V3 Technical Report, v2 报告，后训练用了 5,000 个 H800 GPU 小时，总计 2,788,000 个 GPU 小时，占比约 0.18%。这是报告中的最终训练运行，包含上下文扩展，不含研究和消融实验的成本。

他对 DeepSeek-R1 的比较，依据就不一样了。Lambert 回忆，有位研究员发过一条后来删掉的推文，说 R1 的训练花了几周。假设 RL 用的是同一整个集群，他试探性地估计算力占比在 10–20%。他明确表示这个假设很强，可能并不准确，所以这个数字应该看作他的推测，而不是 DeepSeek 披露的训练成本。

他还指出，DeepSeek 的预训练基础设施可能比 RL 基础设施高效得多。集群分配和实现效率不一样时，光看耗时长短，没法判断算力孰多孰少。

研究方向是把不断增长的 RL 预算，花在能执行更长计划的模型上：把任务拆成几部分，决定每部分怎么处理，再用手头的资源逐一解决。这样一来，自主拆解任务就和推理技能并列，成为训练目标；正是这些推理技能，催生了第一波应用。
