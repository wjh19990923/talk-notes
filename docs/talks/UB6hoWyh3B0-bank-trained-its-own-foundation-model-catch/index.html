Transformer 架构与规模估算

幻灯片原文
The decoder scores the next transaction from account history. Chinchilla sizing set an initial target of 20 tokens per parameter; Lecue says experiments ultimately required about ten times that token budget.

[10:05](https://www.youtube.com/watch?v=UB6hoWyh3B0&t=605s) [Architecture table for a billion-parameter decoder-only transaction model, alongside Chinchilla sizing estimates and reasons for choosing a decoder.](https://assets.ai.engineer/sites/aiecode2025/sha256/a9bbb9bcf635d9846ddca0b0606f37d56dc1600b8e5db5058b0cdfda997811ba.webp)

THE BACKBONE
1B-parameter decoder-only transformer, sized by Chinchilla

ARCHITECTURE — 1B-PARAMETER TRANSACTION FOUNDATION MODEL
Input sequence: 1,024 / 2,048 tokens (account history)
Embedding dimension: 2,048
Transformer stack: 16 decoder blocks
Attention: 32 heads · head dim 64 · masked MHA (Multi-Head Attention)
Per block: MLP (Multi-Layer Perceptron) dim 8,192 · residual · layer-norm
Position: RoPE (Rotary Position Embedding)
Objective: Next-token prediction (Causal + Masked Language Modelling auxiliary)

SIZING MATH (CHINCHILLA-OPTIMAL)
Optimal tokens ≈ 20 × parameters
DATA TARGET: ≥ 20B tokens
TRAIN COMPUTE: 6 × 1B × 20B ≈ 1.3 × 10²⁰ FLOPs
WALL CLOCK:
8 × NVIDIA H200 ≈ 3.5 days
≈ 576 GPU-h
(2.6B transactions · 220B tokens)

WHY DECODER-ONLY (vs. ENCODER) ?
▸ Strong fine-tuning surface — last-token pooling works very well.
▸ Causal masking matches reality — we always score the next transaction given history.
▸ Standard infra path — reuses the Large Language Model pre-train tooling.

因果语言建模与掩码语言建模目标

幻灯片原文
CLM predicts the next token from left context and supplies the primary loss. MLM reconstructs masked tokens using both sides of the sequence; its weighted auxiliary loss regularises the embedding space.

[11:57](https://www.youtube.com/watch?v=UB6hoWyh3B0&t=717s) [Side-by-side diagrams show next-token prediction using left context and masked-token reconstruction using context from both sides.](https://assets.ai.engineer/sites/aiecode2025/sha256/184b1c18c472fe8e98f0a657c2468d576668682c50dfa3ab2268754a749a4841.webp)

PRE-TRAINING RECIPE
Two complementary objectives on the same sequence

CLM
Causal Language Modelling

Standard auto-regressive loss — every token predicts the next, given only what came before. Mirrors how the model will be USED at inference.

BOS   Δt_30m   AMT_10   MCC_60   ATM   EOS
left context

target →
ATM   ✓

predict the next token from LEFT context only

MLM
Masked Language Modelling

Mask 15% of tokens and reconstruct them from both sides. Forces the model to use bidirectional context during pre-training.

BOS   Δt_30m   AMT_10   [MASK]   ATM   EOS
left + right context

target →
MCC_60   ✓

reconstruct hidden tokens from BOTH sides

RECIPE — CLM is the primary loss; MLM is a weighted auxiliary that regularises the embedding space.

扩展训练的三个杠杆

幻灯片原文
The training stack combines higher token throughput, fewer steps to converge, and lower memory use. The slide treats these as independent levers whose gains compound, with techniques assigned to each goal.

[12:50](https://www.youtube.com/watch?v=UB6hoWyh3B0&t=770s) [Three columns describe techniques for faster training, faster convergence and memory efficiency.](https://assets.ai.engineer/sites/aiecode2025/sha256/ea27bb7cfb92f5d5b71acb1a15334134f1c7f96346c9770f907c86d688058095.webp)

SCALING PLAYBOOK
Three knobs every training stack has to push at once

FASTER TRAINING
maximize tokens / second

Mixed precision
BF16 (Brain Float 16) / FP16 (Floating-Point 16).
GPU throughput ↑ with negligible quality loss.

DDP — Distributed Data Parallel
Replicate the full model on every GPU; scale data in parallel.

Maximize microbatch size
Use the largest batch that fits before gradient accumulation.

FASTER CONVERGENCE
fewer steps · fewer tokens

Muon vs AdamW
Muon (orthogonalised matrix updates) replaces AdamW (Adam + weight decay) — ~10% lower final loss.

RoPE — Rotary Position Embedding
Easier optimisation landscape, faster convergence.

Effective batch stability
Gradient accumulation for smooth loss curves.

MEMORY EFFICIENCY
fit a bigger model / context / batch

Flash Attention
O(N²) → O(N) memory; 2–4× faster attention kernel.

Activation checkpointing
Recompute on backward; 40–50% memory cut.

FSDP — Fully Sharded Data Parallel
Shard parameters, gradients and optimiser state across GPUs.

THREE INDEPENDENT LEVERS — optimiser, kernels, memory — the gains compound.

FT-TFM 胜过人工特征的 XGBoost 基线

阅读全文

一家银行训练了自己的基础模型来抓欺诈

Freddy Lecue 讲解了富国银行如何把交易表变成 Transformer 的词表，从零开始预训练一个共享主干，并利用交易历史，在欺诈分类上超越了其生产环境中的 XGBoost 基线。

富国银行关于交易基础模型的演示，把原始银行交易、共享主干和专门应用联系在一起。

01

一个骨干模型服务数十亿笔交易

Wells Fargo already had tabular data and an XGBoost fraud model in production. The opportunity Freddy Lecue introduces is to learn more from the bank’s transaction history—and make that learning reusable. Debit cards, credit cards, digital payments and checks generate different records across different channels. Separate teams can build separate models around those records, but each then has to solve its own representation problem.

A transaction foundation model would learn a common representation of customer transactions at scale. Teams could then fine-tune the same backbone for credit decisions, fraud detection, anti-money laundering or marketing. Foundation models need not begin with language: here, the raw material is structured financial activity, with billions of transactions arriving each month.

The obvious objection is practical: why replace XGBoost, an established choice for tabular data? Lecue’s answer begins with the existing production system: “We did that.” The transformer approach had to earn its place against that baseline. He previews higher fraud detection, fewer false positives and a latency advantage, then works backward through the data representation and training decisions that made the comparison possible.

02

预测下一笔交易以学习可复用的表示

The training pattern resembles a language model’s, with a different unit of meaning. A language model learns from language tokens by predicting what comes next. The transaction model instead predicts the next transaction, or the next token within a transaction, using activity from the available channels. That prediction task gives the model a way to learn patterns before it is adapted to a specific business decision.

Next-transaction prediction is an intermediate objective. The useful output is a representation that captures relationships between transactions over time and, as Lecue describes the intent, across customers. Post-training then adapts that representation to questions such as whether to increase a credit line, flag a fraudulent transaction or identify potentially suspicious activity. Predicting a customer’s next action and deciding whether an action is fraudulent are different tasks; the first supplies a foundation for the second.

“From scratch” matters here. Wells Fargo reused transformer architecture rather than an existing model’s learned weights, then pre-trained on its own transaction data using its GPU cluster. The bank was therefore learning the financial representation itself, rather than continuing the training of a language model that already had a different vocabulary and training history.

03

找回工程化特征底下的原始信息

The input design starts with five questions about a transaction. Together, they describe the event before any particular downstream classifier decides what to do with it:

- Who: The customer or merchant involved in requesting, processing or providing the service. - What: What is being bought or transacted. - How: The channel, such as credit, debit or digital. - When: When the transaction happens. - Where: Where it happens.

Those dimensions expand into hundreds of features. Existing production models also carried substantial handcrafted feature engineering, which took considerable time to build. The team stepped back from that inventory to identify roughly a hundred core raw features among thousands of available features. The aim was to let transformer blocks learn relationships among the underlying inputs, rather than begin with an extensive set of features already shaped around individual downstream tasks.

This still leaves a representation problem. Even after combining digital, checking, savings and other transaction types, the input has a relatively limited set of characteristics—but their meanings are specific to financial services. Lecue gives that specialized vocabulary as a reason for training the model’s weights from scratch. The next challenge is to express those characteristics in a vocabulary a transformer can process.

04

分词承载着最困难的设计决策

A transaction table mixes numerical and categorical values. A transaction amount, an elapsed time and a ZIP code cannot all be treated as interchangeable pieces of text. Each needs a decision about what information a token should preserve. Giving every distinct ZIP code its own token is one possibility, but a vocabulary that grows too large makes training harder. Vocabulary design therefore balances the distinctions the model needs against the size of the representation it must learn.

Once that vocabulary exists, an incoming transaction follows a concrete mapping: its characteristics are matched to tokens, those tokens have IDs, and an embedding lookup supplies their model representations. The difficult work precedes the lookup. The lookup applies decisions already made about which values should receive distinct representations and which should share one.

How much vocabulary does each field need? The examples show why the answer varies:

- Small categories: Some categorical fields have only eight types; binary characteristics need fewer distinctions still. - Numerical and temporal values: Transaction amount and the time difference between transactions carry different kinds of information that need encoding. - Location and network information: Two postal-code fields account for 2,858 tokens. One IP-address field maps to 23 tokens. Lecue gives grouping ZIP codes by their distributions as an example, without specifying the grouping algorithm.

These examples make tokenization part of the model design itself. Grouping location values changes which geographic distinctions remain available to learn; representing time differences makes spacing between events available alongside their other characteristics. Lecue later calls tokenization and post-training the “secret sauce.” The transformer machinery can be familiar while the financial vocabulary requires substantial domain work.

05

一个 11 亿参数的模型，数据比最初预想的更多

What architecture was sufficient for the transaction task? The team used Chinchilla scaling mathematics as a starting point, then adapted through experimentation in the tabular setting. The selected model had 1.1 billion parameters: Lecue describes it as the smallest model that delivered the highest boost in their experiments. It used a decoder-only architecture for next-token or next-transaction prediction. An 11-billion-parameter version was work in progress at the time of the talk.

The initial data budget used twenty training tokens per parameter. Experiments required substantially more—described as roughly ten times that initial allowance. The useful correction is that a sizing rule borrowed from language-model training did not settle the transaction model’s data needs. The team had to test how much transaction data its chosen model required.

History length was another training decision: how many transactions should fit into the model’s context? That choice determines how much past activity is available when learning a sequence. Evaluation included perplexity-based checks of predictive learning and accuracy dashboards for downstream tasks, keeping the pre-training objective and the eventual business task in view.

The training setup otherwise drew on established large-model techniques. Lecue lists mixed precision, distributed data parallelism and maximizing microbatch size, alongside RoPE, FlashAttention and activation checkpointing. These supported training and memory efficiency; he presents no new training infrastructure algorithm. The distinctive work remained the transaction vocabulary, adapting pre-training to the data and deciding how to post-train for useful tasks.

06

对照历史判断一笔新的借记卡交易

Fraud classification supplies the concrete downstream test. The production XGBoost model learned from transactions labeled fraudulent or non-fraudulent. The transaction foundation model brought a sequence representation to the same decision: someone has just used a debit card; given the preceding transactions, should this new transaction be classified as fraud?

The proposed advantage is access to relationships between the current transaction and earlier ones. In Lecue’s account, the XGBoost system needed those relationships to be encoded into features explicitly, a difficult engineering task. Transformer attention lets the current transaction draw on past transactions in the supplied sequence. Lecue identifies this as the team’s explanation for the higher detection rate, rather than presenting an experiment that isolates attention as its cause. The comparison concerns their production baseline; it does not mean tree models cannot use historical features.

At inference time, the input is therefore the transaction sequence, including the new event and its historical context. This makes the history-length decision operationally relevant: the classifier can use the history supplied to it. The model must also fit a card-decision processing window of less than 250 milliseconds. Lecue presents the engineering outcome as satisfactory and earlier claims a latency advantage over XGBoost, but the closing latency wording is internally inconsistent, so it does not establish a reliable measured inference time.

07

抓到更多欺诈，同时拒掉更少的正常支付

Wells Fargo compared its production XGBoost model, which used about 100 engineered features, with a fine-tuned transaction model that used none. On a holdout set of about 10 million samples, the discovery rate measured the share of fraud accounts caught. The false-positive ratio measured non-fraud alerts per fraud alert at a 0.5% cutoff. With last-token pooling and a five-transaction history, the model raised the discovery rate by 28% and lowered the false-positive ratio by 26% relative to XGBoost. With the same pooling and a 12-transaction history, the discovery rate was 33% higher and the false-positive ratio was 29% lower than XGBoost’s. The slide gives no absolute rates or holdout dates.

How do those two metrics turn into business value? More detected fraud addresses fraudulent activity directly. Fewer false positives avoid another chain of costs: a legitimate customer’s payment is declined, the transaction is lost, and the customer may call the bank, creating operational work. Lecue attributes millions of dollars in savings to the improvement. That is a reported business outcome, without a savings calculation developed in the talk.

08

欺诈是已验证的用例，其他团队复用这个基础

The closing distinction is between building the foundation and adapting it. Wells Fargo pre-trained on billions of its customers’ transactions, using an existing architecture without importing existing learned weights. Lecue describes initial pre-training runs taking a couple of weeks and later runs taking a couple of days. Once the model had learned to predict transaction patterns, that foundation became available for downstream training.

Fraud detection was the completed application presented here. Credit-line increases, anti-money laundering and marketing were under investigation. The same foundation was being used across organizations within Wells Fargo, fulfilling the original goal of sharing learned representations. The fraud result gives that approach a concrete first use; the other applications still need their own task-specific evidence.

要点总结

  • 交易基础模型可以通过预测下一个 token 或下一笔交易，从结构化的金融活动中学习，然后针对不同的业务任务进行微调。
  • 分词是核心的设计问题：数值、小类别和位置信息需要不同的表示，而词表大小限制了可选方案。
  • 最终选定的模型有 11 亿参数。实验所需的每参数训练 token 数，大大超过了团队最初设想的二十比一。
  • 在欺诈分类中，模型接收一段交易序列，让新的交易能在历史上下文中被评估。团队认为正是这些关系帮助了检测。
  • Lecue 报告称，在留出测试中，使用 12 笔交易历史的模型比生产中的 XGBoost 基线多抓到 33% 的欺诈账户，每个欺诈告警对应的非欺诈告警少了 29%。信用额度提升、反洗钱和营销用途仍在研究中。
