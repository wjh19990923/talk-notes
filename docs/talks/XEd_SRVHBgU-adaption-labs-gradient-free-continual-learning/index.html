Adaption Labs：无梯度的持续学习

自动化训练配方、改变算力投入的回报点，或许能让更多人参与前沿 AI，但数据质量、模型规模、安全和访问权限仍然决定着机会的大小。

对模型训练、推理和超参数有基本了解会有帮助；不需要了解 AutoScientist。

01

通往科学发现的窄路

在 AI 前沿，谁有资格提出问题？谁又得先争取到使用工具的机会？Sara Hooker 的演讲从这个问题讲起。计算机科学还很年轻，在她看来，这门学科的历史大约只有两代研究者。可定义其前沿的机构和课题，已经天翻地覆。她把这段历史放在战时背景下讲，这里要澄清一点：第一个晶体管于 1947 年演示成功，那时二战已经结束；曼彻斯特的实验性晶体管计算机则在 1953 年问世。

科学史上有个类似的先例。过去，有钱的独立研究者可以以“绅士科学家”的身份自由探索。后来，17 世纪的皇家学会等科学团体，帮助建立起更有组织的研究共同体；全职科研也成了一门职业。机构让长期持续的探索成为可能，也在参与者面前设了门槛。Hooker 借用 Rosanne Liu 的说法，把这种结果称为“窄得离谱的路”。

她展示的例子是 Yann LeCun 的职业生涯：从博士、博士后，到 AT&T Labs、NEC Labs、NYU，再到 FAIR，一步接一步。通行的建议大家都耳熟能详：进对博士项目，再进对工业界实验室，做出机构觉得够有意思的工作，最终在前沿做出贡献。

Hooker 把自己的经历也放进这套筛选体系里看：她研究大规模下的效率，读了博士，又在 DeepMind 工作。有名的导师、重要的实习都有帮助；在错的时间对错的问题好奇，就可能被挡在门外。可是，学会用计算的方式表示世界，从来不是最终目的。真正的目的，是回答那些有了这些表示才变得可解的问题。能用上工具，才能碰到问题。

02

算力又加了一道门槛

在机构这道筛子之外，AI 又加了一道硬件筛子。Hooker 先提到 Merve 那条关于“GPU 穷人”和“GPU 富人”的推文，又举了匿名的 A、B、C 三家公司：只有少数几家实验室，有资源造出别人都在用的模型。她还引用了一张据称出自 Stanford 的地图，说明地域上的集中。这里要分清两件事：模型开发高度集中，不等于整个科学发现都集中。Stanford 的 AI Index 统计重要模型的产出，同时也承认，学术界在高被引研究上依然实力强劲。

这种集中会影响下游拿到的产品。模型开发转向工业界后，同一个模型被交付给需求千差万别的人。交付一刀切，算力花费也容易一刀切：简单任务和困难任务，本不该分到同样的算力预算。所以，要让更多人参与，光是允许大家用前沿模型还不够。构建者需要能自己决定怎么定制智能、把算力花在哪里。

03

自动化数据与训练循环

AutoScientist 把模型训练自动化，以此拆掉专业门槛。它希望人们直接从一个领域问题出发，而不是先花好几年，去学研究这个问题所需的训练知识。Hooker 描述的是一个从数据一直覆盖到对齐的循环，它会根据领域和数据类型调整自己的选择。

据 Hooker 介绍，在 Adaption 的内部评测中，AutoScientist 在不同规模和架构的模型上都胜过了研究人员给出的配置，其中包括稠密模型和混合专家模型。她的解释是搜索广度：单个研究者往往只熟悉某几类模型，自动化流程却能探索更大的配置空间，并不断积累经验。这里比较的只是这些评测中的训练配置，并不衡量通用的科研能力。

收益来自数据和模型选择的联合优化。 只允许智能体生成数据还不够。系统还得把控数据质量，并根据数据上的改动来选择模型怎么适配。调整数据集时学到的东西，连同领域知识和该领域其他组件积累的经验，一起反过来指导训练。数据准备和模型优化是相互耦合的决策，不是各管一段、做完就往下一环一扔的独立步骤。

解读结果时，要留意停止条件。Hooker 说，展示出来的胜率都在 60% 以上，是因为有一条预算规则：智能体流程一旦超过 60% 就可以退出。去掉这个阈值后，她说效果还在继续提升。所以，结果扎堆在这一带，反映的是实验何时被允许停下，而不是性能撞到了天花板。

用一个小小的 Python 函数，就能把当时这个阈值说清楚。胜率用小数表示时，恰好等于 0.60 并不满足“超过 60%”的条件，0.61 才满足。去掉目标值后，另外那个迭代预算依然有效：

```python def should_stop( win_rate: float, iteration: int, max_iterations: int, target: float | None = 0.60, ) -> bool: target_exceeded = target is not None and win_rate > target budget_exhausted = iteration >= max_iterations return target_exceeded or budget_exhausted

print(should_stop(0.60, 3, 10)) # False print(should_stop(0.61, 3, 10)) # True print(should_stop(0.61, 3, 10, target=None)) # False ```

这段代码只用来说明停止判断，不是 AutoScientist 的实现。单独的迭代上限是为了讲解而加的预算；Hooker 指出的实际情况，是胜率一超过目标就允许退出。

搜索时还会同时改动许多超参数。人类研究者往往不敢同时改好几处，这样实验更好解释，但也放不开手去探索各种组合。在 Hooker 看来，更广的配置搜索能让定制结果更可预测：利用领域知识，找到一套管用的配方，少把训练算力浪费在失败的尝试上。

04

从领域定制到交互

演讲前大约四周，beta 版刚刚发布。Hooker 说，医学和科学领域的兴趣尤其浓厚，法律和代码方向的应用也不少。在这些领域，通用模型可能力有不逮，最后一层定制非常关键。展示的领域分布图里，Medical 和 Science 排在最前面，柱子最长。

眼下的目标是缩短创新周期，提高训练跑出有用结果的概率。Hooker 说，下一步要做的是自适应测试时计算：根据任务决定推理时投入多少算力。在这次演讲里，这还是未来的工作，并没有实际演示。

可及性还包括语言和任务的覆盖。Hooker 说，团队从第一天起就决定覆盖 242 种语言。这是对覆盖范围的承诺，不代表模型在每种语言上都一样好。她还特别强调不可验证的任务：很多日常工作的好坏，没法简化成一个能自动核对的标准答案。这类任务处在学习问题的核心，尽管它们缺少“测试通过”“数值算对”这类方便的反馈。

设计的基本单位也随之改变。在旧的组织模式下，一个团队构建庞大的单体模型，另一个团队负责部署服务，再一个团队负责前端。到了会交互的系统，这种分工就不太够用了：系统行动效率如何、从环境中学到什么、学到的东西又怎样影响后续行为，都成了核心问题。真正的任务是通过交互持续适应，训练循环只是这个更大系统中的一环。

05

算力的回报点正在变化

如果每个用户仍然需要庞大的 GPU 集群，那么把训练专长自动化，也解决不了可及性问题。Hooker 用一个假设的提议把问题说得很具体：智能体随便用，但请自带一万张 GPU。只有算力门槛也跟着降下来，拆掉专业门槛才能真正改变谁能参与。

她的第二个论点出自 On the Slow Death of Scaling：多出来的算力，最划算的用法已经不再是扩大预训练模型的规模。这一区别直接影响基础设施：预训练高度耦合，适合大型、集中部署的集群；推理和其他一些算力用途，则更容易分布式执行。

| 算力分配 | 对基础设施的影响 | Hooker 强调的机会 | |---|---|---| | 更大规模的预训练 | 集中部署的算力，并需冗余 | 回报受架构限制 | | 推理及其他计算 | 更适合分布式算力 | 用好算力能换来更高回报 |

Hooker 认为，扩大预训练规模的回报在减弱，原因是架构已趋于饱和；换一种分配方式，每个 FLOP 能换来更多性能。这些是她对优化格局变化的判断，并没有针对某个具体工作负载给出量化对比。

Hooker 提到 Open LLM Leaderboard 上的一组对比：每天排名第一的 13B 参数以下模型，随着时间推移超过了更大的模型。这组对比用了哪些基准、怎么汇总、覆盖哪些日期，这里都没有交代。所以它能支撑她关于相对性能变化的讨论，却不能证明小模型在所有任务上都会胜出。她还认为，近来的规模增长没能复现前几代那种阶跃式的提升。

由此带来的机会，是更广阔的优化空间。性能可以取决于配方、算法、数据决策，以及模型周边的各种动作，不再主要靠把预训练做得更大。在这些地方，研究和自动化发现都能发挥作用，不必手握最大的集群。

事先准备的论证就这样回到了开头的问题。如果获取工具变得更便宜、受机构的限制更少，研究问题本身就可以成为起点。这并不是说科学判断会消失，而是说，更多人不必先走完那条规定好的职业漏斗，就能用上自己的判断。

06

更广泛的参与将如何发生

第一个观众提问，问的是民主化背后的机制。Hooker 估计，全世界懂得如何大规模训练前沿模型的人不到 5,000 个。在她看来，这些专长很大程度上是师徒之间口口相传的配置经验：宝贵、稀缺，也非常适合交给自动化去探索。

两种效应会一起起作用：

- 实验更便宜： 把训练决策自动化，能缩短创新周期。提出一个研究问题的成本降低了，人们能探索的问题会变多，觉得值得问的问题也会不一样。 - 算力的买法变了： 智能体和后训练阶段的计算同样能提升性能，却不一定像大规模预训练那样，需要堆大量集中部署的 GPU。这样一来，拥有基础设施和拥有好点子之间，谁更占优势就变了。

第二种效应并没有消除算力成本，它改变的是参与者参与竞争所需的资源。

07

适应性也改变了风险

下一个问题揭示了用户掌控权的另一面：有人可能把一个本来设计得行为安全的模型，改造成不安全的模型。Hooker 承认，工具更容易获得（包括开源）确实有真实的风险。系统越容易拿到，人们能拿它做的事就越多，其中也包括有害的用途。

她把定制和开源发布区分开来。AutoScientist 的目标是让用户掌控自己的模型，不管是在本地、私有环境还是公司内部。部署在哪里，本身并不决定系统或其模型会不会开放发布。

限制也有代价：它决定了谁能参与。Hooker 既不认同“开放毫无风险”的说法，也不接受“限制访问就能解决问题、不会带来别的后果”的假设。她的回答点明了其中的取舍，并没有提出一套技术手段来强制保证改造是安全的。

08

同时优化模型和它的框架

被问到哪些研究方向最有前景时，Hooker 指出了参数化存储与非参数化存储之间的平衡：前者存在模型权重里，后者存在权重之外。自适应系统必须决定什么该放在哪一边。这样一来，学习不只是获取知识，还要决定把知识放在哪儿。

接着，她把数据与模型联合优化的经验延伸到框架（harness），也就是组织模型交互的外围系统。面向框架的 AutoScientist，需要把框架和模型放在一起优化。单独看对某个组件有利的选择，未必能让两者合起来表现最好。Hooker 认为这是一个长周期问题，涉及联合决策和协同训练，而不是给一个固定的模型单独找最好的外壳。

09

大模型依然重要

后面又有一位观众直接挑战了算力论点。强化学习和微调仍然非常吃 GPU，大模型尤其如此。较小的前沿模型也常常通过蒸馏，向更大的教师模型学习。如果它们的能力依赖于上游昂贵的模型，那么表面上的规模缩小，究竟能在多大程度上扩大参与？

Hooker 承认前沿模型仍然很大。她的主张比“规模不再重要”要窄：她预测，在现有架构下，前沿实验室不会再把预训练模型规模扩大 4 倍。新架构有可能改变这个上限。她并不是建议所有人都去用 0.8B 的模型；她预计，在现有规模上限附近做开发的构建者之间，竞争会更加公平。

蒸馏依然有用，因为更好的数据能让模型更充分地利用自身容量。Hooker 还预计，与后训练相关的技术会前移到预训练阶段，让学习的质量和组织方式成为更有力的杠杆。超大模型也许仍能在任务分布里那一小段长尾上带来收益。悬而未决的工程问题是：这些收益值不值得多花那么多预训练算力。

10

消除眼前的算力障碍

最后一个问题是：有没有计划开源模型设置？Hooker 的回答是去用 beta 版，并说他们正在免费提供 GPU，帮大家迈过算力门槛。这是演讲中给出的具体使用方案，不是明确的开源承诺，也不保证永久免费提供算力。结尾把参与的论点落到了实处：让手里有领域问题的人，能够开始做实验。
