始于一篇开源论文：FlashNorm

幻灯片原文
Filip Makraduli co-authored FlashNorm with Nils Graef and others. The paper folds normalization weights into the next linear layer and defers the RMS divide, allowing the operations to run in parallel.

[1:05](https://www.youtube.com/watch?v=c1hGBoWw20A&t=65s) [A screenshot of the FlashNorm paper appears above a note connecting it to the talk.](https://assets.ai.engineer/sites/aiecode2025/sha256/da669ba4292526f693446f9de4fb92b64c23d2731829656e70866098a9f8922f.webp)

WHERE THIS STARTED

It began with an open-source paper: FlashNorm

[Submitted on 12 Jul 2024 (v1), last revised 24 Apr 2026 (this version, v5)]
FlashNorm: Fast Normalization for Transformers
Nils Graef, Filip Makraduli, Andrew Wasielewski, Matthew Clapp

Normalization layers are ubiquitous in large language models (LLMs) yet represent a compute bottleneck: on hardware with distinct vector and matrix execution units, the RMS calculation blocks the subsequent matrix multiplication, preventing parallel execution.

We present FlashNorm, an exact reformulation of RMSNorm followed by a linear layer that (i) eliminates the normalization weights by folding them into the subsequent linear layer, and (ii) defers the scalar RMS normalization to the output of the matrix multiplication, enabling the two operations to execute in parallel.

Additionally, by the scale invariance of RMS, an RMSNorm followed by a linear layer followed by another RMSNorm allows the first RMSNorm to be eliminated entirely -- a mathematically identical simplification that removes the pre-attention RMSNorm in models using QKV-normalization (e.g., Gemma-4) and in MLA-models with latent normalization (e.g., DeepSeek-V2, Mistral Small 4, and OpenMythos).

The same techniques extend to LayerNorm, Dynamic Tanh (DyT), feed-forward networks with GLU variants, and RoPE-based attention.

On an NVIDIA T4 GPU, FlashNorm achieves 33 - 35% lower latency on the norm-then-project operation in the compute-bound (prefill) regime at SmolLM2-135M scale, and 12 - 14% at Llama-7B scale. We verify zero-loss weight folding on three models.

Beyond inference speed, FlashNorm simplifies model implementations by reducing parameter tensor count.

FlashAttention 推迟 softmax，FlashNorm 推迟 RMS

幻灯片原文
FlashAttention normalizes after multiplying, avoiding a huge score matrix in memory. FlashNorm similarly defers the RMS divide until after the weight multiply, so the matmul can start sooner.

[1:31](https://www.youtube.com/watch?v=c1hGBoWw20A&t=91s) [Two columns compare deferred normalization in FlashAttention and FlashNorm.](https://assets.ai.engineer/sites/aiecode2025/sha256/efccaac201c618d9aff9f6b59bb84f887c274c63e31697bc153dcee608d01b9a.webp)

THE SAME MOVE, ONE LAYER OVER

FlashAttention defers the softmax, FlashNorm defers the RMS

FLASHATTENTION

The softmax waits until after the multiply

Attention normally finishes the softmax before it can use the scores. FlashAttention multiplies first and normalizes at the end, so the huge score matrix never has to exist in memory.

FLASHNORM

The RMS divide waits until after the multiply

RMSNorm normally divides before the matmul can start. FlashNorm multiplies by the weights first and divides at the end, so the norm stops holding up the matmul. Same move, one layer over.

GPU 计算周围的三种开销

幻灯片原文
GPU time goes into launching work, reading weights and waiting for normalization. Fusing reduces launches and memory trips, folding reduces reads, and deferring the divide lets normalization and matmul run in parallel.

[3:05](https://www.youtube.com/watch?v=c1hGBoWw20A&t=185s) [Three columns explain starting work, moving data, and waiting for normalization.](https://assets.ai.engineer/sites/aiecode2025/sha256/3770e0efd4c80d7ace81e0ac3cbc9ce646feb29e36e9485f6ed77047164f47be.webp)

WHY · THE THREE COSTS

The GPU is not slow at math, it is slow at everything around it

01
STARTING WORK
Every piece of GPU work costs about 10 microseconds just to start, and RMSNorm’s math takes about 1. One decoded token starts RMSNorm 33 times. Fusing each norm into the matmul next to it removes those starts.

02
MOVING DATA
Making one token means reading every weight in the model from memory and using each one once. The math finishes instantly; the reading does not. Folding means less to read, fusing means fewer trips.

03
WAITING IN LINE
The matmul cannot start until the norm in front of it finishes, in every layer, for every token. Deferring the divide removes the queue: norm and matmul run at the same time.

Bigger batches share the weight reading across requests, but the norm still runs for every token and the matmul still waits for it.
Source: FlashNorm, arXiv:2407.09577.

三个 FlashNorm 改写

幻灯片原文
FlashNorm folds the gain into the weight matrix, moves the RMS divide after a bias-free matmul, and removes the first normalization when a second RMSNorm follows.

[4:22](https://www.youtube.com/watch?v=c1hGBoWw20A&t=262s) [Equations summarize weight folding, deferred normalization, and cancellation of pre-normalization.](https://assets.ai.engineer/sites/aiecode2025/sha256/2ace68c436175da75f160e3d9bdf13e501ec03cd5eff3ce9465d39bb8a030cde.webp)

THE THREE REWRITES

FlashNorm: three exact rewrites of RMSNorm → linear

z = RMSNorm(a) W,   RMSNorm(a)ᵢ = aᵢ/RMS(a) gᵢ,   RMS(a) = √(1/n ∑ᵢ aᵢ²),   W*ᵢ,ⱼ = gᵢ Wᵢ,ⱼ   (i.e. W* = diag(g) W).

Proposition 1: Weightless normalization
fold the gain into the weight

W* = diag(g) W  ⟹  z = a/RMS(a) W*.

The gain g is deleted from the checkpoint, saving one weight and one multiply. Holds with or without a bias.

Proposition 2: Deferred normalization
defer the divide past the matmul

z = a/RMS(a) W* = (a W*) · 1/RMS(a).

Bias-free layer. Now the matmul aW* and the reduction 1/RMS(a) are independent, so run them in parallel and combine with one scalar multiply.

Proposition 3: Cancellation of pre-normalization
drop a whole RMSNorm

RMSNorm(a/RMS(a) W*) = RMSNorm(a W*).

In the pattern RMSNorm → linear → RMSNorm the first norm is redundant (RMS is scale-invariant), so it can be removed entirely.

把增益折叠进下一层

幻灯片原文

[4:57](https://www.youtube.com/watch?v=c1hGBoWw20A&t=297s) [Before-and-after diagrams show the normalization gain folded into the linear weight matrix.](https://assets.ai.engineer/sites/aiecode2025/sha256/9caea08a93e18a37c8b0996b5ea31473a0d5c068570dd00c416d77115408899d.webp)

PROPOSITION 1 · WEIGHT FOLDING

Fold the gain into the next layer, delete the norm weights

× g ≡ × diag(g)

Before (2 steps)
a → ÷ RMS → × g → W → z

fold in

After (folded)
a → ÷ RMS → W* → z

W* = diag(g) W

The gain g and the weight W fold into one matrix W*, computed once offline. RMSNorm becomes weightless: one less weight load and one less multiply per norm.

推迟标量除法

幻灯片原文
The matmul and 1/RMS(a) run in parallel, then their results are multiplied. Because RMS is one scalar per token, moving the divide after the matmul gives the same answer.

[5:26](https://www.youtube.com/watch?v=c1hGBoWw20A&t=326s) [Diagrams compare serial normalization and matrix multiplication with parallel matrix multiplication and RMS reduction.](https://assets.ai.engineer/sites/aiecode2025/sha256/3cc8d28f89fd7dc7bc162b10d532f0d5f8e86f6cb04ce67ef3ace3a428d75197.webp)

PROPOSITION 2 · DEFERRED NORMALIZATION

Defer the scalar divide so the matmul and the norm run at once

Before (serial): a → ÷ RMS → · W* → z
waits

After (parallel): a → a W* and 1/RMS(a) → × → z
scalar

1/RMS is just one number per token, and multiplying by one number gives the same answer before or after the matmul. So do the matmul first and divide after: the norm stops blocking the matmul.

张量核心与 CUDA 核心

幻灯片原文
Tensor cores run the matmul while CUDA cores can compute the 1/RMS reduction. Using the separate hardware in parallel lets deferred normalization fill otherwise idle CUDA cores.

[7:16](https://www.youtube.com/watch?v=c1hGBoWw20A&t=436s) [Two columns describe tensor cores running matrix multiplication and CUDA cores running the RMS reduction.](https://assets.ai.engineer/sites/aiecode2025/sha256/f4c23f625e08ff4352abd241456357f34953875b8a5efe71fe7235c395f92ca0.webp)

WHY IT CAN OVERLAP

Tensor cores and CUDA cores are separate silicon

TENSOR CORES
Run the matmul
Dedicated matrix-multiply hardware: blazing fast at matmuls and useless at everything else.

CUDA CORES
Run the 1/RMS reduction
General vector lanes: elementwise ops, reductions, square roots. They sat idle during the matmul, so deferred normalization fills them.

顺序调度与 FlashNorm 调度

幻灯片原文
FlashNorm overlaps the matmul with RMS computation, then scales the output. In the paper’s n = 512, m = 128 example, the schedule falls from 24 cycles to 17 cycles.

[7:57](https://www.youtube.com/watch?v=c1hGBoWw20A&t=477s) [Timeline compares a 24-cycle sequential schedule with a 17-cycle FlashNorm schedule that overlaps matrix multiplication and RMS computation.](https://assets.ai.engineer/sites/aiecode2025/sha256/4c2102679df063a002728d655e95ea25cb6718663a5b3823e914a8a785d12a30.webp)

SET THE SCENE · WHAT OVERLAP BUYS

Sequentially, the matrix unit idles while RMS computes

SEQUENTIAL  24 cycles
MATRIX UNIT: IDLE, WAITING FOR RMS | MATMUL A · W*
VECTOR UNIT: RMS + SCALE

FLASHNORM  17 cycles · 29% fewer
MATRIX UNIT: MATMUL A · W*
VECTOR UNIT: RMS | SCALE | SAVED

Same arithmetic, two schedules: the scalar 1/RMS gates the matmul, and FlashNorm removes the gate. Paper example, n = 512, m = 128. Source: FlashNorm Fig 8, arXiv:2407.09577.

两条流与一次汇合

幻灯片原文
Matrix multiplication and RMS reduction run on separate CUDA streams, followed by post-scaling. The join was implicit, allowing a race when matrix multiplication had not finished.

[8:31](https://www.youtube.com/watch?v=c1hGBoWw20A&t=511s) [CUDA example launches matrix multiplication and RMS reduction on separate streams, then launches post-scaling on a join stream.](https://assets.ai.engineer/sites/aiecode2025/sha256/8acbeb49e4849d9b3ed333f85249107939638aacf20512b0f85f0a2438957a3d.webp)

THE REALIZATION

The parallel plan is two streams and a join

CUDA

// a stream is an ordered queue of GPU work; separate streams may overlap,
// and NOTHING orders work across streams unless you say so.
// plan: matmul and RMS reduction on two streams at once, then post-scale
// the matmul output by the per-token scalar 1/RMS.
matmul<<<grid, block, 0, stream_A>>>(x, W_star, y_unscaled);  // tensor cores
rms_recip<<<grid, block, 0, stream_B>>>(x, s);               // CUDA cores

// join: y = y_unscaled * s  (this is where it went wrong)
post_scale<<<grid, block, 0, post_stream>>>(y_unscaled, s, y);

so it gets last step’s y (the buffer is reused)

no barrier: nothing forces it to wait

time →

两个事件，模型又能正常往下说了

幻灯片原文
The fix records events after the matmul and RMS reduction, then makes post-scaling wait for both. The result matched the reference byte-for-byte at every length.

[10:05](https://www.youtube.com/watch?v=c1hGBoWw20A&t=605s) [CUDA code records two events and makes the post-scale stream wait for both.](https://assets.ai.engineer/sites/aiecode2025/sha256/291ee821470c1f70844328cca19e401397a059f33b2a0d1632d55de4963517cd.webp)

THE FIX
Two events, and the model spoke forward again

CUDA

// dependency-only events are created with cudaEventDisableTiming elsewhere.
cudaEventRecord(event_A, stream_A);              // mark end of matmul
cudaEventRecord(event_B, stream_B);              // mark end of RMS reduction
cudaStreamWaitEvent(post_stream, event_A);       // post-scale waits for A
cudaStreamWaitEvent(post_stream, event_B);       // post-scale waits for B

post_scale<<<grid, block, 0, post_stream>>>(y_unscaled, s, y);  // now safe

// ~5 lines. byte-for-byte against the reference at every length. it spoke forward.

权重折叠、CUDA 流，以及让我的模型倒着说话的那个 bug

Filip Makraduli 讲解了 FlashNorm 如何把工作移出 RMSNorm 的关键路径——以及 CUDA 流之间缺失的一个依赖，如何把一个代数上完全正确的优化变成了过时的模型输出。

01

为什么一个几乎没有算术的层也会花掉真实的时间

RMSNorm performs only a small share of a transformer’s arithmetic, yet it can occupy a meaningful share of inference time. Filip Makraduli opens with this discrepancy in work he co-authored with Nils Graef: making normalization cheaper requires looking beyond the amount of math to the work surrounding it. 2:02

In some of the experiments, one decode step starts RMSNorm thirty-three times. That count depends on the model, but it explains how a small operation becomes expensive through repetition. Each launch starts work; intermediate values move through memory; subsequent matrix multiplication waits for normalization to finish. A GPU’s arithmetic can be fast while this sequence still takes substantial wall time.

FlashAttention supplies the opening analogy: reducing communication between memory and computation can matter as much as reducing arithmetic. FlashNorm applies that way of thinking to normalization and its following projection. Fusion reduces separate launches, weight folding removes runtime work involving the normalization gain, and deferred division shortens the wait before matrix multiplication can begin.

02

折叠增益，再移动标量除法

The first two propositions change where normalization work happens. The learned gain can move into the projection weights before inference. The input-dependent scalar division must still happen at runtime, but it can move after the matrix multiplication. These changes have different implementation costs. 4:58

- Weightless normalization: Fold the normalization gain and projection weights into one matrix, \(W^*\), offline. The projection then absorbs the gain multiplication that previously belonged to normalization. “Weightless” describes the normalization operation after this transformation; the learned gain’s effect remains in the folded matrix. - Deferred normalization: Compute the projection and the RMS scalar independently, then apply the scalar division to the projection’s result. Matrix multiplication can start immediately instead of waiting for the normalized input. - Canceling pre-normalization: In the double-normalization configurations discussed in the talk, scale invariance allows one normalization to be removed. This depends on the architecture and implementation; it is not a general rule that any two RMSNorm layers can be collapsed.

What makes the projection independent of the RMS calculation? Using a column-vector convention, let \(x\) be the input, \(g\) the learned gain, \(W\) the projection matrix, and \(r(x)\) the scalar RMS denominator. The rearrangement is:

\[ y = W\left(\frac{g\odot x}{r(x)}\right) = \frac{W\,\operatorname{diag}(g)\,x}{r(x)} = \frac{W^*x}{r(x)}. \]

The gain is fixed, so \(W^*=W\operatorname{diag}(g)\) can be prepared offline. Both remaining calculations depend on \(x\), but neither needs the other’s result. Only the final division needs both.

Transformer Tricks provides the straightforward checkpoint transformation for weight folding. Realizing the second proposition’s parallel execution requires kernel work. Algebra removes the dependency between the two calculations; the implementation still has to schedule them concurrently and combine their results correctly.

03

那段不断重复“because”的续写

The implementation problem first appeared as a language problem. A prompt about how the transformer architecture revolutionized NLP ended with “because.” The continuation repeated that word, and longer generation showed repetition with a one-step lag. The model seemed to produce outputs from the past. 6:40

Deferred normalization divides the work between hardware suited to different operations. Tensor cores perform the matrix multiplication. CUDA cores handle operations such as reductions, square roots, and element-wise calculations needed for the RMS path. In the sequential arrangement, the matrix unit waits while the vector unit computes normalization and scaling. FlashNorm aims to overlap the projection with the RMS calculation.

Makraduli implemented this overlap in CUDA. The code initially looked plausible: unit tests passed, and perplexity testing suggested similar quality. Long generation exposed the failure those checks had missed. The optimization had introduced a timing dependency that the successful tests did not establish was correct.

04

后缩放必须等待两条流

The join between the two CUDA streams was implicit. Post-scaling could read its input before one stream had finished the current matrix multiplication. The buffer still contained an old value, so the final operation consumed stale data. That race condition explains the observed lag: the arithmetic transformation was valid, but the result being scaled did not necessarily belong to the current work. 9:11

The fix makes completion explicit. Mark the end of the matrix multiplication, mark the end of the RMS calculation, and make post-scaling wait for both streams. The two producers can still run in parallel. Their consumer simply cannot start until both required results are ready. 10:10

Where does parallelism end and synchronization become necessary? The diagram separates the independent calculations from their shared consumer. Neither calculation has to wait for the other; post-scaling has to wait for both. This is the dependency the implicit join failed to enforce.

With those waits in place, Makraduli reports that the bug disappeared—the model could “speak forwards instead of backwards.” The title’s backwards speech refers to stale, lagging outputs, rather than text generated in reverse order. The developing example ends with a scheduling repair, without changing the intended normalization algebra.

05

一个折叠后的检查点给了你什么

The experiments return to the distinction between changing weights and changing execution. Most tests discussed use Llama models, with separate experiments for deferred normalization and a fully fused kernel. Even weight folding alone shows improvement. The practical first step is therefore smaller than implementing the complete CUDA optimization. 10:40

The recording’s description reports a 33–35 percent speedup for the normalization-plus-projection operation. That is an operation-level result, not a whole-model inference speedup. The benchmark conditions behind that range are not specified here, so it should not be treated as a prediction for every model or deployment.

- Checkpoint transformation: The repo’s Flashify operation applies weight folding. The result behaves as a new checkpoint and works with torch.compile; Makraduli also reports compatibility with quantized models. - Execution transformation: Deferred normalization needs the lower-level implementation that overlaps RMS calculation and matrix multiplication. Loading folded weights alone does not supply that scheduling change.

Transformer Tricks collects the algebraic transformations and the associated paper. Makraduli also describes publishing transformed models on Hugging Face so others can try a prepared checkpoint. That makes the weight-folding portion easier to adopt, while the stream bug illustrates the additional engineering required to turn deferred normalization into a correct runtime implementation.

06

算子实验需要对推理的控制权

A modified checkpoint raises the next question: how do you deploy it without rebuilding the surrounding infrastructure? Superlinked’s inference engine provided Makraduli a way to put custom Hugging Face checkpoints on a cluster. He describes hackathon participants bringing fine-tuned checkpoints, as well as using this route to test research transformations such as FlashNorm. 13:12

Kernel changes require more control than an ordinary model request. With open-source cluster software and open-source inference, an experiment can modify the execution path as well as the weights. A rented endpoint that does not expose its inference implementation makes that work much harder. The desired combination is portability, freedom to modify kernels, and enough production infrastructure to test the result at scale.

PSI adds several capabilities around that experiment:

- Multiple-model workflows: A Flashified model can run alongside other models in an agentic task, allowing the optimization to be tried inside a larger use case. - Queuing and GPU sharing: Smaller models can use the same GPU, with models switched around to manage GPU costs. Makraduli found this useful while working with smaller Llama models and small agents. - API control: Model configurations and the cluster can be controlled through an API, reducing the infrastructure work needed to support research. - Other model types: The catalog includes embedding and re-ranking models, extending the deployment setup beyond generation.

The ending connects two kinds of ownership: open weights let you fold the gain into a checkpoint; control over inference lets you change how that checkpoint executes. Makraduli closes by inviting questions and contributions through LinkedIn, pointing to the paper, Transformer Tricks, PSI, and work appearing in pull requests around vLLM and Hugging Face. The research becomes useful through both a correct kernel and a deployment environment that permits it to run.

要点总结

  • RMSNorm 的推理成本包括反复的启动、内存搬运和等待。它在算术上占比很小，并不意味着在实际耗时上占比也小。
  • 权重折叠在离线时把学到的增益吸收进投影权重。推迟标量除法后，投影和 RMS 计算就可以并发进行。
  • 后缩放必须显式地等待两条 CUDA 流。没有这些依赖，即使单元测试和困惑度检查都通过，它也可能读到缓冲区里的旧值。
  • 折叠后的检查点可以与熟悉的工具配合使用，但要实现算子级的重叠，既需要掌控模型权重，也需要掌控推理实现。
