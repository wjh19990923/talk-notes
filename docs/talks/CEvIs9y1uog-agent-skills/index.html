别再重建智能体：把领域专长打包成技能

Barry Zhang 和 Mahesh Murag 讲解了由指令、脚本和资源组成的可复用文件夹，如何在不重建底层架构的情况下，赋予通用智能体专门的专业能力。

别再重建智能体：把领域专长打包成技能

01

真正的差距是专业知识，而不是智能

Barry Zhang 和 Mahesh Murag 认为，智能体手上的任务虽然各不相同，底层却越来越像。与其为每个领域单独做一个带定制脚手架的智能体，不如用一个通用智能体，再接上一个运行环境。在这种架构里，代码成了通往各种数字工作的通用接口，而必要的脚手架可以简单到只有一个 shell 和一个文件系统。0:21 1:20

拿做财务报告来说：智能体可以调 API 收集信息，把数据整理到文件里，用 Python 分析，最后汇总成一份像样的文档。这些步骤并不需要专门为财务报告设计的智能体架构，需要的是三样东西：一个足够强的模型、一个好用的运行环境，以及“这件事实际该怎么做”的知识。1:20

关键就在最后这一样。Zhang 拿数学天才和报税专家做对比：能把事情可靠地做好，靠的是积累下来的操作经验，而不是每次都从第一性原理重新推一遍规则。两位讲者认为，当前智能体最大的短板有三个：事先缺少上下文，很难吸收组织内部的专业经验，也很难随时间越用越好。2:18

- 通用智能体只要有代码、shell 和文件系统，就能跨领域干活。 - 做财务报告可以组合几步：调 API 查资料、整理文件、用 Python 分析、汇总成文档。 - 要可靠地完成专业工作，光靠智能不够，还需要操作经验和事先给足的上下文。

02

技能就是一个让流程可复用的文件夹

Agent Skills（智能体技能） 是一组组织好的文件，里面装的是可以自由组合的操作知识。它刻意设计得很普通，就是一个文件夹：人和智能体都能用熟悉的工具来创建，可以放进 Git，可以通过 Google Drive 分享，也可以打包发给队友。真正重要的抽象不是又一个智能体框架，而是一个可以随身带走的包，里面写着某件具体的事该怎么做。2:18

技能里还可以放脚本，充当工具。Zhang 说，他多次看到 Claude 为了给幻灯片排版，一遍遍重新写同一个 Python 脚本，于是干脆让它把脚本存进一个技能，以后直接复用。直接运行存好的脚本，流程更稳定、更省事，也不用一次次重新生成同一套解决办法。3:33

两位讲者把这类脚本和传统工具做了对比：传统工具的说明可能写得含糊，模型没法轻易改它的实现，而且工具描述会一直占着上下文窗口。放在文件系统里的代码则不同，它随时可用，却不必一直占用上下文，智能体需要时还能打开查看、动手修改。这样一来，文件系统既是干活的地方，也是一个长期保存可复用流程的仓库。3:33

技能多了怎么办？靠的是渐进式披露。一开始，模型只拿到元数据，知道有这么一个技能；等任务真正用得上时，智能体才去读 skill.md，里面是主要说明和其余材料的目录。其他文件按需取用，不会一股脑全塞进上下文窗口。3:33 4:39

- 技能把可组合的操作知识装进普通文件夹，团队可以做版本管理、互相分享。 - 复用现成脚本，代替一遍遍重新生成代码，执行起来更稳定、更高效。 - 渐进式披露：先只给技能的元数据，需要时再加载 skill.md 和其他材料。 - 放在文件里的工具可以随时查看和修改，又不会一直占着上下文窗口。

技能的渐进式披露 智能体需要什么，技能信息就逐步加进上下文。 - 技能元数据——一开始只说明有这个技能。 - skill.md——提供核心说明和目录。 - 整理好的资源——脚本和其他文件随时可用。 - 技能元数据 → skill.md（需要时读取） - skill.md → 整理好的资源（目录指明有哪些文件）

03

生态涵盖基础知识、合作伙伴知识和企业知识

Murag 把他们看到的技能分成三大类：基础技能、第三方合作伙伴的技能，以及组织内部的技能。基础技能的例子有：用来创建和编辑专业办公文档的文档技能，以及 K-Dense 做的科研技能，涵盖电子病历（EHR）数据分析，以及更好地使用常见的 Python 生物信息学库。这些例子说明，技能既能补充通用的工作能力，也能带来更专门的领域流程。4:59

合作伙伴做的技能，是教智能体怎么把某个产品用好。Browser Base 为自家开源的浏览器自动化工具 Stagehand 做了一个技能；Notion 也发布了技能，帮 Claude 读懂一个 Notion 工作区，并在里面做调研。这里的专业知识不只是“能访问这个软件”，而是“在具体情境下怎么用好它”。4:59 6:10

企业技能装的是外人不可能猜到的内部知识。Murag 说，他们和一些财富 100 强公司聊过，这些公司用技能来固化组织里的做事方式，以及一些很特殊的内部软件流程；还有服务成千上万名开发者的研发效能团队，用技能教智能体遵守内部的代码风格。共同点在于：最懂这项工作的人，可以把自己的流程交给大家共用的智能体。6:10 7:12

技能的复杂程度也相差很大。最简单的，就是一个写着基本说明的 skill.md Markdown 文件；复杂的，可以包含可执行文件、二进制文件、代码、脚本、各种文件和素材。Murag 说，金融、招聘、会计和法务领域的人也在做技能。这说明扩展一个通用智能体，并不只是写代码的人才能做的事。7:12 8:08

- 技能分三类：基础能力、合作伙伴提供的产品经验、组织内部的流程。 - 基础技能的例子：编辑专业文档、分析电子病历数据、Python 生物信息学工作流。 - 合作伙伴和企业技能涵盖 Stagehand 的用法、在 Notion 里做调研、内部软件惯例和组织的代码风格。 - 技能可以简单到只有一个 skill.md，也可以复杂到包含可执行文件、脚本、代码和素材。

04

把运行时、连接性和专业知识分开

他们提出的架构分好几层：智能体循环管理模型内部的上下文和 token 流转；运行环境提供文件系统，以及读写代码的能力；MCP 服务器把智能体连到外部的工具和数据；技能库则提供针对具体任务的流程，只在用得上时才加载。构建者不用再做一个又一个智能体，只要给同一个通用智能体配上合适的连接和专业知识就行。9:07

MCP 和技能是互补关系，不是竞争关系。Murag 说，已经有开发者在做这样的技能：把多个 MCP 工具串成更复杂的工作流。MCP 负责连接外部世界，技能负责提供用好这些连接所需的专业知识。前者决定智能体能碰到什么，后者决定它知道怎么把事做成。8:08 9:07

两位讲者说，Anthropic 面向金融服务和生命科学的产品已经采用了这种模式：每个产品都把 MCP 服务器和技能组合起来，让 Claude 更好地为这些领域的专业人士服务。不过他们讲的是架构思路，而不是量化结果：演讲中没有给出这些产品的性能提升数据、对比评测结果，也没有详细的实现细节。10:09

- 智能体循环管理模型上下文和 token 流转，运行环境提供文件和可执行代码。 - MCP 服务器提供外部工具和数据，技能提供使用它们的操作知识。 - 技能可以把多个 MCP 工具编排成更复杂的、连接外部系统的工作流。 - 金融服务和生命科学的产品，都把领域专用的 MCP 服务器和技能组合在一起。

05

像对待软件一样对待复杂的技能

技能里的代码和配套材料越积越多，两位讲者预计，它需要更严格的工程实践。Murag 特别提到了测试和评测，包括一些工具，用来判断智能体在某个任务上有没有加载、触发对的技能，以及最终产出是否达到预期质量。他们把这些当作有待发展的方向，而不是已经成熟的方案。7:12 10:09

版本管理是另一个还没解决的运维需求，因为改了一个技能，用它的智能体行为也会跟着变。Murag 认为，团队应该能追踪这种演变，留下清晰的变更脉络。他还提议，技能应当明确声明自己依赖哪些其他技能、MCP 服务器，以及运行环境里的哪些包，这样智能体在不同环境里运行时，行为会更可预测。11:14

代价是：接口简单，不代表包里面也简单。一个技能可能一开始只是一份很短的说明文件，但复杂的版本最终可能要花几周甚至几个月来构建和维护。可组合性也带来一连串新问题：什么时候触发、彼此是否兼容、依赖怎么管、质量怎么保证，以及某个环境里是否具备这个技能需要的一切。7:12 10:09 11:14

- 复杂的技能可以打包可执行文件、二进制文件、脚本、素材和其他配套文件。 - 设想中的评测工具，会检查技能有没有选对、有没有被触发，以及产出质量如何。 - 版本管理要把技能的改动和智能体行为的变化一起记录下来。 - 明确声明对其他技能、MCP 服务器和环境包的依赖，能让运行时的行为更可预测。

06

构建一个共享的、不断演进的流程知识层

更长远的愿景，是一个由整个组织里的人和智能体共同维护的集体知识库。在这种模式下，反馈和组织流程会变成可复用的能力，让多个智能体和新加入的同事都能受益，而不是困在某一次对话里。Murag 还把这个想法延伸到组织之外：别处做出来的好技能，也能让另一个团队的智能体变得更好，就像外部做的 MCP 服务器能扩展智能体的用途一样。11:14 12:26

Zhang 认为，技能是朝持续学习迈出的实实在在的一步：它是一种标准化、能长期保存的产物，同一个智能体的未来版本也能拿来用。他也明确划定了边界：技能并不能装下所有类型的记忆和信息，只能装适用于特定任务的操作知识。技能很灵活，能力可以随情况变化随时添加、修改或删除，尤其适合相关信息经常变动的场景。13:20

智能体自己也能参与搭建这一层知识：Zhang 说，Claude 已经可以借助一个“技能创建器”技能来创建新技能。最后他打了个比方：模型相当于处理器，智能体运行环境相当于操作系统，而技能是应用层，开发者在这里写入领域专业知识和自己独到的做法。落到实践上，就是把创造力花在可复用的能力上，而不是一遍遍重造底层的通用智能体。14:24 15:31 15:42

- 共享的技能库能把组织知识分发给各个智能体、同事乃至更广的社区。 - 持久保存的技能，能把特定任务的操作知识传给以后的智能体会话，但并不涵盖所有形式的记忆。 - Claude 可以借助“技能创建器”技能来创建技能，也能添加、修改或删除能力。 - 用计算机来类比：模型是处理器，智能体运行环境是操作系统，技能是应用程序。

把智能体架构看作一个计算技术栈 技能是建在智能体运行环境和模型之上的应用层。 - 技能——应用层，承载领域专业知识。 - 智能体运行环境——操作系统层，协调模型的执行。 - 模型——类似处理器的底层，提供核心能力。

要点总结

  • 一个能干的通用智能体仍然需要 领域专业知识；可复用的技能把这种专业知识打包起来，而不必为每个领域设计一种不同的智能体架构。1:20 2:18
  • 技能是有组织的文件夹，包含 流程指令、可复用脚本和辅助资源，其中 skill.md 是主要的指令和导航文件。2:18 3:33 4:39
  • 渐进式披露 先只暴露技能的元数据，仅在任务需要时才加载详细的指令或文件，从而保护上下文窗口。3:33 4:39 9:07
  • 在正在形成的智能体技术栈中，MCP 提供与外部工具和数据的连接，而技能提供编排有用工作流所需的流程性专业知识。8:08 9:07
  • 随着技能变得更复杂，团队需要软件式的 评估、版本管理、依赖管理和运行时可预测性；讲者把这些列为正在推进的开发重点。10:09 11:14
  • 由智能体创建并共享的技能为 可迁移的流程性学习 提供了一条路径，但它们不是完整的记忆系统，也无法捕获每一种信息。12:26 13:20 14:24
