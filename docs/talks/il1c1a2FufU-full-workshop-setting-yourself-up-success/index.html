完整工作坊：为成功做好准备

Jason Liu 的工作坊把语音输入、应用上下文、一个基于 Git 的记忆库和持久的对话线程连接起来，构建出能收集上下文、跟进落实并产出可审查成果的工作流。

熟悉 Git、Markdown 和基本的编程智能体工作流会有帮助；工作坊会在出现时讲解其中的技能、记忆和自动化概念。

01

幻灯片早已是工作流的一部分

The slides are running on localhost inside Codex’s in-app browser. When Jason Liu notices something he dislikes, he can select it with the annotation tool and ask Codex to revise it. The presentation is itself a work product inside the system he is demonstrating. The same workspace supports his prototypes, eval experiments, iMovie launch videos, developer partnerships, education, and operations—from meeting notes to documents used with vendors and funding programs.

The objective is to make that work productive, rather than maximize token consumption. This workshop expands the keynote into a setup exercise: install Codex, bring in a prepared monorepo containing skills and working conventions, and try the workflows as they appear. The bottleneck Liu wants to address is coordination. When colleagues each run several projects at once, the important detail may be a missed Slack message or an unanswered foundation email. Producing more work creates more work to keep track of.

02

给持续进行的工作一条持久的线程

Liu reports using five-week-old threads containing roughly 400 sub-agents while retaining a useful understanding of their jobs. That experience with compaction underlies his preference for keeping work alive in an existing conversation. Alongside persistence, he emphasizes reducing the friction of giving instructions: a foot pedal has one button for transcription and another for Enter, so he can dictate a change and return to talking with coworkers. AppShots provides another quick input path, and its shortcut can lead users through installing Computer Use.

Reusable team practices matter more than individual token totals. A skill used before pull-request review can apply a style guide and catch recurring mistakes across a team. Liu describes an internal finalize-the-Codex-app skill, plus review skills modeled on Charlie’s and Dominic’s feedback. The Charlie version draws on a year of pull-request reviews, turning repeated corrections into instructions that can be applied before another reviewer has to make them.

Pinned threads then become recognizable owners of work. In the workshop, threads can list other pinned threads, rename them, and send messages to one another. A person can manage several project threads; a coordinating thread can, in turn, work with threads assigned narrower responsibilities. The practical starting point is to pin a thread, name it for its project, let it delegate, and record developments in a memory vault. An automation can wake it again later. Liu’s experience leads him to reject the older habit of restarting every long conversation or opening a separate session for each feature and review. The rest of the workflow follows three stages: bring context in, work with it, and take action outside the conversation.

03

带入杂乱的上下文并连接各个应用

Dictation is useful because it lets the user supply the messy version of a problem without first editing it into a polished request. Liu describes speaking as roughly three times faster than typing, though the workshop does not measure that comparison. His more consequential example is a long voice memo: he vaguely remembers meeting Charlie about the Agents SDK, and the agent searches meeting messages to identify the conversation and use it in a memo or tracker. He describes looking through roughly 35 messages in that example. An AI can absorb the tangents and retrieval work that would make the same voice memo burdensome for a coworker.

Once input is easier, add the capabilities needed to act on it. A skill is a small collection of instructions, files, and possibly scripts; a plugin packages a library of capabilities. Liu’s setup sequence is straightforward:

1. Open Plugins in the sidebar and install the services used in daily work, such as Slack, Gmail, or Teams. 2. Set up the Chrome extension and Computer Use. 3. Add other relevant services, such as Notion, Linear, and Obsidian.

He also invites missing-connector requests through Twitter, where his monitoring workflow can route them to the Connectors team.

The two forms of computer access have different scopes.

| Capability | Scope in the workshop | Example | |---|---|---| | Chrome extension | Work inside Chrome | Open and close Twitter DM tabs | | Computer Use | Operate desktop applications | Find iMovie sound effects and export a video |

In iMovie, Liu describes the agent teaching him how to export and placing sound effects at the requested positions. In Chrome, he sees it briefly open tabs to check messages while he handles email. These examples depend on the desktop environment demonstrated in the recording; the background behavior is part of what makes delegation useful to him.

04

把反复进行的调查变成技能

Connected context makes a vague request more useful. An investigation can start with an email, follow a loose thread into Slack or meeting notes, and then look up the people involved. In one meeting-preparation example, Liu’s automation discovers that he and the person he is about to meet attended Waterloo at the same time. That gives him a concrete point of connection when the call begins. As pinned histories and memory accumulate, he can ask what changed about a launch without specifying every source again. The experienced-employee analogy is about accumulated context: broad instructions become workable after the system has learned the procedures and relationships.

A small exercise exposes the same capabilities: ask Codex to find the conference sessions, organize them in Markdown, and put them in a spreadsheet. It may use web search or Chrome. To discover reusable instructions, invoke skill-installer and inspect the OpenAI Skills Catalog. Liu names GitHub workflows, Playwright, and Remotion as examples, then mentions Skillset.sh and Vercel’s skills tool. Vercel’s React Best Practices is a concrete example of bringing framework guidance into an agent’s work; his passing useMemo example is not a general rule against that API.

Inside a company, the most valuable skills may encode operational knowledge rather than programming technique: who receives an outage escalation, how to start a SEV, and which Statsig gates to inspect. To build one, use plugin-creator or skill-creator to interview you, or perform the task once and ask Codex to turn the documented experience into a skill. Liu explicitly permits his personal skills to edit their own files when they learn something new. Corrections then become instructions for the next run.

His developer-experience triage skill records the Slack channels that collect feedback, the engineers responsible for features, and the information required to investigate a regression. If someone reports a regression by DM, it knows to request a feedback ID. A spoken request about a launch, Twitter, or the current browser view can trigger the workflow; AppShots supplies the immediate application context.

05

既记录像素，也记录标识符

An ordinary screenshot of Slack leaves several discovery steps between seeing a conversation and replying to it. The model must read the image, identify the channel, resolve names to people, and obtain the identifiers required by the messaging tool. Liu describes AppShots as capturing the image together with the application’s accessibility tree. In his Slack example, the attached context supplies channel and user identifiers, allowing the agent to address the right destination directly.

Liu describes a one-call reply path when the AppShot already supplies the required Slack identifiers. His spoken identifiers illustrate the routing mechanism rather than establish a Slack API schema. Current AppShots documentation describes a narrower guarantee—an image of the frontmost window plus available accessibility text, with capture varying by application—so a complete tree and all identifiers should not be assumed. The useful principle is to supply structured application context when available, reducing the lookups needed before an action.

Forms provide another example. The captured fields tell the agent what needs filling; the application tells it which control path to use. In Liu’s setup, Chrome leads to the extension and Safari to Computer Use. He reports having gone two weeks without manually filling out a form. With the relevant skills in place, the request can become as terse as a manager forwarding an email with a few question marks: the recipient has enough context to investigate what needs doing.

06

让知识库居于中心，让代码放在别处

The personal monorepo template supplies Liu’s starting directory structure and memory-building skills. He suggests opening the repository, taking an AppShot, and asking Codex to set it up—or simply asking it to find Jason’s personal monorepo template on GitHub. The vault becomes the starting point for work, even when the implementation belongs in another repository.

Asked where individual projects live, Liu describes managing his many demo repositories from a single personal-monorepo project in the sidebar. An AGENTS.md instruction directs code outside the vault. A minimal version of that convention is:

```markdown # Repository placement

Keep project code outside this memory vault. Clone and create code repositories under /dev. The slide project lives at /dev/slides. ```

In his setup, Codex can work on files beyond the selected project directory. That arrangement sometimes interferes with the sidebar’s Git review, so he reviews the code in GitHub. The vault is the coordination entry point, not the container for every codebase.

The assistant plugin handles onboarding: it interviews the user, identifies useful plugins, and creates threads and automations. Liu also uses code- and writing-audit skills. His additional Write Like Me skill, which he says is not included in the workshop template, derives a style guide from his sent email and Slack history, then adapts the tone to the kind of message being written. Other personal tools include loop, a simple HTML artifact skill with his visual preferences, and ultragoal. Scripts for a new person or project bootstrap records, forming a personal CRM around contacts encountered through email, Slack, and iMessage.

07

让记忆可检查、让技能可纠正

Effective compaction does not eliminate the external vault. Liu still wants an Obsidian-style record he can inspect. Keeping it in Git lets him return after several days and see what the agent changed:

``bash git diff --stat git diff ``

A diff might reveal that a colleague replied and closed an outstanding loop. That fact can then inform another conversation. When someone asks a question on Slack, Codex can consult the vault, draft an answer, and ask permission before sending it. A separate automation can maintain the vault, although Liu says that maintenance has not been a major problem for him.

Evaluation depends on who will use the skill. Liu usually starts personal skills quickly and corrects mistakes as they occur. A shared triage skill deserves more scrutiny: does it know feature ownership, and does it route an issue correctly? Repeated personal use gives him confidence to share, but that is experiential validation. He also identifies a practical obstacle to reproducible evals: his skills depend on live connectors, and he cannot snapshot Slack into a fixed test environment.

08

利用桌面的上下文，然后放手让智能体工作

Liu occasionally uses the CLI for speed, but prefers the desktop because so much of his work starts with an AppShot. He can request a summary while continuing to watch a video, or delegate a document workflow. One personal example combines DocuSign, saving the signed file, finding a fax service, and faxing medical records. During agent runtime, he tries to talk with coworkers, learn what they are working on, and discover connections. Those conversations provide context the agent cannot collect on its own.

An audience question compares GPT-5.5 with GPT-5.3-Codex-Spark. Liu’s choices are shaped by unlimited token access and background workflows whose latency he rarely watches. He uses Spark for simple Computer Use tasks such as clicking through a form. His flight workflow starts with a check-in email, checks him in, downloads the boarding pass, and sends it to him on iMessage. Seeing JetBlue unexpectedly open in Chrome is a visible side effect of that background work. The enabling resource is the computer itself: it already has his authenticated sessions, credentials, and filesystem.

Remote access introduces a separate distinction: controlling a Codex thread is not the same as providing a host for GUI automation. Liu describes reaching local and remote machines through Remote Control, and a Computer Use setting called Locked Use. He says a plugged-in laptop can accept phone-triggered actions with its lid closed; current documentation supports opt-in macOS locked use but does not establish that plugging in a closed laptop is sufficient. An iPhone can connect to multiple machines, including a dedicated Mac mini, while Computer Use still needs an operating system with a GUI.

09

把有帮助的行为与强制的边界分开

Computer access makes permission choices consequential. Liu describes earlier versions editing documents too eagerly, while finding GPT-5.5 more reluctant to take destructive actions. Among asking for every permission, granting unrestricted permissions, and using auto review, he favors auto review. He also records restrictions in AGENTS.md when an agent edits something it should leave alone. He explicitly acknowledges that his personal sense of safety is not a complete answer to the risk question.

Organization-level controls can constrain actions independently of a prompt. Liu reports that OpenAI’s configuration blocks MCP email sending when any recipient is outside OpenAI, and blocks messages to external Slack channels. The following privacy question remains unresolved: he does not know the individual-versus-enterprise retention policies. Another respondent emphasizes that models remain fallible and jailbreakable. As the sandbox expands from a permitted command to an entire computer, its computer-level and organization-level boundaries become design problems in their own right.

10

在同一条线程中安排后续跟进

With context available, ongoing work needs a way to resume. Liu keeps a chief-of-staff thread, an Agents SDK thread that delegates implementation and documentation work, and other threads for the CLI, open-source programs, and Twitter. A heartbeat schedules a message back into an existing thread. That preserves the conversation in which the work was assigned, instead of creating a fresh thread for every recurring run. Asking it to keep an eye on something at a specified interval, or invoking the template’s loop skill, supplies the wake-up mechanism.

For a pull request, the recurring job is concrete:

1. Check for new review feedback and address it. 2. Rebase on the repository’s main development branch—called master in Liu’s example. 3. Keep the pull request mergeable. 4. Check CI and fix failures.

The point of his Monday-to-Thursday example is continuity: a busy author can return to a pull request whose feedback and integration work have continued rather than accumulated.

Support follows the same pattern across several applications. An AppShot plus the developer-experience skill identifies a browser issue, routes it to the browser-feedback channel, and contacts James, the responsible engineer. 把推理和唤醒花在要紧的地方

The closing cost question separates reasoning effort from repetitive automation output. Liu cautions against assuming xhigh always produces the best result. In his coupon-search anecdote, xhigh ran for about two minutes searching many sites. He recommends becoming comfortable with low or medium reasoning for routine work, while acknowledging that unlimited token access limits his firsthand experience of hitting user limits. His chief-of-staff thread, he recalls, defaults to medium. Building a game from scratch and checking routine updates do not demand the same deliberation.

For a loop that repeats itself, adjust the operating instructions:

- Unchanged state: Request a minimal no updates response when nothing has changed. - Cadence: Decide whether the work needs checks throughout the day or only a daily briefing. - Stopping criteria: Specify the event that ends the work rather than leaving the loop open indefinitely.

His refund example combines cadence and completion: begin with a long support queue, check periodically, increase the frequency as the turn approaches, and continue the interaction until the refund is obtained. Liu reports starting in a 75-minute Amazon support queue, checking every five minutes until five minutes remained, then every minute, and returning to a $400 credit-card refund.

Adaptive heartbeats are a possibility he has explored only lightly. In the workshop, heartbeat configuration is an editable text file, so he proposes increasing activity on weekdays and reducing it during quieter periods. A related experiment uses a never-stop goal that permits sleeping: he reports the agent noticing it was evening, observing no recent Slack activity, and choosing a longer sleep. The system need not work at a fixed intensity merely because it can keep running. xhigh means more thinking, not a guarantee of better results. That is the final distinction to carry into the setup: give routine work enough reasoning, a useful wake-up schedule, and a clear reason to stop or wait.
