01 | Create the Custom Connection
contoso-cosmos

- Return to the Azure AI Studio tab (Tab 4) https://ai.azure.com/build and ensure contoso-chat-sf-aiproj is the selected project
- Click Settings in the sidebar
- Scroll down to the Connected Resources section, select the New Connection option
- Click Custom keys in available options
- Under Custom Keys, click + Add key value pairs four times, and then complete the entries as shown below:
  - key: key, value: use "COSMOS_KEY" value from .env (it will end in ==)
  - key: endpoint, value: use "COSMOS_ENDPOINT" value from .env
  - key: containerId, value: customers
  - key: databaseId, value: contoso-outdoor
  - check "is secret" on the first key-value pair
- Set connection name: contoso-cosmos

用 Azure AI 构建、评测并部署一个基于 RAG 的零售副驾驶

跟随一个零售 RAG 后端，从商品检索和客户查询，到提示词组装、部署，再到一次揪出“编得像模像样的商品”的评测。

具备基础 Python、GitHub 和 API 知识会有帮助；复现云端工作流还需要一个 Azure 账号，以及配置好的模型、搜索和数据库资源。

01

一个零售聊天机器人需要什么信息？

How do you build a chat backend whose answers come from a retailer’s databases rather than just the model’s training? The workshop starts with that engineering problem: connect an OpenAI model to ordinary database records and a vector search system, then assemble the information into an answer. The production-oriented work is in that surrounding workflow—retrieving evidence, supplying context and checking the result.

The hands-on environment separates instructions, development and cloud resources. Participants need a laptop and a GitHub account. The Windows virtual machine holds the paginated workshop guide; its green text inserts URLs and credentials into the VM’s browser. A participant’s own browser also works, with manual copying from the guide. GitHub Codespaces supplies VS Code, Python dependencies and a terminal, avoiding differences between local installations.

02

一条帐篷推荐，然后是一个关于购买历史的问题

The application is an outdoor retailer’s storefront, with a small catalog of camping equipment, backpacks and hiking clothing. The workshop builds its backend; frontend code and data are also available. Product pages contain much more than names and prices: the Trailblaze hiking pants page includes features, reviews, FAQs, return information, cautions, technical specifications and care instructions. Sarah Lee is already logged in.

A basic capabilities question can be answered from the model’s role and context. A product recommendation needs more. When David Smith asks which tent goes with the Trail Walker shoes, the copilot recommends the TrailMaster X4 tent and refers to an upcoming trip to Andalusia. A subsequent purchase-history question produces an answer naming Sarah’s Cozy Night sleeping bag and Trailblazer hiking tent. The backend therefore needs two distinct sources: product documentation for recommendations and customer records for personalization. Customer context can include a name, loyalty status, location and previous orders.

03

两条检索路径在一个提示词中汇合

Azure AI Studio manages the project, model endpoints, connections and flows. Azure AI Services supplies the OpenAI models. Azure AI Search holds the searchable product information, while Cosmos DB holds customer records and purchase histories. Cosmos DB’s role here is the customer-record store; AI Search performs the product vector retrieval.

The request moves through the backend in a definite sequence:

1. Receive the question as a string, together with chat history. 2. Use Azure OpenAI to embed the question into the same vector space as the product documentation. 3. Search for nearby product vectors and retrieve the corresponding product information. 4. Look up customer information and purchase history in Cosmos DB alongside product retrieval. 5. Assemble instructions, retrieved products, customer context and the question into a prompt. 6. Generate an answer and return it to the website.

An embedding makes semantic similarity searchable: nearby points identify potentially relevant products. The generation step then uses the retrieved information as context. Prompt flow implements this retrieval–augmentation–generation sequence as connected components.

04

启动实验、完成认证并检查数据

The historical lab uses the Contoso Chat repository and its ms-build-lab-322 branch. That branch skips infrastructure deployment because attendees receive preprovisioned Azure resources; the recording directs at-home users to main for deployment instructions. The repository’s archived main branch now uses Prompty rather than the demonstrated Prompt flow implementation, so it is no longer an exact copy of this lab. In the recorded setup, GitHub single sign-on can require using the participant’s own browser rather than the VM browser.

Launch Codespaces from the selected branch, then sign in to the supplied Azure account in the portal and from the development terminal. The temporary workshop account and its resources disappear after the session. The terminal authentication uses az login and a device-login code; completing browser authentication connects subsequent CLI commands to the chosen Azure account. Desktop VS Code can also attach to the Codespace.

Several setup details matter when reproducing the sequence:

- Preserve the lab branch: When forking, uncheck “Copy the main branch only,” then select the lab branch before creating the Codespace. - Use the prepared environment: Its container supplies the command-line dependencies, so a shell is ready once startup completes. - Recover the existing session: Confusion between macOS browser tabs and VM browser tabs does not require creating another Codespace; reopen the one already created. - Finish terminal authentication: After device login, return to the terminal and confirm the subscription when prompted.

These are separate states: a browser login, an open editor and an authenticated CLI are not interchangeable.

The post-provisioning script populates Cosmos DB and AI Search. David inspects the resource group, opens Cosmos DB’s Data Explorer and finds customer records with purchase histories. He then opens Search Service → Search management → Indexes and finds no indexes. Permission errors appear during troubleshooting, and he recognizes that he has skipped configuration. A deployed search service is not evidence that its index has been populated. Inspect the data and index themselves before debugging the chatbot.

05

一个 flow 掌管什么

An audience question about ReAct agents exposes an important distinction: a directed acyclic graph does not loop back through its own nodes. A Python component can nevertheless contain loops or interactive logic. The graph describes dependencies between components; it does not restrict every computation inside a component to a single operation.

Meanwhile, the setup failure narrows to the missing .env creation step. Another question asks whether Enterprise ChatGPT Actions could call the flow through middleware rather than through the retail website. The intended deployment provides precisely that boundary: publish the flow as an endpoint, then let a client call it. Before data setup can succeed, step six must create .env with resource endpoints and keys, plus config.json for AI Studio access. Only then should the provisioning script be rerun.

The product indexing unit is deliberately simple: one Markdown file per product becomes one embedding. David initially agrees that the data is chunked, then corrects himself: this sample does not split each product document into chunks. He contrasts it with AI Studio’s own-data workflow, which performs chunking. That choice determines the retrieval granularity: a match brings in a product document rather than a smaller passage.

06

提示词流程、应用编排与试验场

The framework comparison reflects the presenters’ choices at recording time:

| Tool | Role in the discussion | Main emphasis | | --- | --- | --- | | Semantic Kernel | Application orchestration | Enterprise versioning and API lifecycle | | AutoGen | Experimental agent orchestration | Research and rapidly changing techniques | | Prompt flow | A connected LLM workflow | Flow development, evaluation and deployment |

These roles can compose. Semantic Kernel can call multiple deployed Prompt flow endpoints. Cedric Vidal also corrects an overly narrow endpoint-only description: a flow can be embedded as a Python library for integration tests, evaluation or a native application.

The graph is useful for explaining dependencies and inspecting data, but the underlying YAML defines node types, inputs, outputs and connections. The CLI can run that definition with supplied inputs. Cedric describes a Python configuration alternative with a more code-first experience, while expressing uncertainty about its availability at the time. The workshop itself stays with the YAML-backed graph and a single deployed endpoint. The presenters also note overlapping capabilities: Semantic Kernel can build agentic applications, and embedding Prompt flow is useful for reusable Python snippets and tests.

AI Studio’s advantage in this workflow is integration. Model catalog endpoints, Cosmos DB and AI Search connections, evaluation and endpoint management live together. A React application or another orchestrator can consume the resulting endpoint. The playground supplies a route from experimentation to code: configure a RAG application, export it to Prompt flow, then customize the generated flow. The lab project’s playground exposes GPT-4 and GPT-35 Turbo endpoints for experimentation and connection testing.

Copilot Studio sits at a different level in the presenters’ comparison: assembling a complete chatbot or integrating it into an application such as Teams. A custom AI Studio endpoint is an optional extension when the application needs more control. David directs evaluation questions to the AI Studio endpoint, without establishing Copilot Studio’s full evaluation capabilities. The simplest playground export makes the boundary visible: input → chat model node → output. Adding retrieval and customer context is additional application behavior around that model call.

07

连接、持久化与搜索质量

The retrieval component is replaceable. When an attendee proposes Chroma, David points to the product-retrieval node: its AI Search connection could be replaced by another vector database or an endpoint. The surrounding flow still needs the returned product information in the expected form. A separate startup question highlights the operational cost of the Azure approach. David emphasizes authentication, security, scaling and monitoring, while acknowledging the setup burden of resource groups and supporting resources. Miguel Martinez describes the startup program’s tiered credits, mentors and learning sessions as assistance with that burden.

As setup continues, the presenters return to two kinds of state. Resource configuration must precede the search-index loading script. Conversation state, meanwhile, travels through the flow as chat history; retaining it beyond the interaction requires database storage. Retrieving product information and carrying conversation history are separate responsibilities, even though both eventually influence the answer.

A connection-name mismatch causes another concrete failure. The lab already has an AOAI-named Azure OpenAI connection selected. A separate connection named default points to a different resource set; switching to it breaks the lab. Keep the working model connection, then create the Cosmos DB connection separately through Connected resources → New connection → Custom connection. Its key-value pairs come from .env. Standard connectors handle supported services, while custom connections carry configuration for other services.

An audience scenario asks about nearest-neighbor search over a million vectors: how do approximation, pruning and search parameters affect recall compared with brute force? David explains why indexed vector stores exist—to make similarity retrieval practical at scale—but does not provide a measured recall–latency curve or tuning recipe. His practical recommendation is broader: in the team’s application experience, combining keyword and vector retrieval has worked better than either alone. This workshop intentionally uses vector-only retrieval. Hybrid search requires both text and vector query components; it should not be assumed to happen automatically for every vector query. Product keyword metadata can also be updated.

David does not know the embedding-dimension ceiling when asked. For present-day configuration, use the documented service limit rather than treating that uncertainty as unlimited support: Azure AI Search limits, checked in August 2026, specify a maximum of 4,096 dimensions per vector field. That is a current configuration constraint, not a measurement from the workshop.

08

客户上下文不等于客户授权

The security questions move from signing in to controlling what a request can retrieve. An attendee wants Entra External ID and social logins to establish a user-specific scope across the application, AI Search and Cosmos DB. The presenters distinguish developer access to AI Studio from application access to the deployed endpoint, which can use tokens or managed identity. They do not establish an end-to-end implementation of the requested external-user delegation.

First, clarify what crosses the retrieval boundary. The language model receives document text, not just a vector. The vector identifies relevant Markdown documentation; the retrieved text replaces a variable in the prompt template. Any authorization mistake before that point can therefore expose actual document content to generation.

The next question makes the threat concrete: a broadly privileged flow might retrieve another user’s data, including after malicious prompting. The attendee asks whether a calling user’s delegated token can be propagated to downstream services. Cedric describes passing JWTs through a flow in general terms. Miguel explains the intended separation between identity and conversation: establish who the user is before generation, rather than allowing a message such as a changed name to select someone else’s records.

David then corrects the sample’s actual behavior. Sarah’s customer ID is an endpoint parameter, not an identity derived from a delegated token. The app sends that ID and a purchase-history question; a privileged flow queries Cosmos DB for the corresponding orders and returns generated text. The browser has no direct database access, but that alone does not make the lookup user-authorized. The attendee explicitly wants the flow to inherit the caller’s restricted access instead of retaining broad privilege. That implementation remains unresolved in the discussion; Cosmos DB identity and data-plane authorization require explicit configuration beyond supplying a customer ID.

09

从查询结果到渲染好的提示词

A question about dynamic routing leads into the prompt itself. The customer prompt contains Jinja loops that insert matching product documents and previous orders. Before the customer’s shoe question reaches OpenAI, it has been surrounded by instructions identifying the Contoso Outdoor role, asking for references for factual statements and supplying the relevant documentation. The model receives that assembled context plus the question, not the question alone.

Three different kinds of control are easy to confuse:

- Template control: Jinja loops and conditions determine which strings appear in the rendered prompt. - Python control: A Python node can branch, loop or perform other internal work. - Graph control: Node activation determines whether an entire component runs.

Cedric describes the demonstrated DAG as executing every node, with conditional work inside nodes. His blanket statement that conditional node execution is impossible should not be generalized: Prompt flow’s conditional-control documentation supports activation through activate.when and activate.is. That does not create graph-level cycles or change what this sample executes.

The binding between the lookup and the prompt is ordinary data passing. A database node returns customer information; the next node receives it as customer; Jinja iterates over customer.orders. This compact Python example makes that rendering step explicit, using Sarah and the purchase names shown earlier:

```python from jinja2 import Environment, StrictUndefined

customer = { "name": "Sarah Lee", "orders": [ "Cozy Night sleeping bag", "Trailblazer hiking tent", ], } question = "What have I already purchased from you?"

environment = Environment(undefined=StrictUndefined) template = environment.from_string( """Customer: {{ customer.name }} Previous purchases: {% for order in customer.orders %} - {{ order }} {% endfor %} Question: {{ question }} """ )

prompt = template.render(customer=customer, question=question) print(prompt) ```

The collection is available before rendering begins. Input/output bindings connect that returned value to the template; graph arrows visualize those dependencies. Selecting a node opens its editable definition, while the graph itself is especially useful as an inspection view.

10

在本地运行、打包 flow，并了解它的局限

The VS Code Run button launches Python against the YAML flow. During development, orchestration runs in Codespaces, which substitutes for a laptop; the databases and OpenAI endpoints remain in Azure. This separation gives a fast place to change prompts, test connections and replace model nodes without first deploying a hosted application. The next deployment step packages the same flow into a container-backed Azure endpoint. Packages can be added to the Docker environment for custom processing, and the presenters describe platform-managed deployment and scaling. For a new implementation, the current Prompt flow lifecycle notice matters: retirement is announced for April 20, 2027, and runtime images no longer receive package or security updates.

The sample always performs both retrieval paths. Even a question asking what else the customer purchased is embedded and sent to product search, while the customer lookup retrieves order history. The model must attend to the useful part of the combined context. That simplicity has a limit: asking what was purchased during the last month does not cause this flow to generate a new database query. It receives a predetermined slice of order history; Cedric tentatively recalls it as the last ten orders.

Natural-language-to-SQL is a different implementation: interpret a request, construct a query with the required filters and execute it. David warns that an intermediate model does not eliminate malicious influence over generated SQL. Cedric points to RAG on PostgreSQL as related work. Its documented implementation combines hybrid retrieval with optional model-generated query filters; it should not be treated as verification of unrestricted SQL generation.

11
