打造一家 10 人的独角兽

Gumloop 的小团队实验把明确的工作流自动化，与审慎的招聘、受保护的工程时间，以及一种为持续快速交付而打造的文化结合在一起。

01

一轮没有大团队的 A 轮融资

拿到 A 轮融资之后，怎样让公司继续扩张，又不把它变成一个庞大的组织？Gumloop 参加了 Y Combinator 2024 年冬季批次。拿到 A 轮时，公司只有两位创始人，没有一名全职员工，不过实习生和外包人员也出了力。演讲时，Max Brodeur-Urbas 说团队有九个人。他公开立下的目标是做一家十个人、估值十亿美元的公司。这是要去的方向，不是已经做到的估值。

这条口气很大的推文也有实际的招聘作用：它吸引来了想在小团队干活的人。用好 AI 编程工具只是起点。组织上真正的难题，是怎样把个人的速度变成一个能执行、还能持续扩张的团队。这要求他们在招聘、日常工作和文化上做出选择。

02

用明确的工作流取代开放式的请求

Gumloop 是从一连串失败的尝试里长出来的。Brodeur-Urbas 做过游戏内容审核软件，做过估算儿童年龄的模型，好在 VR 里把成人和儿童分开，还做过 bot 检测软件。在这些项目之外，他顺手给 Auto-GPT 做了一个用户界面。Auto-GPT 的 Discord 里有很多人想用 AI，却不会克隆仓库，也不会在本地配置。一个简单的界面就扫清了这道眼前的障碍。他给它起名 AgentHub，设想的是一个智能体版的 GitHub。

这个界面押在一个更站不住的假设上：智能体马上就能派上用场。观察用户之后，他们看到了另一个机会。用户提的需求，往往是在描述一套复杂但说得清楚的工作流。懂 Python、API 调用和 LLM 查询的人，可以直接把这些步骤实现出来，不必指望智能体自己摸索着完成。于是两位创始人改了配置方式：不再让用户提出一个完整的结果，而是让用户定义一串工作流节点。用户给出流程，自动化执行每一步。

公司进了 YC，招了两名暑期实习生，先拿了种子轮，接着又拿了 A 轮。据 Brodeur-Urbas 回忆，两轮相隔大约四个月。融资是为了招到顶尖的人，而不是把人数堆上去。两位创始人在 Amazon 和 Microsoft 待过，想要小团队那种快节奏和乐趣，会也开得少。Gumloop 后来成了一款大公司都在用的工作流自动化产品。

之后形成的做法涵盖招聘、内部运营和文化三方面。Brodeur-Urbas 把它们当作一位创始人仍在积累的经验来讲：成功里有多少来自这些做法、多少来自一次次好运，他自己也还分不清。下面讲的是一家公司的选择，不是一套验证过因果、照做就灵的配方。

03

保持高招聘标准，再通过产品来招人

Gumloop 招人靠三件事：挑剔、产品带动招聘，以及花时间一起干活。第一件是有意让自己难受。有一次，Brodeur-Urbas 把一位他觉得还不错的候选人推荐给一位投资了 Gumloop 的 Instacart 联合创始人，对方的回答让他更坚定了这一点：别降低标准。招不招一个人，得明显到整个团队都对这个人特别兴奋才行。

Brodeur-Urbas 说，他们面试了几百人，还安排了很多次试工。下这么大功夫，是因为每个招聘决定的分量都很重：团队这么小，每招一个人，就占了公司能力的一大块。一直这么挑剔，也可能让投资人摸不着头脑，毕竟他们出钱就是为了扩张。创始人筛人时必须下足功夫，也得有足够的底气，忍得住人数涨得慢。

产品带动招聘提供的是另一种证据。有两位客户辞掉原来的工作加入了 Gumloop。他们带来了热情，也带来了在企业里实际用这款产品的经验。

- 企业客户关系：最早发现 Gumloop、把它引进 Instacart 的那位客户，加入后负责企业账户和大客户。 - 教育与社区：一位前 Webflow 员工原本在卖 Zapier 课程、办自动化工作坊，发现 Gumloop 后很是着迷，于是加入公司，负责教育和社区。

这些候选人本来就清楚产品能做什么、适合用在哪里。

招聘上的优势正来自他们之前的使用经历：创始人不用硬造热情，也不用从头介绍公司。但前提是，公司想招的人能接触到这款产品。好产品能打开这条渠道，可合适的人会不会碰上它，仍然要看运气。

04

通过一起工作来评估是否合适

第三种招聘做法，是把考察放进真正的合作里。Gumloop 会租下 Airbnb，办为期四天左右的集中工作营。Brodeur-Urbas 说，几天就能做出三周的进度。这是他对集中工作效果的随口估计，不是测出来的生产力基准。演讲里展示的那次工作营，有两位参与者就是正在试工的候选人。

候选人会花几天时间，像已经入职一样干活。这样团队在做最终决定之前，就能实实在在地体会和对方合作是什么感觉。Brodeur-Urbas 认为，专门留出这段时间待在一起，是判断一个人合不合适的关键。这样一遍遍做很花时间，但创始人对招来的人也更有把握。

05

保护工程时间，把实现委派出去

招到能干的人，还得给他们留出做东西的空间才有用。Gumloop 有意把会议压到几乎为零。创始人的日历上排满了客户沟通和上门拜访，工程师的日历则最好几乎是空的。演讲里对比了两份日历，分工一目了然：面向客户的工作占满了创始人的时间，却没有摊到其他人的日程上。

小团队让这件事成为可能。几个人一起做的项目，往往要先同步、先达成一致，才能动手实现。协调的负担轻了，大块不被打断的开发时间就保住了。Brodeur-Urbas 也改了自己的角色：他不再参与每个功能的方方面面，而是根据和客户的交流写出粗略的功能描述，让工程师自己决定怎么实现。招聘时给出的信任，变成了执行时的自主权。

06

把围绕客户决策的准备工作自动化

Gumloop 用自家产品来自动化公司内部的业务工作。某项内部任务没法自动化时，团队就去开发能让它自动化的功能。这样一来，运营需求和产品开发就连到了一起：公司作为自家软件的客户，亲身撞上了自动化的缺口。

有两个工作流帮创始人提前做好见客户的准备：

| 触发条件 | 汇总的信息 | 输出 | | --- | --- | --- | | 即将开始的会议 | 关于客户的公开资料，以及对方实际使用产品的情况 | 一份会前准备报告，说明对方是不是重度用户、用了哪些功能 | | 值得关注的新注册 | 谁注册了，在产品里做了什么 | 一条通知，外加创始人收件箱里的一封邮件草稿 |

注册工作流只负责把联络准备好，并不会把创始人从对话里拿掉。他可以用这份草稿主动联系对方、约个电话，问清楚对方为什么注册了免费账户。

用 Python 来写，这个准备步骤就是对一条已经汇总好的注册记录做一次小小的转换。输出仍然只是草稿，留给创始人审阅：

```python from dataclasses import dataclass

@dataclass(frozen=True) class Signup: name: str email: str features_used: tuple[str, ...]

def prepare_outreach(signup: Signup) -> dict[str, str]: activity = ", ".join(signup.features_used) or "No feature usage yet" return { "notification": f"{signup.name}: {activity}", "to": signup.email, "subject": "What brought you to Gumloop?", "body": ( f"Hi {signup.name},\n\n" "I'd love to hear what prompted you to create an account " "and what you're hoping to automate. " "Would you be open to a short call?" ), "status": "draft", }

signup = Signup("Alex", "alex@example.com", ("workflow builder",)) draft = prepare_outreach(signup) ```

这个例子只截取了“准备”这一步：用户的活动被整理成上下文和拟好的联络内容，全程没有任何发送操作。

Brodeur-Urbas 认为，这种主动联络带来了相当可观的增长。另一个工作流把客服对话变成产品反馈。据 Brodeur-Urbas 说，平台上的 AI 聊天机器人每天收到大约 5 万条消息。一个 Gumloop 工作流会读这些对话，找出用户觉得困惑的地方，团队再拿这些发现来指导产品决策。

他估计，这类工作要是不自动化，可能得专门占一个岗位，或者每天吃掉某个人三到四个小时。这只是他估的省下来的活，不是实际测量过的结果。Gumloop 还有一个独特优势：它本身就是做自动化的公司，自家运营一旦暴露出缺什么能力，就能直接拿来改进产品。

07

让速度可持续，才能留住团队

大家要是过得痛苦，或者干脆走人，小团队就很难一直保持出色。可 Gumloop 偏偏有意营造紧迫感。客户提出要某个功能时，Brodeur-Urbas 经常会问：“要是我们今天就把它做出来呢？”这句话在团队里传开了。工程师有时会定一个 45 分钟的计时器，试着用 Cursor 把一个功能做完上线。这是一种挑战，不是交付承诺。

同样的习惯也可能把人累垮。周五晚上八点还要求马上交付，风险就格外明显。Brodeur-Urbas 一边强调速度，一边刻意让大家一起干活时过得开心。工作营总选在风景好的地方，吃得好，还安排攀岩、骑车之类的活动。在他看来，这些共同经历，加上之后还有活动可以期待，能抵消一部分高强度。但这并不说明倦怠的风险就没了。后勤安排也对小公司有利：一套 Airbnb 住十个人很宽敞，住五十个人就不行了。

08

把文化承诺放在候选人能读到的地方

Gumloop 把内部关于怎样建设公司的理念，写进了一本公开的公司手册。演讲中展示的版本当时已经过时一两个月，链接里的手册之后也一直在更新。手册起作用的方式是问责：把原则白纸黑字写下来，团队就有了必须兑现的承诺。

这本手册也帮了招聘。候选人在见到创始人之前，就能先了解公司怎么干活。Brodeur-Urbas 认为，不少初次通话就是手册促成的，它也说服了一些人加入。文化公开出来，面试还没开始，来这里工作意味着什么就已经很具体了。

演讲最后，他直接用上了这套招聘方法。Brodeur-Urbas 跳过了原本要放的视频，邀请大家申请或推荐 Gumloop 的创始增长负责人（founding head of growth）一职，帮公司继续扩张。这份当时发出的邀请，包含了他所描述工作承诺的两面：公司希望大家干得开心，而工作本身强度会很高。
