用 Heroku 托管推理与智能体构建智能体应用

从一个托管的 Jupyter notebook 出发，逐步构建流式推理、可执行的工具、只读的数据库分析，以及其他客户端可以发现并调用的 MCP 服务器。

对 Python、HTTP 请求和环境变量有基本了解会有帮助；按部署步骤操作还需要一个能访问相关服务的 Heroku 账号。

01

从一个只需浏览器的 notebook 开始

不在本地装任何东西，搭一个智能体应用能走多远？这场工作坊先在 Heroku 上部署 Jupyter，把一个 notebook 载进去，再挂上托管推理。接下来，同一个 notebook 依次充当模型响应、工具执行和 MCP 服务器的客户端。AI 服务由 Heroku Managed Inference and Agents 提供，工作环境就是浏览器。

Julián Duque 自我介绍是 Heroku 的首席开发者布道师，同台的还有 Heroku AI 产品经理 Anush DSouza。参与者可以在 AI Engineer Slack 工作区的 Workshop Heroku AI 频道拿到幻灯片和链接。工作坊网站上有个二维码，扫码就能看到课程内容，还有一个表单，填入 Heroku 账号绑定的邮箱即可。在活动现场，这个表单会发放临时权限，不用填信用卡就能部署应用、使用各项服务。动手环节都在部署好的 notebook 里完成。

02

让智能体循环成为一种应用资源

Heroku 起家时面对的是 Ruby on Rails 应用：写起来容易，部署、运维和扩容却很难。git push heroku main 把大部分运维工作压缩成开发者熟悉的一个动作。DSouza 用同样的思路看 AI：拿到模型响应只是开始。要把应用真正跑起来，还得选模型、扩展执行能力、控制工具权限，并弄清系统是否按预期工作。

他们提出的集成单元，是挂在应用上的一个托管智能体循环。 精选模型处在一个控制循环里，能执行代码、访问数据；Model Context Protocol 负责扩展。选模型、做评测、看 trace 依然是运维要操心的事，但平台想提供好用的默认配置，而不是让开发者自己拼装每个组件。DSouza 介绍说，heroku ai models create 是 CLI 入口，用来把 AI 作为资源挂到应用上。

平台组合了三类基础组件：

| 基础组件 | 在应用中的作用 | | --- | --- | | 托管推理 | 在应用代码里调用精选模型 | | MCP 服务器 | 用远程或 stdio 工具扩展智能体 | | 带 pgvector 的 Postgres | 存储 embedding，用于向量检索 |

Heroku 的 dyno 为工具执行提供算力。第一方工具可以在 dyno 上运行，再把结果流式传回智能体；符合条件的工具执行在空闲时会缩容到零。开发者也能把自己的 MCP 工具接进来。工作坊举办时，第一方网页搜索还在计划中，记忆功能则被描述为将来可能推出的能力。

部署带有 notebook 持久化的 Jupyter

想之后接着练，工作坊网站上有分步说明。接受活动邀请后，参与者会加入 Heroku 控制台里的 AI Engineer World’s Fair 团队；按现场介绍，权限有效期到 7 号，覆盖整个周末，还可能延长。团队里已经有一个 Jupyter 工作坊应用、一个 Brave Search MCP 和 ai-engineer-data，后者的 PostgreSQL 数据库会用在后面的分析示例里。

1. 打开仓库，点击 Deploy to Heroku 按钮。 2. 填一个唯一的应用名。演示时最初的名字已被占用，Duque 就加了个 workshop 后缀。 3. 应用所有者选 AI Engineer World’s Fair，费用由活动承担。 4. 在部署表单的环境变量里设置 notebook 密码，然后部署。Duque 演示时用的是 lab；公网能访问的 notebook 必须用强密码。

04

接入推理并加载执行上下文

下一个资源是 Managed Inference and Agents。在 Duque 看来，它的吸引力在于推理留在 Heroku 的基础设施内，不用直接调用外部模型厂商的 API。但这不等于保证推理就跑在应用自己的网络里：后来的文档写明，模型托管在 Amazon Bedrock 上，边界是安全的 AWS 账户。

在控制台打开应用的管理页面，选 Resources，添加 Heroku Managed Inference and Agents。录像里展示的模型目录包括：文本模型 Claude 3.5、Claude 3.7 和 Claude 4，embedding 模型 Cohere Embed，图像生成模型 Stable Image Ultra。Duque 选了 Claude 4。按当时的开通流程，会拿到 API URL、API key 和模型 ID，可以通过 HTTP 或兼容 OpenAI 的 SDK 调用。后来标准套餐的文档改成只列出连接 URL 和 key，模型在请求里指定。

Jupyter 就绪后，用 File → Open from URL 导入工作坊的 notebook。在 Heroku 里，点 Settings → Reveal config vars 能看到工作坊用到的三项连接配置：INFERENCE_URL、INFERENCE_KEY 和 INFERENCE_MODEL_ID。notebook 依次讲环境配置、基础推理与流式推理、原生智能体工具，最后是 MCP 的部署和客户端访问。工具执行用的是 one-off dyno：启动、执行操作、关闭。Duque 说，这样只为工具实际用到的算力付费，不必让一个工具应用一直跑着。

05

检查一次补全，再消费它的增量

基础的 chat completions 接口接收一条或一组消息，返回模型响应。这个端点也能请求自定义工具调用，但执行由调用方负责：应用代码要解析函数调用、执行它，再把结果传回去。ADK、LangChain 这类框架可以代管这个循环。notebook 的第一个示例不用工具，直接发一个 HTTP 推理请求。

请求体里有开通时拿到的 Claude 4 模型 ID，还有一条用户消息，要求用一句话解释托管推理。temperature、最大 token 数、top_p 等参数可以调节生成效果，前提是端点文档写明支持。响应是一个 JSON 格式的 chat completion 对象：choices 里有一条 assistant 消息，解释说托管推理负责模型的部署、扩容和维护，供预测使用。

流式输出改变的是响应到达的方式。客户端不再等一个完整的 JSON 答案，而是收到一串服务器发送事件（SSE），每个事件装着一段 completion 片段。Duque 先把原始事件打印出来，让大家看清结构。每个片段带一个消息增量（delta），最开始的 delta 可能没有文字。下一个示例提取这些内容片段，边收边打印，生成结束后再把拼好的完整回答渲染成 Markdown。

completion 片段解码后，notebook 里的拼接步骤可以写成一个小 Python 函数：

```python from IPython.display import Markdown, display

def render_completion(chunks): parts = [] for chunk in chunks: for choice in chunk.get("choices", []): content = choice.get("delta", {}).get("content") if content: print(content, end="", flush=True) parts.append(content)

print() answer = "".join(parts) display(Markdown(answer)) return answer ```

边生成边打印，用户在等待时就能看到进展。最后用 Markdown 渲染一遍，把完整回答排好版，包括模型返回的代码块。

06

把工具执行移进托管循环

agents 端点在推理外面加了一层托管执行。可用的工具覆盖几类不同的操作：

| 工具 | 操作 | | --- | --- | | Dyno Run Command | 运行 Unix 命令或应用里已有的脚本 | | Postgres Get Schema | 获取数据库结构 | | Postgres Run Query | 执行 SQL 并返回数据 | | HTML to Markdown / PDF to Markdown | 从给定 URL 提取文本 | | Code Execution | 生成并运行 Python、Node、Ruby 或 Go 代码 |

Dyno Run Command 适合运行已随应用部署、可信的代码。两个数据库工具天然有先后：先查清真实的 schema，再生成查询。文档转换给模型提供能处理的文本，代码执行则把计算结果交回推理。

生成代码类的工具还接受一个 packages 数组，可以在执行前装好 Pandas、NumPy 等依赖。Duque 把这些原生工具称为由 Heroku 维护的 MCP；自定义 MCP 也通过同一个端点接入。在演示的 API 里，智能体响应只支持流式，因为工具执行可能要花些时间。需要哪些应用和数据库权限，取决于调用的是哪个工具。

notebook 把请求发到 agents 端点，从流里提取工具调用信息。命令在 ai-engineer-workshop 上执行；notebook 等命令跑完，拿到日期和时间，再显示基于这个结果的推理回答。把 date 换成已部署的脚本，同一套机制就能用来提取数据或访问外部服务。工具先拿到实时证据，模型再据此组织回答。

08

保留计算，更换运行时

有了代码执行，模型不只能请求执行程序，还能自己写程序。Duque 启用 CodeExec Node，问第 13 个斐波那契数是多少。notebook 先用语法高亮显示生成的 JavaScript，再拿到在 Heroku 上执行的结果。Node 演示返回的第 13 个斐波那契数是 233。

按 F₀ = 0、F₁ = 1 的约定，这个计算用一小段 JavaScript 就能写完：

```javascript function fibonacci(n) { let a = 0; let b = 1; for (let i = 0; i < n; i++) { [a, b] = [b, a + b]; } return a; }

console.log(fibonacci(13)); ```

接着，Duque 把工具从 Node 换成 Go。模型生成 Go 代码，Heroku 在 dyno 上编译运行，响应给出同样的结果并附上解释。运行时还可以选 Python 和 Ruby；Duque 鼓励参与者不只换语言，也换换要算的东西。
