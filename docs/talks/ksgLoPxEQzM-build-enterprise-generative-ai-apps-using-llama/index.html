在 SambaNova AI 平台上以每秒 1000 token 的速度用 Llama-3 构建企业生成式 AI 应用

从一次 SambaStudio 推理调用开始，逐步构建一条检索流水线，跟随工作坊中关于专家路由、内存层级、提示词格式和 PDF 搜索的示例。

要完成练习，你需要熟悉 Python、虚拟环境和 Jupyter notebook，并能访问 SambaStudio 的 LLM 和嵌入端点。

01

快速推理让什么成为可能？

如果 Llama 3 每秒能生成 1,000 多个 token，企业应用能拿它做什么？这场工作坊就从这个问题出发：先了解提供推理的平台，再用 Python 接入，搭一个文档问答应用。解决方案工程总监 Rachelle Mattern 介绍平台。首席 AI 工程师 Petro Milan 主持工作坊，高级首席 AI 解决方案工程师 Varun Krishna 协助动手环节。

整场安排刻意偏重实操：先熟悉平台，再搭项目、现场开发，过程中随时答疑。想跟着做练习，需要一台能上网的笔记本电脑和一个 Python 环境，并且能用 pip 装包。工作坊期间，文件、端点信息和 API 密钥都通过 Discord 发放。

02

整合从硬件到模型的整条路径

SambaNova 把企业 AI 当作软硬件一体的问题来做。公司 2017 年从斯坦福起步。演讲中提到的几位创始人 Kunle、Chris 和 Rodrigo 带来了芯片研发和创业经验，也与 Snorkel、Together AI 有渊源。Mattern 介绍，公司已做到第四代芯片，技术栈覆盖芯片、系统和软件三层，支持预训练、微调和推理。她还提到公司融资超过 10 亿美元，投资方包括 BlackRock、Google Ventures、Intel 和 GIC。

企业和政府客户（包括主权 AI 部署）要的是：少在这几层之间做集成决策。Mattern 介绍，这个平台设计上可支持超过一万亿参数。SambaNova 不打算在生态里的每个环节都去竞争，而是把原本要逐一协调的选择整合起来：哪款芯片配哪套计算系统，哪个操作系统支持它，哪些模型能在这套组合上跑。应用团队拿到的是一套协调好的技术栈，不用自己一项项拼依赖。

Samba-1 Turbo 用一个公开演示，把这套方案在推理端的优势摆到台面上。Mattern 引用 Artificial Analysis 的对比数据，称 Llama 3 吞吐量约每秒 1,000 个 token，在展示的结果里领先其他服务商。这些都是当时的对比。演讲没给出提示词长度、并发数等工作负载条件，无法复现这一排名。后面的现场应用会更具体地展示，这种速度用起来是什么感觉。

03

把广泛的能力与企业专家模型结合起来

模型管理的难题，要从企业采用生成式 AI 的两种方式说起。OpenAI 的通用大模型，以及 Gemini、Claude 这类模型家族，知识面广，集成也简单。但企业还有自己的专有信息，往往沉淀在数据湖里，与公共互联网隔开。要让模型用好这些信息，就得考虑隐私、所有权和差异化。Mattern 还提到成本：按 token 计费，应用越多、调用越多，花费就越高。

另一条路是用 Llama 3 8B 这样的小模型，针对企业的特定任务做预训练或微调。这样模型能更贴合专有数据，企业对模型也有更多掌控。代价是运维负担转到了管理一大批专用模型上。

| 方案 | 优势 | 企业负担 | | --- | --- | --- | | 通用大模型 | 任务覆盖广；集成简单 | 难贴合专有数据；隐私和使用成本 | | 特定任务模型 | 可定制，自主可控 | 编排、维护，反复微调 |

法务模型、HR 模型、编程模型各有用处，但凑在一起，并不会自动变成一个好管理的服务。

Samba-1 用专家组合（composition of experts，CoE）来组织这些分散的模型。这里的“专家”指服务某一类任务的模型。要让这批模型真正用得起来，靠的是四项控制：

- 单一安全端点： 法务、HR、编程模型都放在同一个应用接口后面。 - 提示词路由： 检查收到的提示词，选出最合适的专家。 - 独立的微调节奏： 每个模型按自己的周期重训和替换。比如财务模型在政策变动时每年更新一次，编程模型随代码演进每季度更新一次。 - 模型级 RBAC： 只给某个应用、个人或小组开放它该用的模型。

端点简化了集成；路由、更新节奏和访问控制则让背后的各个模型保持各自的分工。

04

选择、评估和调用专家

企业可以选灵活的 CoE，自己挑模型；也可以从预先组好的 Samba-1 集合起步。Mattern 介绍，预组目录有 92 个专家，覆盖多种语言、领域和企业任务。她说平台支持七种基础模型架构，点名了 Llama 2、Llama 3、Mistral、Falcon 和 BLOOM，还提到 LLaVA、CLIP、DePlot 带来的多模态能力。这些例子说明的是集合覆盖面广，并不是说所有模型用同一种架构。

Mattern 说，92 个专家里有 12 个是 SambaNova 自研或联合开发的，包括泰语、日语、匈牙利语模型，一个 text-to-SQL 模型，以及面向多语言场景、SambaNova 参与开发的 BLOOMChat。她称 BLOOMChat 当时是第二大的开源模型。预组目录只是起点，企业可以按自己的需要添加专家。

评测看的是企业任务，不是目录有多大。SambaNova 的基准涵盖信息抽取、text-to-SQL、编程和函数调用。Mattern 称，在展示的企业任务对比中，结果达到或超过了 GPT-3.5 Turbo 和 GPT-4。演讲没有说明这些对比用了哪些数据集、怎么打分、具体是哪个模型版本。

应用调用这个集合，也需要不止一种方式：

| 调用方式 | 应用行为 | | --- | --- | | 路由 | 提交提示词，路由器自动选专家 | | 直接指定 | 已知任务时直接调用对应模型 | | 模型串联 | 在智能体工作流里把多次模型调用串起来 |

应用还不知道该用哪个专家时，交给路由去选；已经知道时，直接调用和串联能保留明确的控制权。

05

让众多模型靠近算力

支撑这套集合的硬件是 SN40L 可重构数据流单元（reconfigurable dataflow unit，RDU）。它的内存分三层：片上 SRAM、高带宽内存，以及容量更大的 DDR。思路是让大量模型常驻待命，执行时再把需要的模型调到更快的层级。各层之间连接紧密，这种搬移本身就成了系统执行策略的一部分。

Mattern 给出的数字是 4 GB SRAM、512 GB 高带宽内存、最多 6 TB DDR。这些口头给出的总量不能当成单芯片规格。SN40L 架构论文写的是每个插槽 520 MiB SRAM、64 GiB HBM、最多 1.5 TiB DDR，并描述了一个八插槽节点。演讲里的 6 TB DDR 对应哪种配置，这里无法确定。

部署上的对比，关键在于一大批模型放在哪里。Mattern 举例说，在 GPU 上托管 500 个模型，模型会分散在多套系统里，应用得找到装着所需模型的那一套。SambaNova 则用 DDR 层把一大批模型留在同一套底层系统里，再把正在用的模型往上层搬。她称容量最高可达五万亿参数，但没说明这个总数按什么精度、什么配置算。真正有用的机制，是把存放专家的容量和执行时的高速内存分开。

06

一份健身计划，然后是边输入边响应

现场演示从 SambaNova 官网打开 Samba-1 Turbo。模型选择器里有 Llama 3 8B、Llama 3 70B、一个 CoE 选项、Mistral，以及 SambaLingo 等 SambaNova 自己训练的模型。Milan 选了 Llama 3 8B，让它为中等健身水平的人制定一份每周练三天的训练计划。他把请求又发了一遍，然后打开性能数据面板。

这份训练计划的回答，Milan 报告的数据是：约每秒 1,000 个 token，首 token 延迟 0.09 秒，总推理时间 0.65 秒。三个指标对应体验的不同环节：生成吞吐量、开始输出前的等待，以及整段回答的耗时。随后他把同一提示词发给 ChatGPT，直观比一比速度。不过这次演示既没对齐模型，也没有受控的基准配置。

下一个模式改变的是交互方式本身。打开实时生成后，用户还在写提示词，回答就已经出来，并随提示词变化。以起草邮件为例：改一下要求，马上就能看到改后的草稿。同样的即时反馈也能用在提示词工程上，不用每次写完再停下来提交。这个公开演示用笔记本电脑或手机都能访问。

一位听众问，能不能调 top-p 这类生成参数。演讲者先说可以，查看界面后又改口：这个 UI 里这些参数似乎是固定的。要配置模型，得等到 API 练习环节。

07

准备基础推理 notebook

动手环节先加载环境变量、初始化 LLM，再用 Python 发一次推理调用。第二个练习用 LangChain、文档加载器、E5-large-v2 嵌入、ChromaDB 和 Llama 3 端点，搭一个 RAG 问答应用。两个练习都在 SambaNova AI Starter Kit 里。录像用的是 2024 年的 SambaStudio 流程和 Python 3.10，仓库现在的安装说明已经变了。

第一个练习进入 workshops/ai_engineer_2024/basic_examples 目录。设置步骤如下：

1. 克隆 starter kit 仓库，在根目录创建 .env。 2. 填入工作坊提供的 SambaStudio 端点凭据。 3. 进入 basic_examples，创建 Conda 或 Python 虚拟环境。 4. 安装练习所需依赖，并把这个环境注册为 notebook 内核。 5. 在 Jupyter 或 VS Code 中打开 SambaStudio 示例 notebook，选中该内核。

工作坊通过 Discord 提供两个专用端点，学员用其中任意一组凭据都可以。演示中的 Conda 环境名为 basic_x，推荐 Python 3.10。

激活环境后，用 pip install -r requirements.txt 安装基础练习的依赖。notebook 可以在浏览器里通过 Jupyter 运行，也可以直接在 VS Code 里跑。演示用的是 VS Code，选中的 Python 内核和每个单元格的执行耗时都显示在示例旁边。

08

配置推理并标记助手话轮

notebook 先导入库、加载 .env，再用端点凭据和模型配置初始化 LangChain 的 SambaStudio 封装。do_sample=False 关闭采样，演讲者称之为确定性生成；设为 True 则启用概率采样。温度和最大生成 token 数也可以配置。这是一个共享的 CoE 端点，所以配置里要指定 Meta Llama 3 8B-Instruct 作为专家。

第一次推理调用用 llm.invoke 提问 What is the capital of France?。模型给出了答案，但还接着输出了用户没要的内容。下一步按 Meta 的 Llama 3 仓库里的文档，加上指令消息格式：标出文本开头，标明用户轮次，结束这一轮，再开启助手轮次。在这种直接拼原始提示词的流程里，这些边界告诉模型：用户的请求到哪里结束，它的回答从哪里开始。

接着可以把同一个问题做成可复用的 LangChain Expression Language（LCEL）链：提示词模板填入国家名，配置好的 LLM 生成回答，输出解析器返回文本。基于已初始化的 llm，组合如下：

```python from langchain_core.output_parsers import StrOutputParser from langchain_core.prompts import PromptTemplate

def make_capital_chain(llm): prompt = PromptTemplate.from_template( "<|begin_of_text|>" "<|start_header_id|>user<|end_header_id|>\n\n" "What is the capital of {country}?<|eot_id|>" "<|start_header_id|>assistant<|end_header_id|>\n\n" ) return prompt | llm | StrOutputParser()

def ask_capital(llm, country: str) -> str: chain = make_capital_chain(llm) return chain.invoke({"country": country}) ```

调用 ask_capital(llm, "France")，问题本身不变，但国家名成了输入参数，不再硬编码在提示词里。

09

在生成之前加入文档检索

第二个练习在 workshops/ai_engineer_2024/ekr_rag 下，有 notebook 和 Streamlit 两个版本。检索增强生成把训练数据之外的信息喂给 LLM。专有文档，或者想用上又不愿为此重训模型的最新信息，都适合这么做；在某些场景下，它还能减少幻觉。

这条流水线把文档准备和回答问题拆成两部分：

1. 加载并解析文档。 按 PDF、文本或 PowerPoint 选合适的加载器，提取下游工具能处理的文本。 2. 切分文本。 切成较小的块，块大小和重叠量都可配置。 3. 嵌入文本块。 用 E5-large-v2 把每个块映射成数值向量。 4. 存储索引。 把向量连同文本和元数据存进 ChromaDB；演讲也提到可以用 Faiss。 5. 按查询检索。 把问题嵌入成向量，用相似度度量找出相近的文本块向量。 6. （可选）重排序。 按相关性给检索到的块重新排序，剔除无用内容。 7. 生成答案。 把问题和选出的上下文交给 LLM。

向量检索负责找出相关的原始材料，最后一次模型调用再把这些材料变成答案。

执行过程有一条清晰的分界。加载、切分和存储交给第三方工具。嵌入模型可以在笔记本电脑的 CPU 上跑，也可以调用 SambaNova 硬件上的端点；LLM 则跑在 SambaNova 硬件上。录像里用的是远程嵌入。演讲者提议做一次 CPU 对比，但完整演示里并没有出现。

10

准备 PDF 处理环境

继续用之前克隆的仓库，但设置 RAG 练习前，先退出第一个练习的环境。根目录的 .env 现在需要两组连接信息：SambaStudio LLM 端点和 API 密钥，以及嵌入端点和 API 密钥。安装要在 ekr_rag 目录下执行。

处理 PDF 除了 Python 包，还需要系统依赖。在 macOS 上，工作坊在虚拟环境之外装了用于 OCR 的 Tesseract 和 Poppler，然后使用 Python 3.10 环境：

``bash brew install tesseract brew install poppler python3.10 -m venv .venv source .venv/bin/activate ``

这些环境命令要在练习目录下运行。如果 shell 找不到 Python 3.10，先安装它并更新 shell 的路径，视情况重新加载 .bashrc 或 .zshrc。激活环境后，运行练习的安装脚本，安装 ipykernel，再注册内核供 notebook 使用。

有些学员的笔记本电脑遇到了 NLTK 或 SSL 证书问题，演讲者给了一个额外的修复脚本。依赖装好后，就可以用 Jupyter 或 VS Code 打开 notebook。练习里也有 Streamlit 版本，但录像接下来用的是 notebook。

11

为 SN40L 论文建索引并提出一个问题

ekr_rag/notebooks 下的 RAG notebook 负责调度各个辅助模块，包括 document_retrieval.py 和向量数据库工具。开头几个单元格把 kit 目录设为 ekr_rag，仓库目录设为 ai-starter-kit。用哪个加载器由配置决定：演示先用 PyPDF/PyPDF2，也可以换成 Unstructured。

输入文档是 SN40L 论文，内容涉及 SambaNova 的硬件、技术栈和专家组合。练习通过 GitHub 提供这份文档，也可以换成自己的 PDF。PyPDF 把文档内容加载成一个列表，再用 LangChain 的递归切分器切块。块大小设为 1,200、重叠设为 240，演示用的 15 页 PDF 切出了 89 个块。口头介绍的配置没说大小的单位，所以不要把 1,200 理解成 token 数。

接着在 config.yaml 里把嵌入类型设为 SambaStudio，让嵌入在 RDU 上执行。端点每批接受 1 个或 32 个块；批大小设为 32，就一次处理 32 个块。这个嵌入服务是独立端点，所以 CoE 设为 false。生成的向量在 ChromaDB 里建索引。

演讲者起初预计向量化大约要十秒，随后重启 notebook，重新运行各单元格。重启后，他报告嵌入演示文档用了四秒。这只是本次运行的耗时，不是 CPU 与 RDU 的对比。

现在，QA 链会把收到的问题嵌入成向量，检索出最相关的三个块，连同问题一起交给 LLM。这次运行没有用重排序器。提问“What is a monolithic model?”（什么是单体模型？），演讲者形容回答是瞬间出来的；notebook 在答案旁边显示了来源链接和检索到的原文。结果一目了然：生成的答案能追溯回所依据的文档。

12
