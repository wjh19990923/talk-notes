为大众消费者打造一个智能体式视频剪辑器

Reelful 通过媒体理解、一份经批准的创意方案、基于代码的合成和验证循环，把个人拍摄的素材变成可分享的短片。

对 React 有基本了解有助于理解合成示例；不需要视频剪辑经验。

01

那些从未被分享出去的录像

大会上有多少人拍了照片或视频？又有多少人真的把视频发出去了？Ekaterina Deyneka 用这两个问题开场。问到第二个时，举手的人少了不少。她自己录过会议、活动、旅行和聚会，对这种情况再熟悉不过：拍素材很容易，把素材做成值得分享的东西却得下功夫。

剪视频枯燥，大部分靠手工，还离不开审美判断。Deyneka 是 Reelful 的创始人兼 CEO。Reelful 把这道坎当作智能体剪辑问题来解决：用户只管提供素材，剪辑交给智能体。素材一直躺在相册里，卡的正是剪辑这一步。

02

从素材和指令到一段成片

起始界面很简单：把照片和视频拖进来，再交代一下发生了什么，或者说说想怎么剪。用户可以要求加字幕、配乐或旁白。智能体要看懂素材，找出合适的片段，把它们拼起来，再生成所需的辅助素材（包括 B-roll），最后交回一段可以直接分享的短片。

拿对着镜头讲话的视频来说，剪辑要做什么就很具体了。原始素材里可能有长时间的停顿，也有说砸了的段落。理想的成片只留下有用的讲话，去掉这些打断，用户不必自己去找每一个剪切点。Deyneka 接着展示了一段剪好的视频预览：这个产品交付的是成品短片，而不是一份剪辑说明。

03

一个产物不同的应用构建器架构

底层架构和智能体应用构建器很像。两者都从用户请求开始，启动一台远程机器，也就是沙箱（sandbox），让智能体在里面调用工具和技能干活。视频剪辑器的请求里还多了媒体素材。对比幻灯片上有个标题写重复了，Deyneka 顺手更正：第二列应该是“智能体视频剪辑器”。

| 组成部分 | 智能体应用构建器 | 智能体视频剪辑器 | | --- | --- | --- | | 输入 | 提示词 | 媒体素材 + 提示词 | | 执行 | 智能体在沙箱中调用工具和技能 | 智能体在沙箱中调用工具和技能 | | 工作产物 | 代码库 | 视频合成（composition） | | 用户看到的结果 | 应用预览 | 渲染好的视频 |

两者在架构上真正相通的是工作产物：智能体在远程环境里修改一个结构化的项目，系统再把这个项目变成用户能查看的东西。

04

真实的素材约束了创作任务

基础设施相同，不代表创作难题也一样。Reelful 专注剪辑用户自己拍的真实生活素材，自己生成的内容相对很少。Deyneka 认为这比从一张白纸开始更难：智能体得从现有素材里挑出最好的片段，决定哪些不要，再把剩下的组织成连贯的序列。

素材还可能杂乱、不完整，但质量目标不变：做出精致、有专业水准的剪辑，最好让观众分不出是人剪的还是 AI 剪的。这是指导选材和拼接的方向，演讲并没有拿出实测结果。

05

先理解素材，再批准方案

整个流程把“做什么”和“怎么剪”分成两步：

1. 理解素材。 搞清楚用户给的视频片段和照片里发生了什么。如果有对着镜头讲话的素材，就把讲话转成文字。 2. 提出创作方案。 开剪之前，用户可以批准方案、提出修改，或者重新生成。 3. 启动执行环境。 用户批准方案后，拉起沙箱，智能体就在里面干活。

有了审批这一步，用户可以在智能体动手拼合成之前先把方向纠正过来。

06

剪辑判断在工作流的哪里介入

在沙箱里，智能体带着一套技能（skills），里面写好了剪辑上的各种判断。Deyneka 举的例子把品味和手艺落到了具体决策上：

- 剪辑规则：怎么挑出最好的片段。 - 字体搭配：哪些组合适合特定场景，哪些不适合。 - B-roll 说明：怎么为这次剪辑生成补充镜头。

智能体靠这些技能，把手头的素材组织成一个视频合成。

智能体还可以启动子进程：按这段合成量身生成音乐、生成旁白、加音效，或者让图片动起来。这样，用户提供的照片可以变成动态元素，不必在整段视频里一直是静止画面。这些素材会进入下一阶段：Remotion 合成。

07

把剪辑表示成代码，再验证它

Remotion 让人可以用 React 编程来合成视频。Deyneka 用素材、轨道和它们的顺序来描述这种表示方式。更准确地说，一个 composition 由一个 React 组件加上帧率、尺寸、时长等视频元数据组成。她说这个框架是开源的，但它目前公开的源码用的是一份特殊许可证，对使用资格和商业用途都有限制条件。

用代码表示合成，剪辑决策就变成了编程智能体能完成的任务。 举个例子，一个很小的 React 合成就能表达两张照片先后出现。其中 from 和 durationInFrames 定义时间线，composition 本身则提供输出的元数据：

```tsx import { AbsoluteFill, Composition, Img, Sequence, registerRoot, staticFile, } from 'remotion';

const PhotoEdit = () => ( <AbsoluteFill style={{backgroundColor: 'black'}}> <Sequence from={0} durationInFrames={60}> <Img src={staticFile('arrival.jpg')} style={{width: '100%', height: '100%', objectFit: 'cover'}} /> </Sequence> <Sequence from={60} durationInFrames={90}> <Img src={staticFile('gathering.jpg')} style={{width: '100%', height: '100%', objectFit: 'cover'}} /> </Sequence> </AbsoluteFill> );

const Root = () => ( <Composition id="PhotoEdit" component={PhotoEdit} durationInFrames={150} fps={30} width={1080} height={1920} /> );

registerRoot(Root); ```

这里的文件名和时长只是为了说明表示方式；实际用哪些素材、怎么排列，要由 Reelful 的智能体根据素材和批准过的方案来定。Deyneka 选这条路，理由是智能体本来就擅长写代码。

代码生成之后，还有一层验证层。它检查合成是否干净、定义清晰、能够渲染。如果发现问题，智能体会反复修改合成，然后再产出精致的成片。这个循环会检查生成出来的产物，而不是默认第一版合成就能跑通；至于具体查哪些项、怎么实现，演讲没有细说。

08

隐藏工作流但不移除控制权

理解素材、制定方案、在沙箱中执行、生成素材、合成、验证，这是一套复杂的流程，普通用户不需要全部搞懂。Reelful 在界面上的第一个选择是移动端优先，好让创作融入日常生活。Deyneka 提到了散步和举铁，还把开车列为一个使用场景；不过要操作剪辑器，得等车安全停好再说。

接下来两个选择，分别针对不同的使用阻力：

- 方向模板省去写提示词的功夫。 用户可以选“对镜讲话”“B-roll”或“旁白”方向，然后把素材拖进来。Deyneka 说，不写明确的提示词也能用。 - 内置剪辑器保留熟悉的掌控感。 智能体生成之后，用户可以手动做些小改动，比如删掉一秒，或者改正字幕里的一个词。

初版视频由智能体生成，精细调整交给熟悉的剪辑器。随后，Deyneka 展示了她最近用 Reelful 做的几个视频。

09

一段活动回顾，然后回到录制

播放的示例以一场 Cursor 创作者专属晚宴（Cursor Creators Dinner）的邀请开头。播放中途停了一下，Deyneka 确认观众能不能听到声音。接着，旁白介绍了活动场地：一处定制空间，布置成了热带日落的样子。视频先交代场地，再一步步带出整场体验。

接下来是美食和氛围：从洛杉矶请来的私厨，龙虾、和牛、螃蟹，还有草莓冰淇淋。视频随后转到大家聊各自工作的场景，讲到融入这个社区有多轻松，说到礼物时播放就断了。这个例子很具体地展示了理想的成品：把活动录像拼成一段带旁白、适合发社交媒体的回顾视频。

Deyneka 说，这些视频全靠智能体拼成，没用常规的视频剪辑软件，而且她已经在社交媒体上发了。这正好呼应了开场的问题：以前录完就压箱底的素材，现在成了她发布的内容。

在大会现场，她开放了 Reelful 第二版的 beta 体验。产品还处在早期，正在积极开发中。她欢迎大家提反馈、发邮件联系，也想听听大家实际怎么用。她还宣布 Reelful 最近拿到了 a16z Speedrun 的投资。

最后，她提议和观众一起拍段视频。演讲在开头的地方收尾：又有人在记录一场活动，只是这一次，手里有了把录像变成可分享内容的工作流。
