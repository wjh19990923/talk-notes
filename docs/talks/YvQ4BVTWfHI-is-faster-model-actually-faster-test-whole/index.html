更快的模型真的更快吗？测一测整个任务

Morgan Suo 用一个金融研究任务，把模型优化与一份分析师真正能用的报告的准确性、成本和等待时间联系起来。

01

任务是一份可核查的研究报告

A research report arrives quickly, but it misses an important source. Someone must find that source and repair the report before using it. Morgan Suo of MiniMax starts with that familiar failure: a faster model response does not necessarily mean a faster finished job.

The example asks whether suppliers of printed circuit boards for AI servers are turning growing demand into cash. An internal review describes work across 14 company reports. The model must find the right reports, compare matching reporting periods, keep separate businesses distinct and explain the numbers. The analyst receiving the result needs to open the sources behind important claims, check calculations and see what evidence might change the conclusion.

Profit and cash flow make the distinction concrete. Sales and reported profit can rise while customers have yet to pay, or while purchased materials remain in storage. A useful report points the analyst to the cash flow statement and relevant disclosures to investigate why. The internal review describes the output; its sources and calculations still need verification, and the same job needs time and cost measurements. The technical tests that follow use separate tasks to expose individual tradeoffs.

02

稀疏注意力仍然必须找到那条脚注

MiniMax M3.1 Flash has a stated one-million-token context window, but capacity alone does not say whether the model can use the right passage quickly and accurately. Sparse attention reduces work by scoring blocks of text and applying the main attention calculation to a selection, while keeping nearby text in view. The selected blocks can change with the query: a cash-flow question may need a different part of a report from an industry-outlook question.

That selection creates a consequential test. A short footnote may change the conclusion even if many pages of outlook seem relevant. Suo says the model uses sparse attention in its first three layers. In a separate retrieval test that placed facts at different positions in long inputs, one run passed all 39 requests, with the longest inputs around 830,000 tokens. That result covers the cases in that test.

For the analyst's job, repeat the question on real reports while moving the important passage to different positions. Check whether the model finds the cash-flow footnote, uses the right period and notices conflicts between documents. The goal is to save attention work without losing the evidence that decides the answer.

03

更小的 KV 缓存可能掩盖不均衡的质量变化

The key-value, or KV, cache retains internal information for the model to use later. M3.1 Flash stores its keys and values at 4-bit precision instead of 8-bit, while queries remain at 8-bit. Fewer bits can reduce the data stored and moved, at the cost of representing those values less precisely.

How much does that precision change matter to the answer? In the comparison Suo shows, the average score is nearly unchanged, yet one individual score falls by 6.6 percentage points while others rise. The table compares two full setups, so it does not isolate which change caused each score difference. An average can still conceal a failure important to a particular user: for the research report, check the sources, arithmetic and whether the explanation follows the evidence.

04

低精度专家依赖于计算顺序

The model also uses a mixture-of-experts architecture: it selects some computing components, called experts, for each token. The selected experts use 4-bit weights and activations; the shared expert is outside that change. Weights are stored model values, while activations are values calculated as the model runs. Lower precision can reduce data movement and make computation more efficient, but the calculation must scale values, perform the operation and restore the scale in the right order.

The placement of scale restoration matters to the result, so measure the complete implementation as well as its speed. Then rerun the same research questions and check whether their answers still meet the agreed standard.

05

推测解码只有在草稿划算时才省时间

Speculative decoding changes how the answer is generated. A faster draft process proposes a short sequence of tokens; the target model checks it. The system keeps the initial portion the target accepts, corrects a rejected token when necessary and continues. The diagram traces the two outcomes after that check.

The opportunity is to obtain several accepted tokens from one target check. The cost includes drafting, checking and work on proposals that cannot be kept. Acceptance by the target model is also separate from checking a financial claim against its source. For the research job, retrieval, tool calls and retries belong in the clock for a usable report.

From draft tokens to the next generation step The target check determines how much of a draft is kept; a mismatch adds a correction before generation continues. - Draft process — Proposes a short token sequence. - Target model — Checks the proposed tokens. - Accepted prefix — Keeps the initial tokens the target accepts. - Correction — Corrects the proposal when needed. - Continue — Repeat generation from the resulting sequence. - Draft process → Target model (Proposes tokens) - Target model → Accepted prefix (Keeps accepted beginning) - Accepted prefix → Correction (If correction is needed) - Accepted prefix → Continue (If the draft is accepted) - Correction → Continue (Continue after correction)

06

更高的吞吐量可能意味着更长的等待

A separate serving test used story generation at low reasoning effort. When concurrent requests rose from 32 to 64, total output per second grew about 1.9 times. At the same time, the P95 wait for a first token rose roughly eightfold from about 1.5 seconds. P95 describes the wait by which 95% of requests had received a first token; Suo contrasts this deterioration with a median that remained acceptable.

More aggregate output does not tell an individual analyst when the report will be ready. The first token may itself be reasoning rather than the finished answer. Set a deadline for the usable report, test at the expected load and choose a serving level that meets it.

07

推理强度同时改变工作量和准确率

Reasoning effort controls how many tokens the model uses for thinking. In the setup Suo describes, thinking remains on and leaving effort blank defaults to max. A default can therefore request more work than a user intended.

In one coding test, high reasoning used fewer output tokens than max, but accuracy fell from 80% to 68% on those task items. The comparison shows the price of a smaller budget for that test, not a universal difference between settings.

Compare effort settings on the same company reports: does each find the relevant evidence and support the calculations? A quick first pass and a report ready for review may need different budgets. Record the chosen setting so the comparison can be repeated.

08

以可接受的报告为标准评估这次切换

Start a model comparison with the same question, source reports and information cutoff, and agree in advance on what makes the report acceptable. Suo proposes three checks:

- Trust: Open sources behind important claims, check reporting periods, recalculate financial figures and look for evidence that could change the conclusion. - Finished-job cost and time: Count retrieval, tool calls, retries, failed attempts and human repair. Test at the expected number of users and measure whether acceptable reports arrive within the promised time. - Repeatability: Save model and runtime versions, prompt settings and sources, and keep examples of failures. Start with a small rollout and retain a way to switch back.

Suo closes with the analyst's standard: sources that can be opened, numbers that can be checked and a report that arrives when needed. The model's optimizations change where computation is spent; the complete task reveals what those changes mean to the person doing the work.

要点总结

  • 衡量得到一份可接受报告所需的时间和成本，包括检索、重试、失败的尝试和人工修补。
  • 稀疏注意力通过选择文本块来减少计算，所以要测试重要的证据在真实文档的不同位置上是否仍能被找到。
  • 更低的精度可以减少数据搬运，但几乎相同的平均分可能掩盖个别任务上的变化；完整配置之间的比较无法单独分离出原因。
  • 对照实际工作所需的截止时间和质量来测试服务负载和推理强度，而不是只依赖吞吐量或首 token 延迟。
