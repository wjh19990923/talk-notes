Your SKILL.md Is 70% Stuff the Model Already Knows

In the first skill Nikolay Petrov’s team tested, the model already knew 70% of the material. Testing individual claims helps an editor find the details worth keeping. Running the original tasks shows whether the shorter file still works.

01

What bought the last two task passes?

A prompt you keep typing is a good candidate for a skill. Pack the instructions into a file and another agent can use them, too. Nikolay Petrov of Intel distinguishes two reasons to do this. A process skill gets an agent to perform familiar actions in a repeatable order. A knowledge skill supplies information the agent needs to solve a problem. For that second kind, it makes sense to ask how much of the file the model already knows.

Start with tasks whose results you can check. Give the agent the same tasks in two conditions, once without the skill and once with its instructions in context. In Petrov’s example, the agent solves three of five tasks without the file and all five with it. Loading the file buys two additional successes. Token use and time to completion are separate costs you can compare across the runs.

Now suppose you want to shorten the file or move it to a newer model. The five passes tell you the skill works as written. Which instructions earned their place? User feedback can point to a task that went badly. Trying combinations of line edits can narrow the search, at the price of running each combination. There’s also a choice about what to edit. A line, a sentence and an idea can be three different units.

02

Give each claim a question and an expected answer

Petrov borrows an idea from FActScore: split the text into claims small enough to check individually. In a skill, an item might express a proposition about how something works. It might also specify what action the agent should take, which Petrov calls a contract. For each item, write a question and the answer you expect. He gives 25 or 30 items as an example budget for one skill.

Who gets to see which information? The target model gets the same question in both runs. Only one run gets the skill. A judge, ideally from a different model family, or a panel of judges grades each response against the expected answer. Keep that answer out of the question itself. If the question gives away the detail, even the run without the skill can get credit for repeating it.

Tool access changes the meaning of a correct answer. With tools and other information withheld, the baseline probes what the model can supply on its own. Give both runs web access and the comparison answers a practical question about a working agent. The baseline can now succeed by looking something up. In either setting, each claim gets a pair of grades, while the input that varies is the whole skill. Finding out what happens when you delete a particular sentence takes another experiment.

Which inputs reach the model, and which reach the judge? Follow the question through both runs. The skill enters only one branch. The branches meet at grading, where the same expected answer applies to both responses. - Item question — Ask about one claim or required action. - Skill text — The full instructions available as context. - Run without skill — The target model answers the item question. - Run with skill — The same model answers with the skill loaded. - Expected answer — Defines what counts as correct for this item. - Judge or panel — Grades each response to produce the pair of results. - Item question → Run without skill (same question) - Item question → Run with skill (same question) - Skill text → Run with skill (additional context) - Run without skill → Judge or panel (answer without skill) - Run with skill → Judge or panel (answer with skill) - Expected answer → Judge or panel (grading reference)

03

Four ways a single item can score

A pass with the skill loaded could mean the instructions taught the model something. It could also mean the model could already answer the question. Read the baseline grade first, then the grade with the skill.

- Pass → pass. The model could already give an acceptable answer. The corresponding passage is a candidate for shortening. - Pass → fail. Loading the skill spoiled a previously correct answer. Inspect the instructions associated with that regression. - Fail → pass. With the skill, the model can answer a question it previously missed. Preserve the detail that enabled the answer. - Fail → fail. The model still misses the concept with the instructions in hand. If the task needs it, check whether the wording makes the expected answer or action clear.

04

Put the grades back on the lines they describe

Petrov starts with regressions. Here the model has demonstrated that it can answer the question, and loading the skill makes it stumble. These cases were rare in the popular skills tested. In one collection, only one item out of roughly 400 showed a regression. Even that single item gives the editor a specific passage to investigate.

Where in the file did the skill supply something useful? Petrov’s example colors the source lines by outcome so an editor can locate passages that helped and passages the model already understood. The distinction can be finer than the display suggests. Two claims in one sentence can earn different colors. Deleting the whole sentence could take the one needed detail with it.

Each question costs model calls in both conditions, plus grading. Petrov reports spending about $14 across 29 skills in a run using Haiku and Sonnet, with Sonnet as judge.

05

Knowing the idea and supplying the right key

How precise does an answer have to be to pass? Lenient grading accepts the general idea. Strict grading checks the details the task calls for, such as a particular key, parameter, value or sequence of steps. An answer can explain what a parameter does and still leave the agent without the value it needs to use.

In the larger-model comparison Petrov highlights, the model met the general-idea standard on 70% of the material. When the judge required the specific details, the score fell to 22%. That gap explains the risk in shortening a skill by eye. The introductory explanation may be easy for the model to reconstruct. A key or value that barely registers in a summary may be the part the agent needs from the file.

06

The same file can teach two models different amounts

How well does a result for one model carry over to another? Across three popular skill repositories, the smaller model generally knew less of the material than the larger Sonnet model, though both already understood a substantial amount. A passage that looks redundant in a Sonnet run may still supply something the smaller model needs.

The recording’s description places the headline’s 70% figure on the first skill the team tested. Results varied considerably from skill to skill, and the purpose of each file matters. A process skill can do its job by getting the agent to choose a particular workflow even when every action is familiar. For skills meant to teach, Petrov would run the comparison across a broader set of models and model families before deciding which details to remove.

07

Try the deletion on the original tasks

A model can explain an idea when asked directly and still benefit from a reminder while doing the work. Petrov proposes a deletion experiment. Remove some or all of the material the model could explain unaided, load the shorter skill, and rerun the original task evaluations. Compare which problems the agent solves with each version. If it still solves the same problems, the shorter file saves input tokens and leaves more room in context. The 70% knowledge result identifies candidates for that experiment. How much text can go depends on the task results.

The team ran the experiments in a framework for comparing how agents use context, including skills, AGENTS.md instructions and MCP tools. It also supports task evaluations, routing checks and comparisons of names and descriptions. Those checks address different decisions. A description can affect which skill the agent selects. Once the skill is loaded, the item questions locate details worth editing, and the task evaluation shows whether the agent can still finish the job.

要点总结

  • Ask one question per claim in both conditions. Keeping the expected answer out of the question makes the baseline informative.
  • Grade at the precision the task requires. In the highlighted comparison, 70% under a general-idea check fell to 22% when the judge required specific details.
  • Use the paired grades to choose a deletion. Test its effect by comparing the shortened file with the original on the tasks the skill was written to solve.
