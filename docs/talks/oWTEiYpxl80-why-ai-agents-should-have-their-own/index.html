Introducing the Interactions API

幻灯片原文
The Interactions API uses the same interface for models and agents: each takes an input, with tools for a model or an environment for an agent. It also supports optional server-side state and long-running tasks.

[3:22](https://www.youtube.com/watch?v=oWTEiYpxl80&t=202s) [Interactions API benefits and code examples for models and agents.](https://assets.ai.engineer/sites/aiecode2025/sha256/5e72c472e10a3618ebbea087f3649b7af4f1ba99bb1fa95ed95069beffd9338c.webp)

Introducing the Interactions API

A unified API to support inference of models and agents. Built for:

Complex context management
Long horizon background tasks
Optional server side state management
Easy interpretability and composability
Combined-tool use (Google Search + Custom Functions)

For Models

from google import genai

    model="gemini-3.5-flash",
    input="Who won the last euro?",
    tools=[{"type": "google_search"}],
)

# 1. First turn
interaction1 = client.interactions.create(

    input="Hi, my name is Phil."
)

Audio Generation

import base64
from google import genai
import wave

# Set up the wave file to save the output:
def wave_file(filename, pcm, channels=1, rate=24000, sample_width=2):
    with wave.open(filename, "wb") as wf:
        wf.setnchannels(channels)
        wf.setsampwidth(sample_width)
        wf.setframerate(rate)
        wf.writeframes(pcm)

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-3.1-flash-tts-preview",
    input="Say the following: WOOHOO This is so much fun!. [laughs]",
    response_modalities=["AUDIO"],
    generation_config={
        "speech_config": {
            "language": "en-us",
            "voice": "kore"
        }
    }
)

for output in interaction.steps:
    if output.type == "audio":
        print(f"Generated audio with mime_type: {output.mime_type}")
        # Save the audio as wave file to the current directory.
        wave_file("generated_audio.wav", base64.b64decode(output.data))

import base64
from google import genai

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-3-pro-image-preview",
    input="Generate an image of a futuristic city.",
    generation_config={
        "image_config": {
            "aspect_ratio": "9:16",
            "image_size": "2k"

)

    if output.type == "image":
        print(f"Generated image with mime_type: {output.mime_type}")
        # Save the image
        with open("generated_city.png", "wb") as f:
            f.write(base64.b64decode(output.data))

from google import genai

client = genai.Client()

file_incident = {
    "type": "function",
    "name": "file_incident",
    "description": "Files a security incident in the internal tracking system.",
    "parameters": {
        "type": "object",
        "properties": {
            "cve_id": {"type": "string", "description": "CVE identifier"},
            "severity": {"type": "string", "description": "Critical, High, Medium, or Low"},
            "summary": {"type": "string", "description": "Brief description of the vulnerability"},
        },
        "required": ["cve_id", "severity", "summary"],
    },
}

interaction = client.interactions.create(
    model="gemini-3-flash-preview",
    input="Search for the latest critical CVE affecting react, read the full advisory page, and file an incident for it.",
    tools=[
        {"type": "google_search"},
        {"type": "url_context"},
        {"type": "function", "name": "file_incident", "parameters": ...},
    ],
)

for output in interaction.steps:
    print(f"{output.type}...")
    if output.type == "function_call":
        print(f"Function: {output.name}")
        print(f"Arguments: {output.arguments}")

The Steps Data Model

幻灯片原文
Interactions use a typed timeline of steps instead of user-model turns. Each action or generation has its own type, so a function result can be represented as a function result rather than a user message.

[6:37](https://www.youtube.com/watch?v=oWTEiYpxl80&t=397s) [Slide describing typed interaction steps, their statuses, and a JSON example.](https://assets.ai.engineer/sites/aiecode2025/sha256/4f8080022f4e7214e78768de414bc2d32fbe5d7ed4704aa317e08197b702a115.webp)

Part 1: Interactions API & Agents

The Steps Data Model

A typed timeline of everything the model did

Steps [ ] replaces the legacy Outputs [ ] array
Type discriminator: Model_output, thought, Function_call, google_search_call
Content [ ] is reserved for raw modalities (text, image, audio, video)
Structured data lives in typed fields (name, arguments, signature)
Step Status: done, waiting, in_progress

{
  "id": "int_456",
  "status": "COMPLETED",
  "steps": [
    {
      "type": "thought",
      "status": "done",
      "summary": [{"type": "text", "text": "Analyzing request..."}],
      "signature": "abc123..."
    },
    {
      "type": "model_output",
      "status": "done",
      "content": [
        {"type": "text", "text": "Here are the results..."}
      ]
    }
  ]
}

为什么 AI 智能体应该有自己的沙箱

Philipp Schmid 讲解了 Gemini 的 Interactions API 和托管的 Antigravity 智能体如何把执行转移到一个持久的云端环境中，然后拆解了一个“AI 谈话电台”演示，展示指令、技能和模型调用如何组合在一起。

01

从补全句子到朝着目标工作

A model that continues a poem needs text. An agent asked to research a topic, create files, and return later needs somewhere to work. Philipp Schmid, who works on AI Studio and the Gemini API at Google DeepMind, starts with that change in expectations: applications have moved from requesting an answer to assigning a goal, describing how to verify it, and hoping the system can keep working for hours or days.

The progression explains why the surrounding API has to change. Early text completion extended a supplied prefix. Instruction following made questions and answers useful. Chat introduced alternating user and model messages, and function calling let the model request actions. Once reasoning and actions sit between the initial request and the final result, the application has to represent more than a conversation: it has to handle ongoing work and the environment that work changes.

The opening also points to an expanding workload: image generation and programmatic video creation and editing join text in the API. For experimentation, AI Studio provides API-key setup, billing, and budgets without a separate trip into Google Cloud. The rest of the talk develops the execution model beneath those capabilities.

02

一个接口，历史和长时间运行的工作都放在服务器上

The Interactions API gives models and agents the same basic calling pattern. Choose a model or agent, supply an input, and attach the tools or environment it needs. Input can be a string or multimodal data. Schmid compares this to OpenAI's Responses API: the important change for this talk is that calling an agent does not require a separate style of interface from calling a model.

What must a client send when work continues? With server-side state, a follow-up request supplies the new input and the previous interaction's ID. The server assembles the earlier context so the model can see what has happened. This moves history management out of the client; the application still identifies which interaction it is continuing.

```python from google import genai

client = genai.Client()

# 1. First turn interaction1 = client.interactions.create( model="gemini-3-flash-preview", input="Hi, my name is Phil." ) print(f"Model: {interaction1.output_text}")

# 2. Second turn (passing previous_interaction_id) interaction2 = client.interactions.create( model="gemini-3-flash-preview", input="What is my name?", previous_interaction_id=interaction1.id ) print(f"Model: {interaction2.output_text}") ```

Long-running operations address a different problem. Video generation can take long enough that keeping an HTTP connection open is inconvenient. The client starts the operation, receives an ID, and follows completion through streaming or polling. Conversation history and operation tracking both use identifiers, but serve different purposes: one carries context forward; the other lets an application follow unfinished work.

The same interface extends to output modalities. For speech, the request selects Gemini TTS, supplies the input, requests audio output, and configures a voice. Image generation follows the corresponding pattern: select the image model, supply the input and generation configuration, then receive an image. The shared interface keeps the request structure familiar while modality-specific settings describe the desired result.

03

一次 CVE 查询说明了为什么工具结果需要自己的类型

The React CVE example makes tool composition concrete. What does each tool contribute to turning a question about vulnerabilities into usable records?

- Google Search: Finds relevant material about CVEs affecting React. - URL context: Visits the websites used in the lookup. - Custom function calling: Gives the findings structure suitable for later lookup or storage in a database.

The request declares these capabilities together, and the model decides which tool it needs to call. This is a small lookup agent; the example explains how information becomes structured output, without establishing that the search finds every relevant vulnerability.

That example exposes a mismatch in a simple user/model transcript. A function's output comes from the environment, yet an older turn-based representation can require returning it as user content. Reasoning introduces another kind of event: a model may expose thoughts or a signature before it produces its answer. Treating all of these as ordinary conversation turns obscures what actually happened.

Interactions instead represents execution as a timeline of typed steps. Each action or generation has its own type, and a function result is returned as a function result. The distinction gives the application a more explicit record of execution and leaves room for new event types. A user request, a generated answer, and an environment's return value can retain their different meanings.

04

沙箱在请求之间保存工作

The Antigravity agent in the Gemini API uses the same harness as the Antigravity product. Here, a harness means the backend machinery that runs the agent. It does not imply identical agents: the IDE's coding agent and the API agent can have different tools and system instructions. Improvements to Gemini's behavior with the shared harness can benefit both products while their configurations remain distinct.

An environment field supplies the agent with a managed cloud sandbox. The backend starts it, and the agent can run code, create and edit files, install dependencies and tools, and call APIs. The developer sends a request rather than provisioning the execution infrastructure. This is the practical meaning of giving an agent its own computer: its actions have a filesystem and runtime in which to take effect.

The environment can persist across interactions. In Schmid's example, an initial request researches the latest technology news and creates a file; a follow-up reuses the same environment. The next request therefore has access to the earlier filesystem work, alongside the conversation context carried by interaction state. Persistence is described as a capability here, without a specified retention period.

The filesystem also provides a way to share work. Three agents can use one environment and exchange context through files, or a subagent can pick up work another agent has done. That makes file creation useful beyond a single request: it can become a handoff between agents. Shared access is the mechanism described; it does not by itself define how simultaneous edits are coordinated.

A useful computer needs the right starting material. Sources can come from GCS buckets, GitHub repositories, or inline files. Skills stored in the skills directory are picked up automatically and included in the system instruction, as is an AGENTS.md file. These files supply procedures and instructions that shape how the agent uses the environment.

05

把一个准备好的环境变成一个可复用的智能体

Sending all configuration in an individual request is convenient until another team needs to reuse the agent. The Agents API packages a base agent, instructions, and an environment into a reusable definition. The environment can be described through sources or taken from an existing environment.

How does work done during setup become the starting point for later calls? Schmid's example lets an agent install the GitHub CLI, add skills, and perform sanity checks. Once setup finishes, its environment ID is used to create a new agent. Calls to that agent then start from the prepared environment. The dependency matters: the reusable agent is defined from the result of setup, so its callers do not have to repeat that scaffolding themselves.

The Gemini API CLI provides a command-line route to these operations. It is an API client rather than a coding agent, and is distinct from Gemini CLI. An existing agent can use it to request generated assets, create agent definitions, and iterate on them. Dedicated skills for the Interactions API and Agents API supply additional guidance for that work.

From setup work to a reusable starting environment The environment ID connects completed setup to the new agent definition; later calls start from that prepared environment. - Agent prepares environment — Installs GitHub CLI, adds skills, and performs sanity checks. - Prepared environment ID — Returned after the setup agent finishes. - Create reusable agent — Define the base agent and instructions using the existing environment. - Later agent calls — Start from the preloaded, preconfigured environment. - Agent prepares environment → Prepared environment ID (Returns identifier after completion) - Prepared environment ID → Create reusable agent (Identifies the environment to reuse) - Create reusable agent → Later agent calls (Supplies prepared starting environment)

06

AI Talk Radio 把一个话题变成一场表演出来的辩论

AI Talk Radio puts a simple UI over a managed agent with access to research, thumbnail generation, speech, and music. The live input asks whether pineapple belongs on pizza. The environment starts, the model considers the work, installs Python dependencies, reads the skills, and continues. Those setup actions are part of producing the show, rather than tasks the user performs beforehand.

While that request runs, Schmid plays an earlier show about whether cereal or milk should go into a bowl first. The distinction matters: the recording demonstrates playback of the earlier output, rather than completion of the live pineapple request. The example aims for a call-in radio format, with a host introducing a topic and multiple characters offering opinions.

The generated host, Paul, welcomes David from Boston. David makes cereal the “independent variable”: pour it first, observe its volume, then add enough milk to complement it. He also argues that dropping dry cereal into milk causes splashing and compares milk-first preparation to putting gravy in a bowl before the mashed potatoes. Paul turns those remarks into two themes—cleanliness and portion control—then introduces Sarah from Sydney, who opens the counterargument with texture.

That short exchange shows what the workflow produces: differentiated characters, a developed argument, a host's transition, and the beginning of a rebuttal, delivered as speech. The fictional locations and callers belong to the generated program. They give the output a radio-show structure rather than implying real people have joined a live broadcast.

The applet sits in AI Studio's Build gallery and can be remixed. A developer could change the format toward a podcast application while retaining the underlying generation capabilities. The next part of the demo opens the code to show what must move with that behavior.

07

深入电台智能体：指令、技能和 Python

“Our agent is just files” is the useful compression of the demo's implementation. An AGENTS.md file lives inside the environment and is loaded into the system instruction at startup. It tells the agent to research, write scripts for the different people, generate music and speech, and mix the outputs together. The managed runtime executes the agent, while these files describe the application-specific work.

Where does a text instruction become an audio-producing action? The TTS example has both a skill explaining how to run generation and a Python file implementing it. That Python file calls other Gemini models through the Interactions API to generate speech the agent can use. The instruction file describes the intended show; the skill describes a procedure; the Python implementation makes the model request. Together, they connect planning to an artifact that can be mixed into the program.

This file-based arrangement also explains the path from an applet to a backend. Schmid describes copying the agent files, creating the agent, and invoking it outside the UI. The reusable part is the instruction and skill setup in its environment; the radio interface is one way to supply a topic and present the result.

08

检查计算机、取回它的文件，让循环留在服务器上

The final demo makes the environment itself the subject of the request. In the playground's agent picker, Schmid selects the standard Antigravity template and asks it to explore where it is running. He estimates seven to ten seconds for the first request to start the environment. The agent runs inspection commands and reports Ubuntu, eight vCPUs, 16 GB of memory, Python, and pip. These are the reported properties of this demo environment, rather than a specification for every sandbox.

```text System Profile and Resource Allocation

By aligning our execution strategies with the exact capabilities of this system, we minimize operational friction and maximize throughput:

• Operating System: Ubuntu 24.04.4 LTS (Noble Numbat). Detailed system configuration parameters can be referenced in the system configuration file: /etc/os-release. • Kernel Version: Linux 4.19.0-gvisor x86_64 (running under a secure and optimized gVisor virtualization layer). • Computational Capacity: ◦ CPU: 8 vCPUs (configured as 8 cores per socket), which provides excellent parallel processing capabilities to complete tasks rapidly. ◦ Memory: 15 GiB of total system RAM (with approximately 15 GiB currently free), enabling us to handle memory-intensive operations without bottlenecking or triggering out-of-memory errors.

Pre-Installed Tooling (Zero-Setup Friction)

The presence of pre-configured tools eliminates installation overhead, saving valuable time and energy:

• Python: version 3.12.3 (accessible via python3) • pip: version 24.0 (for installing packages, use --break-system-packages where necessary) • curl: version 8.5.0 (fully enabled with support for HTTPS, HTTP2, and standard networking protocols) ```

A follow-up asks whether Node is installed, continuing the investigation in the environment. The recording does not give that answer. For work that produces files, the playground offers an environment download, and an API provides a retrieval route as well. This completes the practical path from remote execution to artifacts a user can extract or share.

The closing explanation locates the main architectural decision. In a client-managed agent, the application receives a function call, executes it somewhere, and sends back the result. With the managed agent, a request starts the sandbox, loads the files, and runs the agent loop on the server. The single API call is the entry point to that execution; the work inside it can still involve many actions and model calls.

Tools can extend that environment in two ways: connect a remote MCP server, or run a local MCP server inside the sandbox. The developer trades direct responsibility for provisioning and driving the loop for a managed execution path, while still supplying the files, instructions, and tools that determine what the agent can do. Schmid closes by pointing to the agents quick start and coding skills as the route to sending a first request and building a reusable agent.

要点总结

  • 交互历史和沙箱文件承载着不同类型的连续性：交互 ID 保存对话上下文，复用环境则保存被动作修改过文件、安装过工具的那个地方。
  • 带类型的步骤让函数结果和其他执行事件保留自身的含义，而不是被表示成普通的用户消息。
  • 智能体可以先准备好一个环境，再用它的环境 ID 定义一个可复用的智能体，之后的调用都从已安装的工具和技能开始。
  • AI Talk Radio 让基于文件的机制变得具体：指令描述节目，技能解释流程，通过 Interactions API 进行的 Python 调用为最终的混音生成语音。
  • 托管执行把函数调用循环移到服务器上；开发者仍可以提供环境文件，并连接远程或本地的 MCP 服务器。
