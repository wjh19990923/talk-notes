把持续学习带进企业

在企业拥有可回放的环境之前，生产 trace 就能教会智能体更好的行为。下一步是让提示信息适应当前模型的实际行为。

熟悉语言模型蒸馏、智能体 rollout 和监督微调会有帮助；文中会解释 trace 来源和提示来源如何影响学习。

01

智能体能从昨天的 trace 中学到什么？

手上有一批生产环境的 trace，来自一个能干活、但也会犯错的智能体。怎样把这些 trace 变成更好的模型？这正是 Applied Compute 平台研究负责人 Samuel Denton 的出发点：拿企业已经处理过的请求事后复盘，从中学习。

第一个要定的是：学习和生产环境绑得多紧。一次性批处理给出一份固定记录供学习。每日批处理形成周期循环：部署模型，收集它的 trace，再用这些 trace 改进下一个版本。走到完全在线的那一端，推理和训练合成一个统一的引擎：

1. 处理一个生产请求，生成一次 rollout。 2. 从这条 trace 中提取学习信号。 3. 更新模型。 4. 用更新后的模型处理下一个请求。

这几种做法是同一条光谱上的不同位置，并不是彼此独立的训练方法。

很多企业还停在第一个位置：能拿出历史 trace，也能指出模型哪里不足，但还没有实时的学习闭环。另一些企业已经开始一边承接生产流量，一边更新模型。所以，要支持持续学习，就得在两端都给出好用的切入点，而不是要求企业先搭好一套服务与训练完全打通的系统。

02

教师的额外信息从何而来

trace 什么时候采集，只是一个维度。另一个维度是提示来源：什么信息让教师模型比学生模型（也就是当前在干活的策略）知道得更多？提示（hint）提供的是特权信息，教师可以拿它来引导学习。

离线提示来自静态信息：任务评分细则、行为先验，或者生产中反复出现的某类失败。比如，客服智能体可能退款退得太痛快。这个已知问题就能催生一条提示，套用到大量 trace 上。离线提示的关键特征是：它不依赖当前模型的 rollout。

在线提示根据当前策略实际做了什么来构造。它可以包含同样的行为先验，但其中的纠正信息取决于具体那一次 rollout。把提示来源和 trace 来源两两交叉，得到四种有用的组合。这里的边界是对两条连续光谱的简化，介于两者之间的情况同样重要。

| 组合 | 用于学习的 trace | 提示的依据 | |---|---|---| | 离线 trace + 离线提示 | 录下的生产 trace | 通用的行为先验 | | 在线 trace + 离线提示 | 当前策略的 rollout | 通用的行为先验 | | 离线 trace + 在线提示 | 历史前缀，加上当前策略生成的一步 | 新生成的这一步 | | 在线 trace + 在线提示 | 当前策略的完整 rollout | 这次 rollout 里实际发生的事 |

第一种组合里，退款相关的提示套用到历史 trace 上，蒸馏针对的是那个已知行为。第二种组合里，智能体生成一次新的 rollout，拿到通用提示，更新策略，然后继续承接流量。

第三种组合把历史和下一个决策拆开。几天前录下的 trace 提供一段 off-policy 前缀：生成它的并不是正在训练的策略。接着，当前模型从这段前缀出发生成一步，不与环境交互。提示就根据新生成的这一步来构造。第四种组合把这种依赖延伸到整个 rollout：让当前模型跑完，看它做了什么，量身构造一条提示，再基于这条在线 trace 做蒸馏。

03

不靠重放或标准答案来学习

Applied Compute 主攻第一种和第四种组合。离线 trace 加离线提示，不需要可重放的生产环境。 团队可以先看清发生了什么，再针对性地改一个具体行为：少做不必要的退款、遵守某种格式约定，或者调整推理的长短。企业可以直接拿手头已有的数据起步。

在线 trace 加在线提示，构成一个适应性更强的循环。trace 可以来自可重放的环境，也可以来自真实生产流量。每条提示都针对当前这次 rollout，所以学习过程能在各种行为冒头时逐一处理，再把更新反馈回模型。Denton 认为，要全面提升评测成绩，这条路更容易规模化。

Denton 把这个演进概括为：今天“免费变好”，明天抬高上限。这里说的眼前机会，是复用现成的生产 trace，并不是说训练零成本。等有了在线策略，它产生的新 trace 就能支撑一轮又一轮更新。

一个核心约束是：企业任务往往没有标准答案，也没有覆盖每个请求的完整评分细则。学习方法不能假设数据集里躺着完美的目标回答，得自己提炼出有用的行为指导。把服务和训练基础设施拉近，持续更新才成为可能；至于持续抬高上限，仍是 Denton 对这套系统的展望。

04

教一个编程智能体在截止时间前提交

第一个实验用离线 trace 和离线提示，在 SWE-bench 上改一个具体行为。Denton 说用的模型是 Qwen3.5-Thinking。在这个设置下，它最多要八十轮才提交答案；目标是让它在第四十轮之前调用提交工具。实验要回答的是：模型能不能学会早点收尾，而不是照老习惯走完一条长长的推理路径。

三个指标把“成功提交”和“代码写对”区分开：

| 指标 | 怎样算成功 | |---|---| | 任务完成率 | 智能体调用了提交工具 | | 测试通过率 | 环境中所有任务测试都通过，不管智能体有没有提交 | | SWE-bench 综合通过率 | 既提交了，测试也通过了 |

综合通过率是实验中前两种行为的交集，不是底层测试通过率的另一个叫法。目标是提高综合成功率，同时不削弱代码通过测试的能力。

提示把逼近的截止线讲得很具体：告诉模型离四十轮上限只剩三轮左右；点明它总爱继续探索、迟迟不收尾；要求它在时间用完前定下修复方案、验证一遍、调用提交工具。这条提示纠正的是行为，并没有给出软件问题的解法。

Denton 报告，提交工具的调用率从约 22% 升到 60%，测试通过率基本持平，还略有上升。所以涨的是目标提交行为，并不是说测试成功率本身从 22% 涨到了 60%。

出人意料的是这个行为怎么冒出来的。录下的 trace 几乎从没调用过目标提交工具。蒸馏仍以这些 trace 为条件，教师也没有直接替换工具调用的 token，而是把学生的推理往“把任务做完”的方向推了一把。录下的轨迹里并没有通向这次调用的推理路径，学生却更容易走到提交这一步了。

05

当前策略的一步就改变了教师能教的内容

一个小扩展放松了录制轨迹带来的限制：从历史 trace 出发，用当前模型生成一步。学生学会收尾之后，新生成的这一步就让教师有机会去鼓励真正的提交工具 token。这样，学习过程看到的是正在训练的策略自己做出的决策，而不只是旧数据里留下来的决策。

Denton 报告，加上这一步扩展后，SWE-bench 综合通过率的提升比完全离线学习更大，但没有给出具体数字。这个实验用的仍是离线提示。它加入了当前策略生成的一步，却没有完整采用前面分类里的第三种组合——那种组合要根据这一步动态构造提示。trace 新不新、提示从哪来，仍是两个独立的选择。

06

从实时 rollout 中纠正超链接格式

完全在线的例子来自一位客户的编码智能体框架。这个框架要求一种特定的超链接格式，和后训练模型平常的输出分布相去甚远。智能体要学会这个约定，同时保住原有的编码能力。

最初的两种做法都出了问题：一是给正确的超链接格式加奖励，二是用链接格式正确的 trace 做监督微调。Denton 报告，两种做法都拉低了编码智能体的整体表现。团队于是改用在线 trace 加在线提示。

每次 rollout 结束后，提示会指出这次 rollout 是怎么写超链接的，并说明下次该用什么格式。提示的信息针对模型的实际输出，而不是泛泛地重申规则。Denton 报告，用了在线提示后，超链接格式的正确率从约 15% 升到了 80%。

对照组在所有 rollout 上用同一条静态提醒：只要输出超链接，就用规定格式。这条离线提示也改善了格式，但幅度远不如针对每次 rollout 的纠正。保住基础编码能力是实验的硬性要求，不过演讲没有量化蒸馏后编码能力保留了多少。演讲展示的对比是：提示针对当前策略的实际行为时，格式提升明显更大。

07

把提示放在需要改变的那个决策点上

提示的内容只是方法的一部分。提示放在哪里，决定了教师的额外信息能影响哪个决策。 Applied Compute 不把每条提示都放在开头，而是用一个评判模型在 rollout 中挑出该注入提示的位置。随后的蒸馏集中在紧接着的一步或几步上，而不是整个 rollout。

这样，更新就紧贴教师真正有东西可教的那个时刻。Denton 画出的 KL 学习信号显示，离提示越远，信号越弱。落到实践上就是局部训练：找出需要纠正的决策，在那里给提示，把学习集中在提示作用最强的邻近几步。

08

学习相关的 token，而不是教师的每一个偏好

相关性掩码自蒸馏 把学习范围进一步收窄，从选定的步骤缩小到选定的 token。按 Denton 的描述，LLM 评判模型会挑出学生该向教师学哪些 token。比如，教师可能偏爱某些连接词，而这些偏好跟要教的行为毫无关系。照搬这些差异，只会往更新里掺进无关的改动。

只挑相关 token，是为了保留纠正信号，同时剔除教师那些附带的偏好。Denton 报告，用这种方法，模型能更好地学会严重偏离分布的行为，也更不容易出现灾难性退化。两种局部化技术管的范围不同：逐步提示决定在哪个时刻教，相关性掩码决定学习信号里哪些 token 级差异才算数。

这给企业留下了一条务实的演进路线。历史 trace 加静态提示，是教会某个已知行为的切入点。在线 trace 加动态提示，让循环能随着模型变化，及时响应新出现的行为。Denton 设想的更高上限，靠的是这个自适应的评判模型：它不必反复纠正一张固定的错误清单，而是能根据当前模型在生产中的实际表现做出响应，带动多个方面一起进步。
