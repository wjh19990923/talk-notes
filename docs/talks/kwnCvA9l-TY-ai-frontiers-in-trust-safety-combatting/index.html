信任与安全的 AI 前沿：在 Tinder 的规模上对抗多方面的伤害

Tinder 的做法结合了精心标注的平台数据、小型的针对任务的适配器，以及共享模型推理，在实时约束下检测多种类型的伤害。

熟悉分类、微调以及精确率与召回率会有帮助；文中会解释适配器如何改变训练和推理服务。

01

在广泛的范围内检测危害

违规行为在发生频率和严重程度上差别巨大，这样的检测系统该怎么搭？在 Tinder，这个问题属于更大范围的信任与安全工作。Vibhor Kumar 在 Tinder 做了五年信任与安全系统。他借用 Twitter 前信任与安全负责人 Del Harvey 提出的四个目标来概括这项工作：预防风险、降低风险、检测危害、减轻危害。这些目标既保护用户，也保护运营平台的公司，但落实起来仍然离不开伦理判断。本文的工程重点是检测危害。

要检测的行为五花八门。在个人资料里推广社交媒体账号，算是相对轻微但很常见的违规，触犯的是 Tinder 的隐私信息政策。这类违规多出自并不真想在交友平台上认真参与的用户。另一端则是发生率低、危害大的行为，比如仇恨言论、骚扰和“杀猪盘”诈骗。好用的检测器组合必须覆盖这整条光谱：光看频率，判断不了哪些类别值得重视。

02

廉价的生成改变了防御者可用的信号

生成式 AI 首先改变的，是平台要处理的内容量和内容种类。虚假信息、政治宣传和低质量垃圾内容可以廉价批量生产，把真实内容淹没。Kumar 称之为“内容污染”。他还提到，托管生成内容的平台日后可能面临版权风险。深度伪造工具越来越容易获取，冒充身份和 catfishing（用假身份网恋行骗）的门槛随之降低，制作未经同意的色情图像等恶意用途也更容易实现。

有组织的诈骗带来了更具体的检测难题。攻击者能为每个账号生成全新的资料文本和图片，哈希和相似度匹配就没那么可靠了。一场诈骗行动不再需要反复使用某段显眼的内容。于是检测重心转向基础设施和物理瓶颈相关的信号：IP 地址、ISP 信息和手机号。生成内容可以低成本地变来变去，账号背后的基础设施却仍可能暴露出限制。LLM 还能自动撰写这些账号发出的消息，自动化从注册账号一路延伸到了互动本身。

03

从语义能力出发，再做专门化

同一套模型生态，也让防守方有了更高的起点。预训练开源模型本身就具备大量语义知识，往往还支持多种语言。用少样本提示词驱动 Llama 3 或 Mistral，就能先搭出一个违规检测器，不必从头训练语言模型。Kumar 称，在一些下游文本检测任务上，微调后的开源模型可以胜过少样本的 GPT-4，不过他没有给出这项对比在具体任务上的评测细节。

如今成熟的库覆盖了从模型开发到线上部署的全流程，团队要自己搭的底层训练设施少了很多。Kumar 称，借助这些工具微调预训练模型，能把模型开发周期从几个月缩短到几周。目标行为不断变化时，这一点尤其有用。

在对抗性检测里，一条规则生效后，环境也会跟着变：拦下一波垃圾信息，攻击者就有动力改变手法，直到再次绕过去。Kumar 认为，LLM 能泛化到训练时没见过的模式，所以模型退化得更慢。攻防循环不会因此结束，但检测器在两次更新之间能撑得更久。

04

让训练契约小而明确

落地的第一大步是构建训练数据集，Kumar 认为这是最难的环节之一。对某些微调任务来说，几百到几千条样本就够了。这并非放之四海皆准的样本量要求，但它意味着每条样本的质量都格外要紧。

设计数据集时，可以把生成式模型——无论是 GPT-4、Claude Opus，还是开源的 Llama、Mistral——看成一个“文本进、文本出”的函数。输入是包在提示词里、可能违规的文本；目标输出要么是分类标签，要么是作为违规证据需要抽取出来的字符。产品只要分类结果时，模型不必写解释。

Kumar 用一段合成的个人简介来说明这种输入输出约定，简介里透露了用户未成年。下面是同一任务的一条示例记录，把提交的文本和监督训练的目标清楚地分开了：

``json { "input": "Does this bio explicitly state that the user is younger than 18? Return YES or NO.\nBio: I am 17 and enjoy hiking.", "output": "YES" } ``

这里，提示词限定了一个很窄的判断，output 里放的是训练标签。如果是抽取任务，这个字段里放的就是相关字符。两者遵循同一套基本的“文本到文本”训练约定。

05

挖掘真实的平台样本，再核实标签

数据集规模不大，手工整理完全可行。也可以借助更大的 LLM，但输入从哪里来很关键：

| 方法 | 主要优点 | 主要局限 | | --- | --- | --- | | 人工整理 | 直接由人判断 | 人工标注工作量大 | | 少样本合成生成 | 容易产出候选样本 | 可能偏离平台的真实分布 | | 用 LLM 标注平台数据 | 从平台真实内容出发 | 预测结果仍需核验 |

纯合成样本哪怕看着像模像样，也可能跟具体平台毫无关系。Tinder 发现混合做法更管用：让 GPT-4 对内部分析数据做预测，再从预测结果里挖掘训练样本。Kumar 提到要靠提示词应对模型出于对齐考虑的拒答，但没有给出具体写法。

成本高低取决于发生率。要凑够固定数量的有害样本，违规越罕见，要筛的内容就越多；Kumar 说在 Tinder 的实际使用中，这笔成本可以忽略不计。估算发生率对信任与安全运营本身也有价值，不只服务于眼下的数据集构建。还可以先用启发式规则挑出更可能违规的候选，再交给大模型，减少模型调用次数。

最后一步是人工核验。大模型挖出候选样本后，审核人员纠正标错的记录，并在标签模棱两可时做政策判断。大模型负责找素材、打初步标签；训练目标最终仍由运营和政策专家敲定。

06

为什么生产检测器使用自有的权重

既然 GPT-4 能帮忙标数据，为什么不直接让它做每一个线上判断？Tinder 的资料互动量很大，又要求实时，Kumar 认为成本、延迟和吞吐量是瓶颈。托管的大模型在构建数据集时很有用，但不一定适合为每次互动提供推理服务。

模型掌控在谁手里，也影响后续维护。权重握在自己手里，检测质量下降时，团队可以在基础模型不变的前提下重新微调。做分类时，拿得到输出的概率分布，还能据此算出预测置信度。这是一个有用的决策信号，不过光有概率，并不能说明分数已经校准过。

07

训练适配器，而不是为每个任务训练一个完整模型

训练生态提供了几种不同程度的控制：

- 代码和 notebook： Hugging Face 的库只需相对少量代码就能搭起训练流水线；Kumar 称他们在 notebook 里搭这些流水线很顺利。 - 配置驱动的训练： Axolotl、Ludwig 和 LLaMA-Factory 把大部分设置挪进了配置文件。 - 用于实验的界面： H2O LLM Studio 提供带无代码 GUI 的框架，Predibase 则提供托管工具。Kumar 特别看重 UI 和数据集管理功能，并称用 Predibase 效果尤其好。

这些工具省掉了搭实验的繁琐步骤，工程工作的重心就落在数据集质量和任务定义上。

再往下一步大幅省资源的是参数高效微调。LoRA（低秩适配）冻结基础模型的权重，只学习一小组额外的适配器权重。Kumar 描述的流程里，适配器只有几 MB，不必为每个模型单独存一整份权重。只训练这一小部分，就能在一张或几张 GPU 上快速做实验，更大的基础模型也随之用得起了。

Kumar 称，对更大的基础模型做参数高效适配，效果往往好过对小模型做全量微调，分类任务上尤其如此。他们用 QLoRA 也取得了不错的效果：QLoRA 把量化和适配器训练结合起来，进一步降低显存需求。能不能在单卡上跑，取决于模型大小、硬件和训练配置，并不保证任何模型都塞得下。适配器结构的好处还不止训练效率：推理时，许多专用检测器可以共用一个基础模型。

08

通过一个共享基座服务一组检测器

Tinder 在生产环境中用 LoRAX 部署这些适配器。这套架构让多个专用微调共享昂贵的基础模型，再通过切换适配器、批处理请求，高效地联合执行。Kumar 称 LoRAX 能在单张 GPU 上承载数千个微调适配器。这说的是能承载多少适配器，不是能同时处理无限多的请求。

共享基础模型后，新增一个类别的成本就不一样了。Kumar 说，在同一基础模型上再加一个适配器，边际成本几乎为零。实际意义在于：仇恨言论、推广、catfishing 和杀猪盘检测可以各用各的适配器，不必各自部署一套完整模型。请求量照样消耗算力，但多一个检测器，不一定意味着多一个专用 GPU 服务。

部署操作也相应地很轻：

1. 把训练好的适配器权重存到推理系统能访问的文件系统上。 2. 修改 LoRAX 客户端请求，指定使用该适配器。

这样，检测器就成了共享基础模型上的又一个专用分支。Kumar 提到，LoRAX 由 Predibase 开发和维护，Predibase 也为 Tinder 的部署提供了支持。

09

限制昂贵的推理，并保持输出简短

Kumar 称，在 A10 GPU 上跑 70 亿参数的模型，能做到每秒几十次查询、延迟约 100 毫秒。这是 Tinder 自己报告的运行结果，不是通用基准：输入长度、批处理方式、GPU 数量和延迟百分位都没有说明。这个水平够一些实时场景用，频率更高的场景还需要额外过滤请求。

其中一种过滤方式刻意做得很简单。检测社交媒体推广时，系统可以只对含有词典外单词的简介做预测。这条启发式规则只负责为模型挑候选，不能据此认定违规。它的作用是减少送到昂贵检测器的请求数。

Tinder 还在借助蒸馏探索分类级联。先在较小的基础模型上训练一个高召回率的适配器，只有小模型的分数超过阈值，才调用大基础模型上的适配器。第一阶段先大范围筛一遍，再决定要不要动用大模型的算力。这仍属探索性工作，和已上线的 LoRAX 推理系统是两回事。

最后，输出约定本身也能减少推理开销。自回归生成一次只产出一个 token，长篇解释就意味着要多跑很多步解码。分类或抽取任务可能只需要一个或几个输出 token。只返回简短的标签或一小段抽取文本，预测中的生成部分就能压到很小。

10

语义理解对准确性和规避检测都有帮助

Kumar 称，与早期 NLP 模型相比，精确率和召回率都大幅提升，他把这归功于现代 LLM 的语义能力。在识别社交账号这类较简单的任务上，召回率接近 100%。演讲没有交代评测集，也没说对应的精确率工作点；对语义更复杂的任务，他只说有提升，没给具体数字。

真正的考验不只是熟悉样本上的表现。想逃避检测的用户会故意打错字、字母数字混写、话里有话。这些手法能骗过紧盯特定字符串的检测器，背后的意思却依然看得出来。Kumar 称，基于 LLM 的适配器更能读懂这类变体，因此比传统机器学习检测器过时得慢。这种韧性很关键：用户摸清系统能抓什么之后，系统还得继续管用。

11

把流程扩展到多种模态和长尾

下一个探索方向是非文本内容。Kumar 提到，LLaVA 这类预训练视觉-语言模型，有望成为露骨图像检测的基础。这项工作还在研究阶段，并不代表 Tinder 已经上线了这项审核能力。

更大的目标，是让构建新的危害检测器成为一件常规的事。信任与安全运营和政策专家在 AI 辅助下打造高质量数据集；自动化流水线负责训练和重训适配器；LoRAX 让每个新适配器都能低成本地加入推理。已上线的文本推理架构打好了基础，更全面的自动化和长尾覆盖则是接下来的路线图。照这个思路搭起来的防线，能不断纳入新类别、跟上行为变化，最终目标是一个更安全、更健康的平台。
