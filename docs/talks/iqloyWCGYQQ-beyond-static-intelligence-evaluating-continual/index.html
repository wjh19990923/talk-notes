超越静态智能：评估持续学习

一个模型可能得分很高，却没有从经验中学习。Continual Learning Bench 把初始能力与改进幅度区分开来，然后检验这种改进能否在变化的环境中保持下来。

对语言模型、模型训练和 SQL 查询有基本了解会有帮助；文中会介绍评测指标。

01

如果每个任务都会抹掉你的记忆会怎样？

让语言模型解决一个任务，丢掉它的经验，再让它解决下一个。在一个个基准上重复这个过程，汇总各自独立的分数，排出一张排行榜。这种常见的评测方式，衡量的是模型从零开始能做到什么。可模型学到了多少，又在哪里衡量？UC Berkeley 博士生 Parth Asawa 一开场就抛出了这个问题。

每做完一个任务就重置系统，就像每做一件事都要把人生从头来过：以前学到的东西，对接下来的事毫无帮助。评测学习能力，应该把表现画成先前经验的函数。真正值得关注的信号不只是高分。系统见过前面的实例，后面的实例就做得一次比一次好，这才是关键。

02

高效学习而不遗忘

Asawa 把持续学习定义为样本高效、在长时程上保持稳定的在线学习。每一部分都不可或缺。系统必须从有限的新经验中学习，边运行边更新，并长期保留有用的信息。光会记住还不够：新证据出现时，系统还得修正自己的先验。

按这里描述的常规训练与部署模式，数据进入离线训练流程，产出一个冻结的 checkpoint。这个 checkpoint 部署之后，权重不再改变。其实，语言模型系统有好几处可以把学到的东西延续下去：

| 机制 | 随经验改变的是什么？ | |---|---| | 上下文学习 | 模型上下文里的信息 | | 外部记忆 | 笔记、键值记录或其他记忆存储 | | 参数化学习 | 通过在线更新改变的模型权重 |

这几种机制保存经验的方式各不相同，但评测应该能把它们都测到。眼下的目标不是宣布哪一种解决了持续学习，而是先把这个领域想提升的能力测出来。

03

保留和回忆留下了缺口

持续学习在神经网络领域由来已久，尤其是关于灾难性遗忘的研究。常见的实验是让模型先在任务分布 A 上训练，然后是 B，再然后是 C，看它能否学会每个新分布，同时不丢掉在旧分布上的表现。语言模型研究沿用了类似的顺序评测，另外还会测试模型能否从超长对话里回忆起事实。

这些测试覆盖了重要的能力，但 Asawa 指出了三处空白。第一，样本效率未必被当成首要要求。第二，记住一个事实，不一定说明模型学到了能提升后续表现的东西。第三，大规模预训练让人很难为前沿模型构造真正全新的任务：互联网上的大部分内容、许多有经济价值的活动，早已出现在它们的训练分布里。一个有用的基准，必须给在线经验留出发挥作用的空间。

04

一个序列需要有值得学习的东西

为什么不直接把现有基准的题目串起来？Asawa 拿一串 AIME 题目当反例。把各自独立设计的题目排个先后，并不能保证做出前一道就能帮上后一道。这类评测必须有序列，但光有序列，并不会凭空造出学习的机会。

要让“从经验中进步”有意义，设计上需要满足三个条件：

- 提升空间： 任务必须要求在线适应。如果多做些离线训练，模型就不必在评测中学习，这个任务就不适合用来测持续学习。 - 共享结构： 各个实例所处的环境必须有共同的潜在结构。前面的经验应该能揭示一些东西，让系统在后面的任务里加以利用。 - 学习信号： 环境必须提供让系统改进的依据，比如标量奖励、报错信息或文字反馈。

三者合在一起，既给了系统学习的理由，也给了它切实的学习机会。

05

把起点实力与学习收益分开

每个任务都为单个实例定义奖励，数值越高，表现越好。视领域不同，奖励可以反映效率、利润，或预测与正确答案的接近程度。把这些奖励加总有用，但累计奖励可能把学习能力和模型的初始实力混为一谈。

演讲用红、黑两个系统来说明这一点，另有一条灰色基线，代表黑色系统在每个实例之间都重置状态。允许保留经验时，黑色系统会进步。但红色系统起点更强，单凭这一点就可能累积更多奖励。假设它仍有提升空间，那么它的高分并不能说明它从之前的任务中获益。

要把这部分收益单独拎出来，可以把每个系统评测两遍：

1. 有状态运行。 在实例之间保留经验，形式可以是更新后的策略、笔记，也可以是不断变长的上下文。 2. 跑一个无状态基线。 每个实例之间都重置系统，让之前的经验无法延续。 3. 把成对的奖励相减。 差值衡量的就是在这个实例上保留经验带来的收益。

``math \begin{aligned} g_t &= r_t^{\text{stateful}} - r_t^{\text{stateless}} \end{aligned} ``

这里的 t 表示实例编号。第五个任务上的增益，问的是前四个任务的经验让第五个任务的表现提升了多少。这是演讲中使用的原始增益定义；已发表的基准还报告了归一化增益，即按无状态基线之上剩余的提升空间，对这个差值做缩放。

增益不能取代奖励。一个学得很多的系统，表现仍可能不如起点更强的模型；两个系统中任何一个，运行成本都可能更高。所以 Asawa 把奖励、增益和成本放在一起做帕累托比较：看清其中的取舍，而不是把初始能力、进步幅度和开销压进一个号称足够的单一指标。

06

学会一个数据库，再扛过它的迁移

数据库探索能把这种学习机会讲得很具体。数据工程师面对一个陌生的数据库，得摸清 schema、表之间的关系、数据格式，还有各种本地特有的怪癖。人会把这些发现带进后续工作。而记忆被反复清空的智能体，每次都得重新付出探索的代价。

在这个任务里，智能体收到一个自然语言问题，通过 SQL 查询来回答。早期的问题需要先探索，智能体才能给出答案。举个例子，问题是“每位客户的订单总金额是多少？”，智能体可能要先看看两张表，再写 join：

```sql SELECT * FROM customers LIMIT 5; SELECT * FROM orders LIMIT 5;

SELECT c.customer_id, SUM(o.amount) AS total_amount FROM customers AS c JOIN orders AS o ON o.customer_id = c.customer_id GROUP BY c.customer_id; ```

表名和列名只是让例子更具体；真正要学的是 schema 及其中的关系。如果这些知识能保留下来，后面的问题就可能少做几次探索性查询。Asawa 拿第十个实例做对比，是为了说明预期中的效率提升，并不是报告实测的查询次数。

现在来一次数据库迁移。有些列消失了，出现了名字不同的新列，数据格式也变了。以前帮你省事的经验，现在可能让查询失败。智能体必须识别出哪些假设已经过时，把它们丢掉，同时留住仍然适用的知识。

这就是落到实际任务里的稳定性–可塑性权衡。稳定性保住有用的经验；可塑性让新证据能够改变系统的认知。如果系统继续相信过时的信息，单纯堆更多记忆解决不了问题。基准的各个任务里都设置了概念漂移，正是为了测试这种有选择的更新，而不只是固定环境下的记忆保留。

Continual Learning Bench 把这套设计用在了六个领域：

| 任务 | 领域或目标 | |---|---| | 盲频谱监测 | 信号处理 | | 代码库适应 | 软件工程效率 | | 队列研究 | 流行病学 | | 可剥削扑克 | 策略博弈 | | 数据库探索 | 高效的数据库查询 | | 销售预测 | 预测误差 |

每个领域提供一串定义好奖励的实例。领域专家会逐项评估：任务是否可学、是否真实；其中的变化像不像合理的概念漂移；希望智能体记住的信息，在该环境里是否真的重要。

首个版本比较的是上下文管理系统，参数化方法计划之后再评测。Asawa 报告说，在初步评测中，最朴素的上下文学习总奖励排名第一，在奖励–成本和增益–成本两条帕累托前沿上也一直占优。这个基线只是把先前的经验直接放进上下文，不做其他系统那种更复杂的记忆管理。

解读这个结果，得考虑时程长短。这些都是中等时程的任务，可能还没把上下文学习逼到暴露极限的地步。Asawa 并没有把它当成持续学习的最终答案。眼下的意外在于：更昂贵的上下文管理系统，在这些测试任务上反而表现更差。把序列拉长已经列入路线图。

08

忘记反馈，再拒绝有用的证据

实际观察到的失败案例，能说明为什么光保存状态还不够。Asawa 按稳定性–可塑性权衡的两侧给它们归类：一侧是保留并复用信息，另一侧是从新信息中学习。系统可能因为丢掉一条有用的约束而失败，也可能因为拒绝修正已有认知而失败。

销售预测的例子展示了稳定性上的失败。智能体要预测大约五年的销售额。它把某次提交得到的反馈理解为预测偏高，于是把预测往下调。接着，它又把后续反馈理解为调低过头了。它没有把两次观察结合起来、取一个居中的预测，而是退回了之前偏高的预测。第一次尝试得到的有用约束，实际上已经丢了。这里的反馈是一个综合分数，要靠智能体自己解读，不一定会明确告诉它该往哪个方向调。

队列研究的例子则败在可塑性上。这个系统有外部记事本，却用一句话打发掉了相关信息：“这些似乎是另一套研究 schema 下的队列定义，不适用于这里。”Asawa 明确表示，那套研究 schema 其实是适用的。问题不只是没有存储：系统没能认出适用的证据，也就没能用它来更新先验。

09

在部署之前构建一个持续学习者

这些评测结果并不能断定哪种机制最终效果最好。Asawa 自己的研究偏好是参数化方法，把架构、数据和学习算法放在一起考虑。换句话说，要从一开始就为持续学习而设计，而不是默认现成的 checkpoint 就是正确的起点。

训练栈已经变了很多。早先一个简化的说法是：预训练、监督微调，再加上基于人类反馈的强化学习。更复杂的训练栈还会加入中期训练、针对不同教师模型的强化学习，以及多教师 on-policy 蒸馏。而很多持续学习的研究，要等这一切都做完才开始：拿到最终的冻结模型，再想办法让它适应。

但这些模型在设计时，未必打算成为持续学习者。Asawa 质疑：坚持从这个起点出发，是不是一种沉没成本心态。如果持续学习是首要要求，整条流水线或许可以改成：先用一个阶段专门训练持续学习者，再部署上线，部署后与环境交互和更新权重同步进行。这是关于另一种训练设计的研究假设，并没有被证明能替代如今的训练栈。

10

更长的时间跨度和更广的研究议程

这种敢于质疑训练流水线的态度，也延伸到了 AI 研究的组织方式上。Asawa 把这项工作放进他所在团队更大的目标里：挑战既有做法，涉及开放科学、权力集中、安全、学术界和独立研究机构等问题。他提到了自己写的文章，邀请更多人一起重新构想第三方机构和开放研究可以变成什么样。

Continual Learning Bench 由 Berkeley、Snorkel 和 UW–Madison 合作完成，得到了 Snorkel AI 的 Open Benchmarks Grants 项目和 Laude Institute 的 Laude Slingshots 项目支持。接下来，评测本身和受测方法都会继续扩展：

- 更广、更长的任务： 增加更多特定领域的环境，以及更长的经验序列。 - 更多学习系统： 评测更多开源模型和参数化方法。 - 更丰富的模拟： 开发易于验证的确定性领域之外的环境。

有些场景的成败没法简化成直接的确定性检查，要在这类场景里测试适应能力，模拟环境尤其重要。

用户个性化就是这样一个未来场景：系统应该在交互中学会某个人的需求。Asawa 怀疑当前模型能否把用户模拟得足够好，来支撑这种评测，但他认为打造这种能力是值得追求的目标。这个基准的目的始终很明确：持续学习不是一个单点能力。只有测出经验如何改变表现，这个领域才能朝着真正会学习的系统去优化。
