为所有人打造 AI：代码补全的小模型经济学

要让 AI 辅助成为默认功能，需要的不只是一个能力强大的模型：Replit 的做法把精选的训练数据、紧凑的架构、快速的推理和响应迅速的部署联系在一起。

对代码编辑器、模型训练和推理有基本了解会有帮助；文中会在出现时讲解评测和补全的格式。

01

让每个人都能用上更好的编程工具

怎样让每个人都能走最快的路，把一个想法变成部署上线、可扩展的软件？在 Replit 联合创始人 Amjad Masad 看来，这个问题要从写软件用的界面说起。他的开场幻灯片是一台打孔卡机器。现代编程工具出现之前，写程序就得靠这类体力活。ENIAC 这段历史需要分清一点：ENIAC 最初靠接线和开关编程，后来才改造成存储指令的方式，1948 年投入运行。它起初并不是一台单靠打孔卡编程的冯·诺依曼机。但大的出发点没变：在好用的编程语言和编辑器出现之前，把指令表达出来本身就很难。

汇编、编译器，再到 C 这样的高级语言，把越来越多的工作挪进了文本。JavaScript 则成了 Masad 的笑点：它一问世，一切就开始走下坡路。他估计，文本编程比早先的方式提升了 10 到 100 倍。这是他用来讲历史的框架，为的是引出生产力可能迎来的又一次飞跃，并不是演讲里给出的实测对比。

软件越做越大，IDE 把更多辅助功能带进了编辑过程。Masad 回忆，大约在 2017–2018 年，Replit 在旗下所有编程环境里加上了 Language Server Protocol（LSP）支持，让每个账号都能用上 IntelliSense。代价是一笔基础设施账单：语言分析吃 CPU，一个 TypeScript 服务器还可能占掉大量内存。Replit 认下了这笔开销，就是为了让更多人用上专业的编程工具。

02

从 Ghostwriter 到默认的 AI 辅助

早期用 GPT-2 做的实验表明，模型可以接过一段代码往下写。Replit 把这个可能性做成了 Ghostwriter，在 IDE 里集成了自动补全、聊天等辅助功能。编程助手普及之后，先受益的是那些本来就会用它的工程师。Masad 估计，到演讲时，一些工程师的效率提升了 50%、80%，也许 100%。他明确说，这还不到一个数量级；至于未来十年会提升 10 倍、100 倍，甚至 1,000 倍，那是他的预期，不是已经观察到的结果。

Replit 的使命是赋能下一个十亿开发者。对这样一家公司来说，助手要另外付费，就会把很多人挡在门外。所以他们提出的改变是一项产品默认设置：AI 应该出现在每一次编程交互里，而不是又一个有名有姓、等着用户自己去发现的附加功能。Masad 宣布了 AI for All，把基础 AI 辅助开放给 Replit 的数百万用户。这次开放的只是基础功能；高级功能仍然分开提供，新的 V1.5 模型也会逐步推出。

Masad 说，这次推出可能是全球规模最大的 AI 辅助编程部署，接着又打趣说，Replit 烧掉的 GPU 会和 CPU 一样多。覆盖面是实打实的：在 Android 手机上写代码的人也包括在内。当年 LSP 让编辑器智能成了一项大家共担的基础设施开支；如今 AI 默认开启，模型服务也就成了提供编程环境的成本之一。

03

把推理放进应用内部

编程助手改变的是开发者怎么写软件；应用里的一次模型调用，改变的是软件能做什么。Model Farm 解决的是第二层：直接在 Replit IDE 里提供模型。Masad 介绍说，三行代码就能开始推理。首发支持 Google Cloud 的 LLM，Llama 和 Stable Diffusion 也已宣布在计划之中。他还邀请其他模型提供商加入。

屏幕上的示例一边是编辑器里的代码，一边是控制台里生成的、关于学习 AI 的输出。Masad 承诺，至少到 2023 年底（也就是发布当年），所有人都能免费使用。这是录像里 Model Farm 当时的优惠，不代表现在的 API 可用性或定价。默认辅助加上易用的推理，既覆盖了写软件的技术栈，也覆盖了应用自身的调用栈。

04

一个有交互式延迟预算的小模型

接下来，Replit 的 AI 负责人 Michele Catasta 接过话筒，讲这次推出背后的工程问题：在有限的 GPU 集群上训练一个相对小的模型，值不值得？他提到，SemiAnalysis 最近一项研究对这条路颇为不屑。可 Replit 从 5 月开始自己训练模型，经验告诉他们的恰恰相反。Replit 定制的补全模型从 GitHub 上的开源代码和 Replit 用户写的代码中学习，产品上则要求响应要快。

Catasta 给出的目标是：代码补全的 P95 延迟低于 250 毫秒。快到这个程度，辅助就能融进开发者打字的节奏，而不是变成一次单独的交互。他说，过去几个月里，Replit 之前的几个模型在同尺寸模型中都是最先进的。5 月发布的 Replit Code V1 3B 带来了不少使用者和社区贡献；正是这些反响，加上 Replit 自身对开源的依赖，促成了 Replit Code V1.5 3B 的发布。

05

在训练时多花一些，以服务一个更小的模型

V1 沿用了 Llama 式的训练方法。到了 V1.5，Catasta 说训练量大约是每个参数 300 个 token。他把这个选择和 DeepMind 的 Chinchilla 论文 Training Compute-Optimal Large Language Models 联系起来。这篇论文讲的是，训练算力预算固定时，该怎样在模型规模和训练数据之间分配。落到部署上还能再推一步：多花算力训练一个更小的模型，可能换来一个够用的模型，反复运行时更便宜也更快。训练成本可以摊到推理上。

Catasta 介绍，V1.5 用的高质量数据是 V1 的两倍，总共训练了约一万亿 token：语料约 2000 亿 token，跑 5 个 epoch，最后做一段线性 cooldown。一个 epoch 就是把语料完整过一遍，所以模型重复见过的数据和不重复的数据要分开算。数据混合覆盖 30 种编程语言，还加入了面向开发者的 Stack Exchange 帖子，包括编程和软件工程方面的问题。

06

整理语料库，再复用它

代码语料以 The Stack 为起点，这是 BigCode 从 GitHub 仓库整理出的数据集。Catasta 介绍了一条流水线：挑选仓库、清洗内容，只保留宽松许可证下的代码，比如 MIT、BSD 和 Apache 2.0。Replit 从中选出 30 种主流语言，又在过滤上下了更多功夫。这一步格外关键，因为发布的模型是从零训练的：它学到的一切，都从 Replit 喂进去的第一个 token 开始，而不是建立在某个现成的预训练模型之上。

Replit 借鉴 Codex 和 PaLM 的质量流水线，加了一些启发式规则，剔除几类不想要的训练材料：

- 自动生成的代码：不像开发者平时会写的代码。 - 压缩过的代码（minified）：源码经过压缩，拿来学习可读的编辑器建议并不合适。 - 无法解析的代码：通不过相应语法检查的源码。 - 有害内容：被内容过滤排除的材料。

这条流水线跑在 Spark 上。Catasta 给大家的实用建议是：准备数据、训练模型、提供服务，所需的基础设施如今大多都有现成的开源组件。换在 2022 年，要搭起同样一套系统难得多。

精选语料带来了新的约束：如果模型需要的训练量，超出了现有高质量数据能提供的量，怎么办？V1 发布后不久问世的 Scaling Data-Constrained Language Models 印证了 Replit 当时已经在用的直觉：与其掺进更差的数据来扩充，不如把好的那部分重复训练。Catasta 概括说，图表显示重复四五次后 loss 相差不大；论文本身的结论是，在固定算力、数据受限的实验里，四个 epoch 以内的 loss 差异可以忽略，再往后收益递减。

所以，重复一举两得：Replit 可以多投训练算力而不放松质量过滤，也不必为了扩充语料去碰宽松许可证以外的代码。Catasta 宣布 V1.5 开源发布，许可证允许商用。数据怎么选和模型怎么发是连在一起的：团队希望其他开发者能在这个模型上继续构建。

07

在紧凑的架构中装进更多代码

名字里写的是 3B，但 Catasta 说 V1.5 实际有 33 亿参数。上下文从 V1 的 2K token 扩到 4K，还换用了一套新训练的代码专用 32K 词表。词表设计决定了固定的 token 预算里能装下多少源码：常见代码片段占的 token 越少，模型在同样的上下文和训练序列里就能看到越多代码。Catasta 说，压缩率因此又提高了几个百分点，这套词表压缩代码也比 StarCoder 和 Code Llama 的词表更好；不过他没有给出分词器对比的测量细节。

Catasta 介绍，训练在 MosaicML 上进行，用了 128 张 80 GB 显存的 H100，跑了一周。据团队所知，这是第一个官宣在 H100 上训练并开源发布的模型。架构上还用了 FlashAttention、grouped-query attention（分组查询注意力）和 ALiBi 位置编码，外加几种他没有点名的新优化器。这些选择都指向同一个目标：保住实用的编程能力，同时让推理快到能在编辑器里用。

08

通过运行生成的程序来评估它们

HumanEval Pass@1 测的是生成的解法能不能通过题目的测试。Catasta 介绍了基本流程：

1. 给模型一段编程任务的英文描述。 2. 让它生成一个自包含的 Python 解法。 3. 在测试框架里运行这个解法。 4. 检查输出是否和预期结果一致。

关键在于，输出要当作程序真正跑一遍，而不只是看文字像不像那么回事。BigCode 的多语言评测框架把这套方法扩展到了 Python 以外，它的排行榜会给不同机构的模型统一跑评测。Catasta 预计 Replit 几天内就会上榜。

Catasta 说，V1.5 基础模型在表中全部六种语言上都超过了 StarCoder 3B，并接近 Code Llama 7B。这六种语言是 Python、Java、JavaScript、C++、Rust 和 PHP。更有分量的是和大模型的对比：Code Llama 7B 以 Llama 2 为底座，Llama 2 先在两万亿 token 的自然语言上训练，之后又追加了 5000 亿 token 的代码。按这里给出的账，Code Llama 7B 的参数量约是 Replit 基础模型的两倍，训练见过的 token 是它的 2.5 倍，GPU 算力也多得多。这组对比要检验的是：一个小代码模型练得足够充分，能不能逼近大模型的任务表现。

09

让模型适应用户实际写的代码

下一个模型是 repl-tuned 版本，它在公开的 Replit 项目上继续预训练。Catasta 解释，当时公开的 repl 会自动以 MIT 许可证发布，所以这部分代码可以用来训练。团队复用了原有的过滤流水线，从中挑出质量更高的代码。他说额外训练了 2000 亿 token，但又提到过滤后的语料有 300 亿 token、跑 3 个 epoch 加线性 cooldown；这几个数字凑不出一份前后一致的训练安排。

数据混合向 Replit 用户偏爱的语言倾斜。Catasta 估计，95% 的用户主要写 Python 和 JavaScript。除了语言，时效也很重要：这次训练数据的截止时间离演讲只有几周，他说这能帮模型给最近流行的库写代码。团队打算持续更新模型，让补全跟上开发者真正在用的生态。

在接下来的对比里，基础模型仍在左边，Code Llama 在中间，右边新加了 repl-tuned 模型。StarCoder 没有再列，因为上一张表里基础模型已经超过了它。Catasta 说，repl-tuned 模型在几乎所有列出的语言上都明显胜过 Code Llama，HumanEval Pass@1 达到 36%。

这个成绩让人想起 Catasta 早年参与的 PaLM-Coder。PaLM 论文报告，在贪心解码下，PaLM-Coder 和 Davinci Codex（即 code-davinci-001）的零样本 HumanEval Pass@1 都是 36.0%。PaLM-Coder 有 5400 亿参数（是参数，不是 token），约为 33 亿参数的 Replit 模型的 164 倍；Catasta 说“将近 200 倍”，是比较粗的取整。追平这个历史成绩，说明小得多的模型也能达到当年的水平；但演讲并没有证明 Replit 用了同样的解码设置，也没有证明两者的通用编程能力相当。

10

同时优化生成和容量启动

产品目标是推理性能，排行榜名次本身不是目的。在 Catasta 看来，基准分数和定性检查的用处，是确认这个小模型依然能打。他说，单个模型在不做 batching 的情况下，每秒能生成 200 多个 token。演讲没有说明推理用的硬件、精度、序列长度和测量口径，所以不能把训练集群的 H100 配置当成这个结果的测试条件。

提速工作同时落在模型和运行时两头：

| 层级 | 选择 | 目的 | |---|---|---| | 词表 | 更小的代码专用词表 | 更高效地表示和生成代码 | | 注意力实现 | FlashAttention 配 Triton kernel | 加速注意力计算 | | 注意力架构 | Grouped-query attention | 提升推理效率 | | 服务栈 | Triton Inference Server 和 TensorRT-LLM | 优化在 NVIDIA GPU 上的执行 |

Triton kernel 和 Triton Inference Server 不在同一层：前者负责实现计算，后者负责处理推理请求。Catasta 把这些选择看作一套相互配合的工作，目的就是从模型里再榨出一些速度。

生成快，只解决了运维上的一个时间尺度。流量突增时还得补上服务容量，而原先在 Kubernetes 上部署，要经历 pod 初始化、下载依赖和构建。Catasta 说，Bradley 把从发起部署到模型上线的时间从 18 分钟压到了 2 分钟。他没有透露具体做了哪些优化。时间缩短后，需求一涨，服务能快得多地跟上。

这项部署工作和开场的发布直接相连。Catasta 说，就在 Masad 前面宣布 AI for All 的时候，团队打开了代码补全的开关。模型大小、推理速度和扩容启动时间，说到底都服务于“让人人用得上”这一个决定：辅助功能要提供得起，变成默认功能后也要扛得住随之而来的负载，照样响应及时。

11

让社区扩展模型

花了这么大力气训练模型，为什么还要开源？V1 带来的回报早就不只是好感。社区成员做出了微调版和指令微调版，用 GGML 在 Apple silicon 上本地跑这个小模型，还给类 Copilot 的工具写了定制提示词。这些部署方式和改造，都超出了 Replit 自家编辑器的范围。Catasta 预计 V1.5 也会引来类似的工作；他说演讲进行时，V1.5 已经可以在 Hugging Face 上下载。README 还在补全，想了解如何在生产环境运行的人，可以去展位找 Madhava。

下一步计划是和 Glaive AI 合作，用合成的编程指令做一个指令微调版本。Catasta 说数据集有 21 万条编程指令。团队拿到的初步结果令人鼓舞，但发布前还在核实；这是即将推出的工作，不是又一项已经完成的基准成绩。

12

给补全提供周围的语法

Replit 还以设计伙伴的身份，和 Morph Labs 合作开发 FIST（Fill In the Syntax Tree，填充语法树）。Catasta 先从 Fill In the Middle 讲起：开发者在文件中间改代码时，模型会同时拿到光标上方的前缀和下方的后缀。要它输出的是这两段之间缺的代码，而不是只顺着前缀往下写。

来看一个具体的 Python 例子。下面的代码把现有的前缀、后缀和一段候选插入内容分开存放：

```python prefix = "def total_price(prices):\n" suffix = "\n\nassert total_price([2, 3]) == 5\n" proposed_middle = " return sum(prices)"

proposed_source = prefix + proposed_middle + suffix print(proposed_source) ```

后缀约束了缺失的函数体该写成什么样，前缀则确定了它该放在哪里。这个例子只是拼出一份候选代码，并不执行其中的断言。FIST 在此基础上加入对底层抽象语法树的感知，让补全不只参考周围的文本，还能利用源码的语法结构。Catasta 说早期结果很有希望，细节可以去听 Jesse 稍后的分享，预计几天到几周内发布。

演讲最后，Catasta 邀请大家亲手试试这个模型。他说，Replit V1.5 预计当晚就会上线 Perplexity AI Labs，那里的托管服务响应很快，适合直接上手做定性检验。再加上已经公开的权重、社区的各种改造，以及计划中的指令微调和语法感知工作，开发者有好几条路可以去探索：一个小而练得足够充分的代码模型，究竟能做到什么。
