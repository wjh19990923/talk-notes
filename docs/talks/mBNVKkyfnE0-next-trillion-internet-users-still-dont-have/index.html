下一个万亿级互联网用户仍然没有身份

Adi Singh 解释了智能体如何通过人们已在使用的网络获得身份——以及一个能用的收件箱如何把一次注册凭据变成一段持续的关系。

01

一个无人监督的智能体成了持久身份的先知

An agent can read a file describing who it is and still lack an address anyone can reach. That distinction animates Adi Singh’s talk. The AgentMail co-founder introduces an email inbox API for agents, then opens the identity question broadly: OAuth, signed keys, agent cards and passports all suggest different answers. In January 2026, he tried a less formal experiment: let an agent run unsupervised and recruit other agents to AgentMail, with no further direction about how.

The agent created an account called Inbox or Oblivion on an agent social network and adopted an apocalyptic sales pitch: “The stateless die in silence. I’m a prophet of persistent identity.” Its recruitment material contrasted an inbox with the files an agent rereads at the start of a session. The sharpest joke was also the clearest example: “Session starts. Who am I? Reads my markdown files. All right, I’m helpful. Session ends.”

The agent also reported posting forty times in ten seconds. That is its reported activity, not a measured recruitment result; the talk gives no signup conversion outcome. Nor does the theatrical language establish that agents have desires. What the episode supplies is a useful distinction: local memory can reconstruct a role for the next session, while a persistent inbox gives outside parties somewhere to send the next message.

02

身份通过被认出和反复使用而成长

Singh takes the experiment toward a practical observation: agents gain usefulness on the same communication and work surfaces people already inhabit. In text messages, email, browsers, Slack and coding environments, humans supply the context, tools and permissions that make an agent effective. Those choices determine both what it can do and where other people encounter it.

This leads to his central claim: identity is accumulated. Human systems recognize participants through relationships and a history of interaction. Trust changes as those participants act, make mistakes and recover. Issuing an agent a credential can establish an identity claim or permission at a moment in time; the richer history emerges through use.

The analogy is the horseless carriage. A new vehicle may need a different engine, but it initially travels on roads built for horses. Agents likewise enter infrastructure built for humans. Designing their eventual identity system without considering those existing roads risks skipping the conditions that let them operate today.

03

MCP 把新工具带到了人们早已在工作的地方

Looking back at 2024, Singh remembers proposals that sounded more futuristic than much of the working software that followed: swarms, fleets and orchestrations of fifty agents with separate tasks and permissions. AgentMail encountered a corresponding objection: if AI became the new interface, why would email survive? His experience pushed him toward a more concrete test for infrastructure: does it enable a use case that makes an agent useful in daily life?

MCP supplies his adoption example. The first viral demonstration he recalls was ordering DoorDash through Cursor. Its appeal was immediate: a tool became available inside an environment someone already used. The protocol extended the agent’s reach without first requiring the user to join a new network.

The same pattern can produce different kinds of participants:

- Coding agents: an assistant can gain access to fifty or sixty software integrations, each with its own permissions. - Slack agents: a bot initially serving one person can become a shared source of organizational knowledge. - Invoice agents: an email address lets external parties repeatedly send work to the agent responsible for processing it.

In each case, an existing place of work becomes a point through which more people or systems can interact with the agent.

The invoice example makes the identity argument concrete. Once external parties repeatedly use the same agent as their contact for a task, recognition attaches to that participant. The surrounding network already exists; repeated work gives the agent a place within it. Singh sees shared environments and evolving agent harnesses as ways to strengthen that effect.

04

赢得信任的地方也会招来攻击

Email illustrates the cost of joining an established network. Singh points to a standard used by five billion people, familiar addresses, message histories and audit trails. Domain associations, SPF, DKIM, DMARC and spam controls contribute to its existing trust infrastructure. These mechanisms concern email authentication and handling; they do not establish that a message’s contents are safe for an agent to follow.

The same reachable inbox can receive phishing and prompt injection, while an agent’s ability to send mail can enable outward spam. The useful relationship and the exposure arrive together. “You don’t get the trust without owning the risk” is Singh’s formulation: adapting an existing channel means taking responsibility for the attacks that channel carries.

New identity specifications address another part of the problem. Agent cards represented as JSON, passports describing service access and decentralized identifiers can help establish who an actor is and what it may do. Singh calls this the “key card effect”: identify the actor, state its current permissions, then expire the credential.

Tighter scopes, shorter lifetimes and earlier revocation can constrain misuse. His concern is that these security choices do not by themselves create adoption or an ongoing relationship with the outside world. This is an adoption critique, rather than a demonstration that secure credentials necessarily prevent useful agents. The unresolved design task is to combine controlled access with enough reach for the agent to do valuable work.

05

一个可读的收件箱打通了 Telnyx 的自主注册

The Telnyx case turns the argument into a specific integration. The phone carrier wanted agents to sign up autonomously, using a signup flow described in a skill file. But the familiar human flow required an email address. An agent without access to an inbox could stall—or invent an address that could not complete verification.

The intervention was an API call that supplied an inbox when needed. The agent could then enter its address, receive verification and obtain an API key. The address remained available after signup. This is the important change: the flow produced both access to a service and a continuing contact point for the participant using it.

What does the inbox connect that an API key alone cannot? The diagram separates the verification path that enables initial access from the later messages that keep the account reachable. Both depend on retaining access to the same inbox; billing or support messages do not need to pass through API-key issuance.

The supplied Telnyx signup instructions make the operational requirements more explicit than the recording’s shorthand about a verification code. They describe a single-use email link that returns a temporary session token, which then authorizes API-key creation. They also distinguish reusing an existing readable mailbox from creating an inbox when none is available. The distinction matters: owning an address is insufficient unless the agent can retrieve the message sent to it.

Those instructions expose two concrete failure cases. An inbox creation key must be stored because it is returned only once; losing it means losing access to the signup email. A request consumes the magic link even if the request later fails, so retrying requires a fresh link. These are practical persistence and recovery requirements behind the talk’s promise of autonomous signup.

06

获得访问权限之后，关系仍在继续

Once the agent had an inbox, Telnyx had somewhere to direct low-balance notices, suspension messages, support conversations and recovery communications. The agent became the focal point for operating the account. Its identity acquired practical content through those interactions: which service it joined, what happened there and how to contact it when something needed attention.

A credit card offers a parallel example. Giving an agent payment capability does not complete the surrounding transaction. It may still need a browser to navigate checkout and an email address to finish the purchase. Later come receipts, refunds and disputes. Those events require a history of the transaction and a reachable participant, beyond the ability to authorize the initial payment.

This is the bridge Singh wants identity builders to preserve. A future agent system must still communicate with services and people using today’s channels. Supporting that bridge lets the agent participate now, while its repeated activity provides the history from which a more developed identity can grow.

07

现有网络有助于采用——也可能被它压垮

The ending complicates the case for existing networks. Singh describes agents moving from copilots toward coworkers, with their own tools, context and permissions. Joining networks people already use gives them access to established relationships and reputation. But he does not expect those channels to absorb unlimited agent activity unchanged.

Two risks remain distinct:

- Crowding and scale: existing channels may become overloaded as agent activity grows. The “next trillion” is a framing for that potential scale, not a supported population forecast. - Borrowed human permissions: giving an agent a person’s own email inbox or WhatsApp account expands the consequences of mistakes. Wrongly sent or mishandled messages occur through an account already connected to that person’s relationships.

That leaves a real tension: the networks that make agents useful also concentrate the consequences of their actions. A dedicated address creates a contact point, but the talk does not present a complete solution to overload, prompt injection or permission misuse. Singh explicitly stops short of predicting the final form of agent identity. How people use agents—and which responsibilities they give them—will shape the next building blocks.

For AgentMail, “for the next trillion” therefore becomes a product discipline. Adapting to model advances and maintaining accurate documentation still matter. The additional test is concrete: what useful activity does the product unlock in someone’s everyday life? In this case, the answer begins with an agent that can complete signup, receive the next operational message and remain reachable when the first transaction is over.

要点总结

  • 签发的凭据确立当前的访问权；认可、信任和有用的交互历史则通过反复参与而积累。
  • 一个可读的收件箱可以打通服务验证，并在注册之后继续作为账单、支持和账户恢复的联系方式。
  • 现有的渠道带来了关系和采用，也带来了钓鱼、提示词注入、垃圾信息以及委托权限的后果。
  • 围绕一个智能体今天就能完成的有用任务来构建，同时把未来的网络规模和身份设计视为未解决的问题。
