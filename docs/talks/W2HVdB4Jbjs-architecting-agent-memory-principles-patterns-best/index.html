设计智能体记忆：原则、模式与最佳实践

智能体记忆需要的不只是保存聊天历史：它还需要检索、上下文选择，以及能让早先的交互影响后续行动的记录。

熟悉 LLM 上下文窗口、检索增强生成和工具调用，有助于理解架构和示例。

01

从无状态的响应到持久的关系

怎样让一个无状态的 AI 应用记住它的用户？在每条提示词里重复指令，可以约束单次交互的行为；但要做到连续，就得有持久化。Richmond Alake 开场讲了三个相互关联的转变：应用从无状态变为有状态；不再每次重复设置提示词，而是保留持久的信息；孤立的回答变成跨越多次交互的关系。最终目标是让智能体可信、能干、可靠。

演进从 ChatGPT 这类 LLM 聊天机器人开始，接着是检索增强生成，也就是 RAG：它补充领域知识，让回答更贴切。按 Alake 的说法，算力和数据规模上去之后，推理和工具调用也随之出现，于是有了智能体和智能体系统。他把自主性看作一条连续谱，用自动驾驶的分级和他自己坐 Waymo 的经历来类比。一端是循环运行的 LLM；再往前，是配有工具、只需少量提示就能更自由行动的系统。

他给出的工作定义包含四部分：感知环境，用 LLM 做认知，借工具行动，再加上短期或长期记忆。记忆提供连续性，让智能体能够反思、交互、主动行事，并应对变化的情况。Alake 是 MongoDB AI/ML 开发者布道师，整场演讲都用 MongoDB 的例子来展开这套架构。

02

保留时长只是记忆的一个维度

短期和长期说的是信息能用多久，但应用要记住的东西不止这些。Alake 还列出了对话记忆、实体记忆、知识、数据存储、缓存和工作记忆。这些类别按信息在系统中的作用来划分。他的出发点是人类的回忆：如果 AI 想复现人类智能的某些方面，那么保存和找回信息的能力就是架构层面要考虑的事。这是个有用的类比，但并不是对智能的完整定义。

拿人来对比，除了短期、长期和工作记忆，还有语义记忆、情景记忆和程序性记忆。为了把程序性记忆讲具体，Alake 问台下有没有人会后空翻：会一套动作、一门技能，和记住一个事实或一件事是两回事。他用简化的生物学说法，把这种技能归到小脑。落到工程上，意思是不同类型的信息要考虑用不同的方式表示，而不是把每段记忆都当成又一条聊天消息。

03

存储的信息在影响执行时才成为记忆

智能体记忆是一种持久状态，可以影响之后的执行步骤。 智能体积累信息、保存信息，在决定下一步时再把它调出来。所以光有存储不够：应用还需要一套记忆管理系统，来安排哪些内容进入模型的上下文窗口。上下文窗口大，只说明能放下相关的记忆，不能成为把整个数据库塞进去的理由。保存下来的信息能不能帮模型给出贴切的回答，取决于怎么挑、怎么组织。

Alake 概括了记忆的生命周期：生成、存储、检索、整合、更新和删除。他接着主张探索遗忘机制：记忆管理不仅要看记录在不在，还要考虑哪些经历仍然重要。演讲把这当作一个设计方向提出，没有给出具体的遗忘算法。借鉴人类记忆，也不等于应用在需要时可以不删数据。整个生命周期里，检索最受关注，因为它把积累的信息和下一个决策连了起来。

RAG 已经是这种连接的一种常见形式，而检索也不只等于向量搜索。不同的信息需求要配不同的搜索方法。Alake 推荐用 MongoDB 来提供这些能力，但 RAG 并不非得依赖 MongoDB。智能体式 RAG（Agentic RAG）改变的是谁来控制访问：把检索做成工具，智能体就能自己决定什么时候去要信息，而不是完全依赖每次回答前固定执行的一步检索。

04

持久化人设，检索当下需要的工具

Alake 把 MongoDB 定位为记忆提供方（memory provider）：一个负责存储和检索的底座，开发者可以在上面构建记忆行为。他的开源配套项目 Memorizz（演讲中念作“Memoriz”）收集了他介绍的各类记忆的实现模式。第一个例子是人设（persona）。他先批评了 ChatGPT 最近的性格变化，随后指出背后的目标本身值得追求：智能体应该有自己的特点，让交互显得可信，关系也更连贯。人设记忆就是把这些特点存成数据库记录。

工具箱记忆解决的是另一个约束：模型不需要在每次请求里都看到全部工具定义。Alake 说 OpenAI 有过一个大致的建议，约 10 到 21 个工具 schema。这应当看作他对过往情况的转述，而不是 API 限制；当前的函数调用指南给出的软性建议是，初始可用的函数少于 20 个，并建议通过评测来确定工具数量。对应的架构模式是：完整的工具箱放在上下文窗口之外，调用 LLM 之前先检索出相关的一小部分。

工具箱的流程很直接：

1. 把工具定义存成文档，包括名称、描述和 JSON 参数 schema。 2. 针对当前请求，在这些记录里搜索相关工具。 3. 把选中的定义交给 LLM，供它做下一步决策。

选出来的那页幻灯片上，工具箱 schema 里还有嵌入向量。检索到某个工具定义，只是让模型可以使用这个工具，并不会执行它。

这个模式依赖数据库两项互补的特性：文档能表示不同的记忆结构，检索能贴合信息需求。Alake 列举了 MongoDB 的图、向量、文本和地理空间能力。工具发现只是这种灵活性的一种用法；同一套存储底座也能存人设记录和其他类型的记忆，不要求它们都用同一种结构。

05

对话历史需要检索信号

对话记忆保存的，是你在 ChatGPT 或 Claude 里熟悉的那种一来一回。Alake 的记录包含时间戳和对话 ID，另外还加了召回时间（recall recency）和关联对话 ID。这些额外字段是当作记忆信号来设计的：管理系统可以借助这些元数据，判断某条信息最近一次召回是什么时候、对话之间有什么关联。他把这些字段和自己在 Memorizz 里做的遗忘实验联系起来。这些字段说明系统能记录什么，但并不代表已经有了一套完整的遗忘策略。

06

把一次失败的执行作为下一次尝试的上下文

工作流记忆给出了最清楚的反馈例子。智能体执行了第一步、第二步，然后在第三步失败。这次失败就是值得保留的经验。把它存下来，下次执行时检索出来，用它提醒 LLM 别再重复失败的那一步，或者换条路试试。适应靠的是检索到的上下文，演讲中没有提到更新模型权重。保留下来的失败能影响下一次尝试，但不保证下一次就能成功。

用一段简短的 Python 来表示，可以清楚地划出“已记录的经验”和“待执行的动作”之间的界线。这里的 workflow-1 是为讲解起的标识符，代表那个三步工作流。下一条提示词里带上了失败的那一步，但还没有真正重试：

```python import json

workflow_memory = [ { "workflow_id": "workflow-1", "steps": [ {"step": 1, "outcome": "success"}, {"step": 2, "outcome": "success"}, {"step": 3, "outcome": "failure"}, ], } ]

def build_retry_prompt(workflow_id, memories): prior_attempts = [ memory for memory in memories if memory["workflow_id"] == workflow_id ] return ( f"Plan another attempt at {workflow_id}.\n" "Use the recorded outcomes to consider an alternative " "to the failed step. No retry has executed yet.\n" f"Prior attempts:\n{json.dumps(prior_attempts, indent=2)}" )

next_prompt = build_retry_prompt("workflow-1", workflow_memory) ```

在做了持久化的实现里，检索会从数据库中取出相关的工作流记录。核心操作不变：之前的结果成为下一次决策的输入。

屏幕上的数据库示例，是 memorizz.workflow_memory 里一份展开的文档，包含一个工具执行步骤、参数、返回结果、时间戳和最终状态（outcome）。屏幕上能看到的状态是成功，而口头举的例子讲的是失败。两者都属于执行历史：工作流记忆记下发生过什么，之后做决策时就能用上这些经验。

Alake 接着提到了情景记忆和长期记忆，然后是智能体注册表（agent registry），用来存放智能体的信息，包括它的工具和人设。实体记忆是另一个类别，不过演讲没有细讲它的实现。这些例子是供学习的模式：Alake 明确说 Memorizz 是实验性、教学性质的项目。

07

把记忆提供方与记忆管理分开

选架构时，要分清基础设施和行为。Alake 提到 MemGPT、Mem0 和 Zep，它们专注于记忆管理；而他把 MongoDB 定位为支撑定制方案的提供方。

| 层 | 职责 | |---|---| | 记忆提供方 | 存储记录，提供检索能力 | | 记忆管理 | 决定保留、检索和整合哪些内容 |

他想说的很实际：不同应用不一定要用同一套记忆策略。共用一个数据底座，各个应用照样可以自己决定记忆怎样影响智能体。

对检索的重视，引出了 MongoDB 收购 Voyage AI 这件事。Alake 介绍了 Voyage AI 的文本和多模态嵌入模型以及重排序模型（reranker），说它们能改善检索、减少幻觉。他称这些模型市场领先，但没有给出基准任务和模型版本，也没有幻觉减少的实测数据。这些是厂商对预期收益的说法，不是工作流例子里实际展示的结果。

路线图接着把更多检索工作挪到数据库这一侧。Alake 预计几个月内会把 Voyage AI 的嵌入模型和重排序模型集成进 MongoDB Atlas，目标是让开发者不用再操心分块和检索策略。在录像里，这还是一项计划中的集成，没有部署演示。它呼应了 Alake 在这部分结尾提出的更大的产品承诺：周边技术不断变化，MongoDB 要帮开发者快速、安全地构建 AI 功能。

08

从记忆研究中借鉴架构思想

结尾又回到生物学，讲到 David Hubel 和 Torsten Wiesel：两人研究视觉信息处理，分享了 1981 年诺贝尔生理学或医学奖。Alake 用层级表示来描述他们的视觉皮层研究：从边缘、轮廓，到更抽象的形状。他借此说明，神经科学如何启发了卷积神经网络背后的思路，以及人脸检测、物体检测这类应用。这个类比落在架构上：研究生物系统，可以得到有用的计算结构，软件并不需要复刻整个大脑。

在智能体记忆上，Alake 提议学科之间也来一次类似的交流。他讲到最近的一次会面：Tengyu Ma 在场，他介绍 Ma 是 MongoDB 的首席 AI 科学家、Voyage AI 的创始人；同场的还有几位神经科学家，以及 MemGPT 的合著者、与 Letta 有关的 Charles Packer。其中一位与会者 Kenneth，据他介绍长期研究大脑和记忆。这次会面也给了演讲最后的方向：让研究记忆的人和构建智能体系统的人坐到一起。自然界能提供思路：该保留什么、怎样回忆、经验如何指导未来的行动；但要把这些思路变成明确的机制，还得靠开发者。
