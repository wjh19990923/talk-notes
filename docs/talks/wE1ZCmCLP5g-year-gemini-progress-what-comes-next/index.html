Gemini 这一年的进展 + 下一步

一次 Gemini 2.5 Pro 的发布，开启了一份路线图：涵盖研究成果转化、主动式助手、推理、上下文限制，以及 AI Studio 作为开发者平台的方向。

01

一个在公告上线之前就发布的 Gemini 版本

Logan Kilpatrick 在台上介绍 Gemini 2.5 Pro 的新一轮更新时，公告还没正式上线。眼下的问题是：这次更新能不能补上开发者在早期版本里发现的短板，补到足以成为最终版。他称之为“希望是最后一次更新”，同时也留了余地：如果反馈暴露出问题，后面还会再改。

Kilpatrick 称这次更新在 Aider 和 HLE 上达到业界最佳，但没有给出分数，也没说明评测条件。他说这些改进来自开发者对前几个版本的反馈，并称 2.5 Pro 是个转折点：DeepMind 内部如此，开发者对 Gemini 的看法也是如此。完整的发布幻灯片还列出了 LMArena 和 WebDev Arena 上的提升、思考预算（thinking budgets）、稳定版候选模型，以及帕累托前沿。这一版是稳定版的候选，但他依然欢迎大家报告问题。

想试用这一版，Kilpatrick 建议开发者去 ai.dev，普通用户去 Gemini app。这是他在发布环节给出的两个入口。演讲剩下的部分讲 Google 怎么走到了今天，以及模型、app 和开发者平台接下来往哪走。

02

研究的广度为主线模型供料

回顾从过去一年密集的工作讲起。DeepMind 的研究覆盖科学、机器人和通用模型，Kilpatrick 认为这种广度是一种优势：专项研究可以反哺主线 Gemini 模型，而不是各自困在独立项目里。

他举了 AlphaProof 和 AlphaGeometry 为例：这些定制模型的工作提升了主线模型在相应领域的能力。关键在于区分两件事：开发一个专用系统是一回事，把有用的成果迁移进通用模型是另一回事。Kilpatrick 说这种迁移确实在发生，但没讲具体的训练机制，也没量化两个系统各自给 2.5 Pro 贡献了多少。更深入的讨论，他留给了 Jack 接下来的演讲。

研究推进的同时，使用量也在扩大。Kilpatrick 引用 Sundar Pichai 在 Google I/O 主题演讲中的数据：一年内，Google 各产品和 API 每月处理的 token 量增长了约 50 倍。主题演讲给出的总数是：一年前 9.7 万亿，到 2025 年 5 月发布时已超过 480 万亿。这个数字衡量的是 token 总量，不是推理速度，也不是算力增长。Kilpatrick 认为，增长来自 Google 内部和外部开发者对 Gemini 的需求。

03

把研究、模型和产品结合起来

一部分原因在组织层面。Google 过去由不同团队分头推进不同方向的 AI 研究。2023 年 4 月，Google Brain 团队与 DeepMind 合并，组成了统一的机构。它的职责不止于基础研究，还要打造模型，交付给 Google 其他团队和外部用户。

之后，产品团队也向研究机构靠拢。Kilpatrick 提到，演讲当年早些时候又迈出了一步；而 Gemini app 团队本身的迁移早在 2024 年 10 月就已宣布。调整之后，研究、模型打造和产品交付都归入 DeepMind：Gemini app 面向消费者，Gemini API 面向开发者。幻灯片上并排放着一份组织调整公告，以及 Kilpatrick 宣布 AI Studio 和 Gemini Developer API 迁入 DeepMind 的帖子。

在 Kilpatrick 看来，离得近了，和研究人员协作更方便，也更容易把新能力交到开发者手里。他的公式很直接：把最优秀的人聚到一起，找到基础设施上的优势，然后发布。这次组织调整的意义在于，它把研究进展和产品交付连了起来。

Veo 的火爆就是一个例子。Kilpatrick 开玩笑说，Veo 热到“把 TPU 都烧光了”——他是在形容大家的兴趣，并不是说基础设施真出了故障。演讲进行到这里时，Veo 已经在 Gemini app 上线；开发者 API 的接入则排在路线图后面。

04

从共享登录到通用助手

Gemini app 的目标是成为通用助手。Kilpatrick 用一个熟悉的对比来解释：过去，Google 账号把人和许多 Google 产品连在一起，但主要作用只是登录各个产品。账号本身并不提供横跨这些产品、能记住状态的丰富体验。Gemini 要成为串起这一切的那条线。

| 跨产品的连接方式 | 作用 | | --- | --- | | Google 账号 | 统一身份与登录 | | Gemini 的目标定位 | 横跨各产品、有状态的助手 |

下一步是主动性。按 Kilpatrick 的说法，大多数 AI 产品仍然要用户先开口，很多活也得用户自己干。主动的助手会更多地自己出手：变的不只是界面，还有谁来发起一次有用的交互。在这场演讲里，这还只是产品方向，没有演示实际的工作流。

对 app 本身有意见，Kilpatrick 让大家找 Josh 和 Gemini app 团队，而不是找他。后面的路线图把面向消费者的助手和底层模型、开发者工具分开讲，这种分工也就派上了用场。

05

更多模态、更多推理、更多上下文

Gemini 最初的设想，是用单一的多模态模型处理音频、图像和视频。当年 I/O 发布的原生音频和文本转语音能力，让它离这个目标更近了一步：用户可以直接和模型对话，Astra 体验和 Gemini Live 也靠对话式音频驱动。Kilpatrick 把终点描述为一个全模态模型，把这些能力整合到一起。

Kilpatrick 称 Veo 在多个领域达到业界最佳，但没有点明评测或分数。他希望把 Veo 的视频能力带进主线 Gemini。接着他提到早期的扩散模型实验，认为这条路能大幅提高 token 生成速率。不过扩散在这里仍是研究探索，不是主线能力，他也没给出任何吞吐量数字。

下一个变化关乎开发者能从模型拿到什么。Kilpatrick 过去把模型接口理解为 token 进、token 出；要搭更大的系统，得靠外围软件提供脚手架。他所说的“默认智能体化”（agentic by default），就是把更多这类工作挪进模型内部。

推理可能会接管一部分如今由外部智能体脚手架承担的工作。 模型越来越有条理，这些行为就可能转移到推理这一步来完成。到底会挪过去多少，Kilpatrick 把它当作开放问题抛了出来——答案会影响那些围绕现有模型做产品的人。他再次提到 Jack 接下来会讲推理的扩展；他并没有宣布开发者自己的编排会被取代。

路线图里还有更多小模型和更多大模型。规模之外，Kilpatrick 指出了一个更难的架构前沿：无限上下文。他认为，当前基于注意力机制的模型范式没法一直简单地扩展下去，要让模型用上更多上下文，就得有新的创新。无限上下文是研究目标，不是承诺的上下文窗口大小。Gemini 模型的产品工作由 Tulsee 负责，关于模型能力的反馈也由她接收。

06

把能力变成开发者 API

开发者路线图从 embedding 讲起。即使大家的注意力转向了智能体，embedding 依然重要，因为它支撑着检索增强生成：先检索相关材料，再作为上下文交给模型生成。Kilpatrick 称 Gemini embedding 模型达到业界最佳，但没说是哪项评测；他预计在演讲后的几周内向更多开发者开放。

规划中的 Deep Research API 面向的是另一层。它不只开放一个模型原语，而是让开发者把研究类工作流集成进自己的应用——这类工作流在消费级产品里已经很受欢迎。Kilpatrick 说的是一个正在开发的定制 API；在这段录像里，开发者还没有可以直接调用的端点或请求格式。

Veo 3 和 Imagen 4 也计划开放 API。Kilpatrick 希望它们很快就能上线，时间取决于开发者平台扩容的进度。这些上线计划反映的是录制时的路线图，不代表现在的 API 可用情况。

07

AI Studio 变成一个开发者平台

路线图的实质内容以一个定位决定收尾：AI Studio 要做成开发者平台。 Kilpatrick 预计它会摆脱现在偏消费级的感觉，转向更明确为开发者设计的体验。配套的路线图幻灯片把这一重点和 embedding、媒体 API、智能体、Computer Use API、评测工具、Deep Research API 以及 Gemini Code / CLI 放在了一起。

设想中的开发者体验会内置智能体。Kilpatrick 希望把 Jules 和其他编程智能体原生集成进 AI Studio，让它们直接融入开发者使用 Gemini 的环境。这就是最终的产品方向：AI Studio 不只是试用模型的地方，而是把模型调用和开发辅助结合在一起的平台。在这场演讲里，原生集成 Jules 仍只是愿景。
