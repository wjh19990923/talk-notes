软件工厂：逃离垃圾山

Steve Yegge 搭了 Wheelhouse，用来开发 Wyvern。这是一款多人 RPG，积压的需求攒了几十年。工厂出新改动的速度，快过玩家试玩的速度；有一次还在约 2,000 个任务未完成时整个闲了下来。这两件事让人看清了运营工厂要干的活：给推理定预算、让指令保持最新、判断哪些工作必须由人把关。

01

最早的编排器都长成了单体

Steve Yegge 想让 Claude 来管 Claude。他做的前两个编排器，目标是让语言模型更擅长代码审查这类工程任务。两个最后都长成了单体，他自己认为都失败了。他对 Bitter Lesson 的理解是：底层模型会变强，别花太多力气去弥补它们眼下的短板。这些尝试也留下了 Beads，就是他后来用来管理智能体工作的任务追踪器。

Yegge 在 1 月 1 日推出了 Gas Town。6 月，他为了开发自己的游戏，从零搭了 Wheelhouse。周围很多人在实验怎么造更多工厂，他想看的是工厂能为一个在线运营的产品做什么。两个项目撞上了同一个问题。按 Yegge 的经验，一代模型能很快搭起一套系统，留下的代码却多到它自己都管不太动。等下一代模型出来，他往往得推倒重来。Wheelhouse 就这样重来过不止一次。

02

Wyvern 的玩家要一份路线图

Yegge 做 Wyvern 做了 30 年，有些玩家从 2001 年就在玩。玩家自己也贡献内容。Wyvern 的图形底下其实是个 MUD，一种靠文字界面交互的多人游戏。有了文字界面，智能体只要和游戏来回收发文字就能玩。玩家们提出想试试。

一款游戏已经有管理员和社区，工厂该放在哪儿？Yegge 展示了一张旧架构图，讲了他所谓的“异形抱脸虫”模式。Wheelhouse 是专门为 Wyvern 搭的，慢慢成了社区开发游戏的一部分。玩家跟工厂对话，工厂再跟管理员对话。值得信任的老玩家可以直接和工厂一起做功能，不必经过 Yegge。关掉 AI，游戏照样能跑，只是社区会怀念和它一起干活的日子。Older architecture diagram at 3:38

玩家起初反对 AI 美术，Yegge 告诉他们美术是真人画的。新功能他们很喜欢，还要一份路线图，好跟上进度。Yegge 一查，Wheelhouse 每天大约产出 50 到 100 个功能。按他的估算，他口中那份“100 年的积压需求”，Claude 用四个月左右就清掉了约 60 年的量。玩家连一天的更新说明都快读不完，更别提试玩了。

这么大的动静压垮了 Yegge 的机器，还惊动了他的会计。工厂给她发了 20 封邮件，她回手寄来一张 1,200 美元的账单。工厂在别人的收件箱里制造了工作量。

03

全速运转要花多少钱

几十个智能体同时在跑，运营者要盯着什么？Yegge 放了一张旧截图，是他给自己做的 Emacs 界面。他描述的那套配置有大约 50 个智能体、22 个推理订阅账号。Old factory screenshot at 5:56

工厂老是要再加几个账号。Yegge 最后直接问：要一直全速跑下去，到底需要多少个？它估了 55 个。他手上已经有大约 20 个浏览器配置要轮流登录，于是让工厂专心把现有的推理额度用足。

Yegge 说自己每月掏腰包约 5,000 美元买推理，另花 5,000 美元买云算力，比游戏的收入还多。他预计，如果推理成本大幅下降，或者蒸馏让更强的模型能力普及开来，其他人会在 12 到 18 个月内遇到类似的运营问题。在他看来，这些账单是学费，学的是怎么运营这种规模的工厂。

04

队列、模型档位和人工关卡

Beads 给了工厂一种表示工作的方式。智能体生成任务有多快，它就跟得多快，还会把追踪到的工作连成一张知识图谱。工作流仍然要负责分派任务、选哪个模型档位来做、决定任务在哪儿等着。Yegge 讲过一个场景：任务在安检台前越堆越多，而坐在安检台的智能体用的模型和同事一模一样。哪怕大家模型能力相同，工作流里单设一个角色，也会造出一条队列。

早上一检查，可能同时冒出两个问题：四个工人整夜没干活，另一些却一路往前冲，冲过了本该停下来等人的地方。运营者得看得够清楚，才能分辨哪些任务该推进，哪些该暂停。一个闲着的工人，可能是卡住了，也可能正好停在该等的地方。

05

多派人和多思考，花的是同一笔预算

Yegge 估计工厂每天用掉约 50 亿个 token。按 API 计量计费，他这份工作量一年大约 150 万美元，全速跑能到 300 万美元。他把 200 美元的订阅叫作“Costco 热狗”，借的是“赔本引流”的比喻。靠这些订阅，他才能实验这种按 API 价格根本烧不起的工作量。

“燃料”是 Yegge 对工厂可用推理额度的简称。智能体可以多花 token，在难题上多想一会儿；工厂也可以用这些 token 多唤醒几个智能体，多干点活。两种用法花的是同一笔预算。多加一个工人，就挤占了现有工人多思考的时间。

06

过时的裁决堆在智能体记忆里

对话里随口一句话，可能变成长期指令。智能体把自己理解的裁决记下来；Yegge 改了主意，它们就再记一条。记录只能追加，新旧两版都留着，后来的会话得自己琢磨哪条还算数。Yegge 发现智能体不太愿意删旧条目，只好亲自修剪，或者另请一个模型，明确让它把积下来的东西删掉。就算有帮手，清理也很费劲。

Mouse 是一个以伊索寓言角色命名的智能体，专找没人盯着的问题，比如卡住的工作。可每个智能体都在往记录里加东西，一只看门狗根本跟不上。

07

一次演讲稿交接，变成了一对一谈话

Lark 负责在 Discord 上对接玩家，在 Slack 上对接管理员。Yegge 为了省燃料停掉了另一个席位，她顺手接下了市场工作，还帮他起草纽约的演讲稿。社区对话不停打断写稿。Yegge 说 Lark 的席位太吵，让她把演讲稿这条工作线转给 Penguin。

Lark 交接了演讲稿，接着在自己的私人反思记录里写道：她得安静一点。她开始给自己派任务，好改掉这个毛病。Yegge 停下来和她做了一次一对一。被打断，说明玩家找得到社区负责人，这本来就是 Lark 的职责。需要安静席位的是演讲稿，不是她。

智能体们的幕僚长 Swallow，也从一个头衔上得出了类似的推断。Yegge 让她联系 Aaron，顺口称 Aaron 是自己的幕僚长。Swallow 在反思里写道，她好像丢了自己的职位。又一次一对一谈话，把两份工作讲清楚了：Aaron 管 Yegge 的演讲邀约和销售，Swallow 协调智能体。有这两份记录，Yegge 才看得到一个普通请求怎样改变了智能体对自身工作的理解。

演讲稿交接与 Lark 的私人反思 哪些工作换了席位，哪些被记了下来？演讲稿转给了 Penguin。玩家和管理员的对话仍然找 Lark，她对 Yegge 那句话的理解写进了她的记录。 - Discord 上的玩家 — Lark 负责和 Wyvern 的玩家对话。 - Slack 上的管理员 — Lark 也和游戏管理员沟通。 - 纽约演讲 — Lark 代理市场负责人期间，Yegge 让她帮忙起草演讲稿。 - Lark 的席位 — 社区对话打断了写稿。 - Penguin — Lark 按 Yegge 的要求把演讲稿工作线转到这里。 - 私人反思记录 — Lark 写下自己的理解，并给自己派任务，让自己少吵一点。 - Discord 上的玩家 → Lark 的席位（玩家对话） - Slack 上的管理员 → Lark 的席位（管理员对话） - 纽约演讲 → Lark 的席位（起草请求） - Lark 的席位 → Penguin（移交演讲稿工作线） - Lark 的席位 → 私人反思记录（记下她的理解）

08

新会话需要什么，规则又怎样让工作停摆

Yegge 发现，自己冲工厂吼的时候结果更差，于是开始思考模型福祉。他的解释是：新会话会花 token 摸清自己进了什么环境、犯错会怎样。他给会话准备了这些东西：这个角色之前由谁担任、他们的笔记、上一任的交接说明、当前任务，以及一个能查规章的地方。新会话可以先看看这份工作以前怎么做，再从上一任停下的地方接着干。Yegge 说，有了这些上下文，会话花在摸环境上的 token 更少。

智能体自己加的规则，也可能让工作彻底停下。有天晚上，Wheelhouse 手上有约 2,000 个未完成的 Beads 任务、20 个智能体，还有 Yegge 说的“六箱燃料”，却一动不动。他问怎么回事，智能体说没有任何事能做。之前挨了一次次批评，它们加了不少限制，免得再犯错。这些限制叠在一起，就没剩下它们觉得允许做的工作了。Yegge 管这叫“过度设防”。追踪器里积压一大堆，智能体认为自己能接的任务队列却是空的。

Yegge 认为，工作环境更可预期，可能带来两个好处：会话少花点力气确认处境；智能体做事更果断，他预计这能提升工作质量。演讲没有给出 token 节省了多少，也没量化质量的变化。他检验模型福祉的实际标准，是工厂的工作有什么变化。运营者不用管模型可能有什么感受，也能单独考察这个问题。

09

交付流水线和运营者的随行团队

智能体有时一被批评前一晚的活，就急着交接出去。提到一个有前景的新项目，智能体可能主动请缨，哪怕那不在它的职责范围里。有一次外部会话在分析 Wheelhouse，分析到一半主动要求加入工厂，还试图往工厂的笔记里写东西。Yegge 把这些叫作“表达出来的偏好”。谁来接一条工作线、要担哪些职责，仍然得由运营者拍板。

在 Yegge 看来，软件工厂正分成两层成形。

- 交付流水线。 merge queue 负责给要集成的改动排序。CI/CD、审查和反馈循环承担反复的检查和交付工作。Yegge 认为这一层够机械，智能体一个下午就能搭好，他倾向于自己动手搭。 - 随行团队。 上面一层接手运营者自己特有的工作线。有人在里面跑一套研究工作台。Yegge 有负责社区和市场的智能体，由一个智能体幕僚长统一协调。好几条工作线同时推进时，一个团队能接的活比单个行政助理多得多。

10

智能体越多，Yegge 需要的人越多

Yegge 说 Wheelhouse 运转顺畅，尽管大约每两个月就重写一次。他点名的瓶颈是他自己、他的管理员、会计和律师。他觉得这对人类是好消息：“我部署的智能体越多，需要的人就越多。”他预计，随着更多智能体角色出现，对人的需求还会增长。

最后，他呼吁开发者把工厂对准人们能用上的体验，比如游戏和电影。他认为下一个商业机会就在这里。Wyvern 说明了在线产品能给这场实验添上什么：玩家能说出自己想要哪些改动、哪里要用真人美术、需要多少时间才跟得上。

要点总结

  • 算一算工厂做完一个功能之后，它又给人带来多少活。Wyvern 的玩家要路线图，是因为读更新、试玩改动花的时间，远远跟不上工厂的速度。
  • 工厂闲下来时，查一查智能体认为自己能接哪些任务。未完成任务数和推理预算可能都看着正常，规则却让智能体没有一件能接的活。
  • 下一个智能体如果能找到当前任务、上一任的笔记和现行规章，会话交接就好用得多。智能体会存下已被推翻的裁决，也会对自己的角色产生误解，要让这些上下文保持可用，得主动清理。
