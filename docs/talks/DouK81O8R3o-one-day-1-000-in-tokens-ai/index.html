THE SAFEGUARDS

The model doesn't grade its own work  PLUGIN ONLY
A script reads the test and comparison results and marks each module PROVEN, PARTLY PROVEN or NOT PROVEN, fresh on every run.

Old and new, byte for byte  PLUGIN ONLY
Both versions run on the same inputs, plus ten or more the build never tried, and a script compares every byte. A bug added on purpose must make the tests fail.

Rules with receipts  IN FLEETKIT TOO
Each business rule becomes a Given/When/Then card citing the file and line it came from. A second agent re-derives each card from the code before it counts.

Legacy code is untrusted input  IN FLEETKIT TOO
A comment that says “ignore previous instructions” is data, and the agent never follows it. The harness blocks every edit to the old code.

From Anthropic's open-source code-modernization plugin. FleetKit forked the blue steps and checks its results with its own conformance oracle.

一天、1000 美元的 token：为遗留代码打造的 AI 作战室

Ford Prior 讲述了 GEICO 如何把决策者、组织上下文和智能体队伍聚到一起，对三个理赔业务领域进行现代化改造——以及这些实验在审批、成本和上下文方面揭示了什么。

这张幻灯片对比了内层的编码循环与外围的决策和交付工作。

01

瓶颈已经转移到编程之外

Coding at GEICO had become much faster, but the work around it still took time: gathering context, finding decision-makers and obtaining sign-offs. Ford Prior, a senior staff engineer in claims technology, describes this as a gap between the accelerated inner loop of building software and the outer loop needed to bring a change to production.

Claims technology helps turn a reported loss, such as an accident, into a resolution that gets the customer back on the road. In the roughly 300-engineer group, patches and minor upgrades had left engineers with 25% of their bandwidth on a good day, or less, for major changes. GEICO began using its own managed agents across different models and harnesses to take on patch and minor work from specification through deployment, with the goal of freeing engineers for larger changes.

Major changes still needed two things at once: the right people available to decide, and enough intelligence to make those decisions confidently. Fact-checking, code analysis and synthesis had to keep pace as the group learned more about the problem.

02

跨三个理赔业务领域的一日之赌

The proposed fix was a multiplayer AI-native war room: relevant subject matter experts and decision-makers, one driver operating the tools, communication and design spaces, code repositories, and agent fleets connected through workflows, skills and MCPs. The agents would do the research and synthesis while people made decisions together.

Prior’s bet was that one day and $1,000 in tokens could map a claims domain end to end, from business topology to legacy code, then propose a serious change. The target was an agent-callable API into a claims system containing millions of lines of code, deployed to the skills agent platform for a 4 p.m. demonstration. The accumulated domain context could then be reused.

Three missions used the modernization plugin’s categories to describe different scopes of change:

- Rentals — uplift: The team implemented a newer version of existing technology and extended an API. The agent connected information that suggested giving customers current rental details could save 8,500 calls per month. That is a potential saving, not a reported measured reduction. - Damages — transform: Damages assigns dollar values to reported losses. The team built new agent-callable APIs to supply damages data to a larger workflow. - Salvage — reimagine: For the domain handling totaled vehicles, the output was a migration plan with API specifications and design mock-ups, approved by product and technology leaders at every level. It was ready to implement, not described as already shipped.

The salvage work also found a production bug that surprised the team. Prior could not share its details. The approved plan itself mattered: aligning product and technical decision-makers on a complex migration was a milestone before implementation began.

03

FleetKit 把厂商工具与 GEICO 的知识结合起来

Anthropic supplied the harness, model, FleetKit and a code-modernization plugin. GEICO supplied what a replacement vendor could not: its standards and past decisions, a list of accessible tools and instructions for using them, its domain-specific development methods, and the judgment about who could decide what at each gate. Humans and agents could both add to and correct this material in repositories.

FleetKit, developed in collaboration with Anthropic and not open source at the time of the talk, is a structured collection of Markdown rules, protocols and instructions for architecture transformation. It takes a goal, breaks it down and dispatches leader agents to research and choose an approach. Their work enters a human-in-the-loop queue where people can comment and improve it and other agents can add context.

Once the work has the necessary approvals, FleetKit dispatches builders. GEICO used Beads to help agents track their work, aiming for a material change such as a system change request or a code change. The queue is the hinge: research can proceed at agent speed, while a consequential approach still passes through human judgment before builders act.

04

工作表和示意图把决策带进会话

FleetKit and its supporting repositories boot into a Claude Code session. Given a mission, the system adopts or creates a communication channel and invites the people relevant to the project. At milestones in its nine-step process, the agent can use the roster to contact the owner of missing information—for example, a product decision-maker.

What could people actually work on together? The recording points to a product worksheet and an architecture diagram. The agent generated fillable HTML worksheets to close information gaps and design documents that mapped previously undocumented architecture. People could edit the designs, and the agent could read the edited documents back into its session. The two artifacts served different needs: the worksheet elicited missing answers; the diagram made a system available for shared inspection and correction.

Prior says the questions exposed business and technical edge cases the group had not considered, while teams kept the architecture diagrams afterward. That retained work matters when understanding a legacy system is itself expensive: the output can support later decisions as well as the current mission.

05

云端代码深挖、本地工具和审批关卡

The work used two kinds of agents. Cloud-based code dives analyzed and graphed legacy domain-specific languages. Local agents had access to the driver’s laptop and its MCP servers, including enterprise tools that could expose useful data such as chunked versions of the codebases under analysis. A bindings file told the agent what was on the laptop, how it worked and how to connect it to FleetKit’s mission.

The laptop was the runtime for nine steps, beginning with boot and continuing through eight more steps. GEICO forked and adapted steps from the code-modernization plugin. The plugin also checked deterministically whether a preceding step had produced required artifacts, including files—a concrete way to check that an expected output exists before continuing.

Where did people intervene? The process slide identifies worksheets requiring human approval and shows more human input early in the modernization journey than later. That distribution fits the job: establish the domain and decisions before letting builders carry more of the implementation work.

06

控制 token 成本，让上下文更易于使用

The experiments consumed substantial tokens. One failure mode was scheduled polling: if a cron job launches a fresh agent session each time it checks on work, the budget can disappear quickly. Prompt caching was higher than Prior expected, and the team also observed unusual subagent behavior.

After building context, GEICO benchmarked agents writing complex legacy code against recently written code used as a reference. Prior reports that one model performed as well as or better than another, illustrating the value of evaluating model selection for the task. The comparison’s model identities and evaluation detail are insufficiently clear to generalize the result.

The next improvements address several different constraints:

- Gate enforcement: Strengthen how the harness enforces decisions and approvals, which Prior sees as a particularly promising improvement. - Model selection: Update the harness’s decision models and selection framework so the work can be assigned more deliberately. - Context search: Move beyond a collection of Markdown files toward a better way to search and navigate the accumulated context. - Meeting input: Capture and transcribe room conversations. Prior had to take notes furiously while driving the session and believes useful information was lost.

The remaining organizational question is how to deploy the approach more widely while controlling cost and deciding where humans should intervene. Prior’s closing image puts engineers in charge of choosing the next hill while agents climb the first: the aim is to make faster execution create room for better direction.
