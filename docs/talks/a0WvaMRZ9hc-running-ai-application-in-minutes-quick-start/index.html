Managed identity is generally considered better than using keys for authentication and authorization because of the following reasons:

1. Simplified management: Managed identity eliminates the need for managing and storing access keys. With managed identity, the identity and access management (IAM) tasks are handled by the cloud provider. This saves time and effort in managing keys and reduces the chances of misplacing or mishandling them.
2. Improved security: Using keys requires securely storing and rotating them regularly. This can introduce a security risk if keys are accidentally exposed or not properly managed. Managed identity, on the other hand, leverages the underlying identity provider's security controls, ensuring strong protection for access credentials.

Running the app "locally"

This step will run the app in a local server inside GitHub Codespaces.

1. Copy .env.sample to .env and fill in the values for AZURE_OPENAI_ENDPOINT, AZURE_OPENAI_KEY, and AZURE_OPENAI_CHATGPT_DEPLOYMENT to use the Azure OpenAI proxy service:

AZURE_OPENAI_ENDPOINT=https://YOUR-ENDPOINT-HERE/api/v1
AZURE_OPENAI_KEY=YOUR-KEY-HERE
AZURE_OPENAI_CHATGPT_DEPLOYMENT=gpt-35-turbo

2. Run the server:

构建并部署一个 Python 聊天应用，然后把同一套工作流扩展到商品检索和文档问答，加上引用、查询改写和经过评测的搜索。

01

如何快速让一个 AI 应用跑起来？

How do you get from an AI application idea to something you can run and customize? This workshop starts with reusable application templates and the support around them. Gabriela de Queiroz introduces Microsoft for Startups Founders Hub as an entry point for founders with an idea, an incorporated company, or a business with or without funding. She describes signup as taking less than five minutes. Beyond benefits, the platform offers one-on-one guidance on technical questions, strategy and going to market. Its Build with AI area provides open-source material hosted on GitHub.

At the time of the workshop, Gabriela describes an offer of up to $150,000 in Azure credits, including Azure OpenAI usage. Azure OpenAI brings model access together with Azure’s security and compliance capabilities; other listed benefits include GitHub Enterprise, Microsoft 365 and LinkedIn Premium. Azure AI Studio also provides access to OpenAI and Llama models. These are program benefits subject to eligibility, rather than an automatic grant to every applicant.

Aishwarya Srinivasan emphasizes the people behind the platform. Startups can participate in private previews, try capabilities associated with models such as GPT-4 and GPT-3.5 Turbo, and send feedback to product teams. Expert matching covers infrastructure, Kubernetes, go-to-market questions and subscription pricing. The support is intended to follow a company from its initial idea through building and scaling.

Templates aim to reduce that setup work, including for applications as involved as retrieval-augmented generation with Azure AI Search. 把部署资金与模型访问分开

运行聊天应用，让它写一首俳句

The OpenAI Chat App Quickstart begins with local development. Here, “local” means the application server runs inside the Codespace; it still calls a remote model. 06

使用异步 I/O 并流式输出响应

The quickstart is a Quart application. Pamela introduces Quart through its Flask-like interface and support for asynchronous request handling; the Python samples use Quart or FastAPI. LLM requests spend time waiting on a remote service, so async and await let a backend handle other work while a request is in flight. The application then forwards the OpenAI client’s streamed output to the frontend as JSON Lines, also called newline-delimited JSON. Each line is a complete JSON value that the frontend can process incrementally.

The core Python operation can be expressed as an asynchronous generator that accepts a configured client and yields one serialized record per received chunk:

```python import json

async def stream_reply(client, deployment, messages): stream = await client.chat.completions.create( model=deployment, messages=messages, stream=True, ) async for chunk in stream: if not chunk.choices: continue text = chunk.choices[0].delta.content if text: yield json.dumps({"text": text}) + "\n" ```

Streaming does not remove the wait for the first token. It lets the interface begin displaying output once generation starts, instead of withholding the entire answer until completion. Pamela requests a long essay about San Francisco to make that behavior visible, but the response arrives too abruptly to establish token-by-token delivery. She suspects the proxy may affect it and cannot confirm the expected stream in the browser inspection.

A locally running application still calls Azure in this setup. Pamela also adds Ollama support to samples where possible, allowing local development against smaller models such as Phi-3 or Llama 2. That changes the model as well as its location, so the resulting answers can differ from the Azure-hosted model’s behavior.

Pamela compares Bicep with Azure’s JSON-based ARM templates and names Terraform as another way to describe infrastructure. During deployment, select the sponsorship subscription and a hosting region.

The packaging step builds a Docker image. Its Dockerfile installs the application requirements and defines how to run the server. The first two templates deploy to Azure Container Apps; App Service, Functions and Kubernetes are other Azure hosting options. 08

在生成答案之前先检索商品行

A general chat model can produce plausible text about a domain without knowing the facts of a particular business. Retrieval-augmented generation, or RAG, gives it relevant source material at answer time:

1. Receive the user’s question. 2. Search a database or search index. 3. Put the retrieved results and original question into the model prompt. 4. Ask the model to answer from those sources.

The quality of the retrieved evidence matters because the model synthesizes what it receives. A fluent answer cannot repair missing or irrelevant source material.

The RAG on PostgreSQL template applies that flow to an existing product table. Think of a retailer whose customers ask which products meet their needs. The database returns matching rows, and those rows become the source material for the answer. Pamela demonstrates an outdoor footwear catalog; the application’s “thought process” view exposes the search query, retrieved rows and answer prompt. It is a diagnostic view of the application’s retrieval steps.

The retrieval step combines pgvector similarity search with PostgreSQL’s built-in full-text search. Vector retrieval searches through embeddings; full-text retrieval searches the words in the indexed content. Pamela recommends combining them and cites hundreds of evaluations behind her concern about vector-only retrieval. The final model call is straightforward: instruct it to answer from sources, then provide the question and matching product rows. The later Q&A returns to why the way those results are combined matters.

09

把对话式请求变成搜索约束

The advanced product flow first asks an LLM to rewrite the user’s question into a better search query. Conversational wording is not necessarily useful retrieval wording. In the first example, the rewrite returns the same query. The need becomes clearer in a follow-up such as “more options”: a search engine needs to know options for what, which requires context from the conversation. Pamela tries that follow-up, but the live PostgreSQL example does not establish the intended contextual rewriting behavior.

Query preparation can also produce structured constraints. For “I want climbing gear cheaper than thirty dollars,” the application uses OpenAI function calling to ask whether a price filter is appropriate. The model returns a less-than condition and a value of 30. The application constructs the SQL filter from that structure; it does not need to accept arbitrary SQL written by the model.

For the same climbing-gear request, a constrained Python filter builder can keep operators under application control and pass the price separately as a database parameter:

```python from decimal import Decimal

def build_price_filter(condition): operators = {"less_than": "<"} operator = operators[condition["operator"]] price = Decimal(str(condition["value"])) if not price.is_finite() or price < 0: raise ValueError("Invalid price") return f"price {operator} %s", (price,)

condition = {"operator": "less_than", "value": 30} where_sql, parameters = build_price_filter(condition) # where_sql: "price < %s" # parameters: (Decimal("30"),) ```

This produces a filter ready to combine with the product search; it does not execute a query. The model identifies the user’s constraint, while the application owns the allowed SQL structure and parameter binding.

10

评估检索组合，而不只是向量索引

Additional metadata enters text and vector retrieval differently. Mark an index field as searchable and full-text retrieval can search it; Pamela recalls the sample starting with three searchable fields. Vector retrieval only represents the content supplied to the embedding model. To include metadata in that representation, the application can combine it with the main text before embedding—a technique Pamela calls content stuffing or content expansion. Whether that helps requires evaluation.

Pamela opens Doing RAG? Vector search is not enough, her experiment using synthetic questions and GPT-4-generated ground truth about her blog. Groundedness was scored out of five:

| Retrieval configuration | Groundedness | | --- | ---: | | Vector only | 2.79 | | Text only | 4.87 | | Hybrid | 3.26 | | Hybrid with semantic ranker | 4.89 |

The 0.02 improvement over text-only search came from hybrid retrieval with the semantic ranker, not from simply adding vectors. The author flags possible lexical bias in the generated evaluation material, and the supplied account does not establish the full run configuration or statistical uncertainty. These conditions matter when interpreting the table.

Why can combining two retrieval methods make results worse? A nearest-neighbor vector search can return the closest available matches even when none is particularly relevant. Combining those candidates with text results through basic reciprocal rank fusion can introduce distracting sources into the answer prompt. Pamela warns that LLMs are susceptible to that distraction. Azure AI Search’s semantic ranker adds a learned reranking step against the query; in her experience, that step is what lets vector-inclusive retrieval match or improve on full-text search. The engineering task is to evaluate the complete retrieval pipeline, including how results are combined and reranked.
