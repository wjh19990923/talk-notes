构建并部署 AI 驱动的应用

从带时间戳的恐龙视频到一个持久的书架目录，Paige Bailey 演示了模型、事实依据、可执行工具和应用基础设施如何协同工作。

对模型 API、提示词和 Web 应用有基本了解会有帮助；示例使用 Python 和 TypeScript。

01

哪个模型应该放进应用？

一个应用既要看懂视频、检索事实，又要生成媒体、保存用户数据，模型该怎么选？先弄清每个组件要干什么活。Paige Bailey 开场时介绍了自己：她是 Google DeepMind 开发者关系工程负责人，2009 年开始做机器学习，给 NumPy、SciPy 和 scikit-learn 都贡献过代码。她从工程转到产品、又回到工程，这段经历说明，设计、构建和讲解这类应用，这三件事越来越分不开。

这次发布的模型各有分工。Gemini 3.1 Flash Live 负责实时交互；Gemini 3.1 Pro 和 Gemini 3.1 Flash Lite 在能力、成本和延迟上各有取舍。Bailey 举了 Augment Code 的例子：对方看中 Pro 的性能和成本，按她的说法是把默认模型整个换掉了。不过 Augment 公开发布的文章（后来有过更新）写的是在其他供应商之外加入 Gemini，并没有整套替换。

- 图像与检索： Nano Banana 2 负责生成和编辑图像。视频、图像、音频、文本和代码共用一个多模态嵌入空间：搜“猫”，能同时搜出猫的视频、猫打呼噜的音频和讲猫的书。 - 生成媒体与世界： Lyria 3 生成音乐；Genie 3 生成可交互的世界。 - 应用与部署选项： AI Studio 的全栈运行时加上了数据库和 OAuth。Gemma 4 是一组开放模型，Veo 3.1 Lite 负责视频生成。

输入输出模态决定了应用架构。 Gemini 能读入视频、图像、音频、文本和代码，也能读内嵌图片的 PDF 这类文档。输出取决于所选模型，可以是文本、代码、音频、图像，或图文交错的内容。Bailey 拿这种广度跟另一些系统对比：它们只能输出文本和代码，或者只能输入静态图片。落到实处，就是看应用需要哪种组合，再选能支持它的模型和接口。

02

把一段恐龙视频变成一张带引用的表格

Google AI Studio 是交互式的起点。Bailey 用个人 Gmail 账号登录，通过模态筛选器挑模型，为了速度选了 Flash Lite。工具面板里有结构化输出、代码执行、函数调用、Google Search grounding、Google Maps grounding 和 URL context。URL context 把指定的网页放进模型可用的上下文；搜索和检索则补上训练数据里可能没有的信息。

第一个具体任务：认出一段恐龙视频里的各种生物，并配上有用的知识。AI Studio 接受多种媒体来源：Drive、本地上传、录音、摄像头、示例素材或 YouTube 链接。有了 YouTube 视频输入，Bailey 直接贴 URL 就行，不用先下载再上传。加视频之前，她先打开了 Google Search grounding。

她选的区间是 0–300 秒，按界面默认的每秒一帧采样。这段五分钟的视频输入，AI Studio 显示约 27,600 个 token。这只是本例显示的总数，token 怎么算取决于媒体配置。她的请求是：做一张表，列出视频里的恐龙种类和出现的时间戳，每种再配一条趣味知识。

选恐龙这个主题，是因为 Bailey 复活节刚出去玩过：穿着恐龙服，骑三轮车冲下旧金山一段弯弯曲曲的山坡。在这次请求里，视频提供视觉证据，Google Search 为趣味知识提供佐证。结果认出了 Rexy 和它的父母、腕龙、迅猛龙和无齿翼龙，还顺带做了一个有用的纠正：无齿翼龙属于翼龙，不是恐龙。来自外部的知识都附了引用。

Get Code 是从实验走到应用的桥梁。 它能导出所选模型、YouTube URI 的处理方式和提示词，支持 Python、TypeScript、Java 等语言。同样的流程也可以换成自己的视频，不必用 YouTube 链接。Bailey 接着演示了思考档位：minimal、low、medium 和 high。为了让交互延迟低，她通常选 minimal 或 low。档位越高，花在推理上的 token 越多。她的建议是：先试试 Flash Lite 的速度和成本，再考虑上更大的模型。

03

给小模型可执行的视觉工具

代码执行给 Gemini 配了一个托管的 Python 沙箱，预装了常用的数据科学库。生成的代码在沙箱里跑，不在开发者本地跑。Bailey 在对比模式的两侧都打开了它：一侧是 Gemini 3.1 Flash Lite Preview，另一侧是 Gemini 3 Flash Preview。

两个模型拿到同一张乐高照片、同一个任务：用 Python 给每块绿色积木画上边界框，再显示标注后的图片。Bailey 说这张图大约占 1,000 个 token。Flash Lite 先出结果：它生成 Python 代码，加载图片、分析图片、确定框的位置。显示的结果里框出了两块绿色积木。

这类按颜色定位的任务，用一小段 Python 就能实现，分三步：颜色掩码、连通区域、最终绘制。下面的代码用色相阈值挑出绿色像素，先按面积滤掉小区域，再给剩下的每个区域画外接矩形：

```python import cv2

image = cv2.imread("lego.png") if image is None: raise FileNotFoundError("lego.png")

hsv = cv2.cvtColor(image, cv2.COLOR_BGR2HSV) mask = cv2.inRange(hsv, (35, 60, 40), (85, 255, 255)) contours, _ = cv2.findContours( mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE )

annotated = image.copy() for contour in contours: if cv2.contourArea(contour) < 100: continue x, y, width, height = cv2.boundingRect(contour) cv2.rectangle( annotated, (x, y), (x + width, y + height), (0, 0, 255), 2 )

cv2.imwrite("green-bricks.png", annotated) ```

这些阈值只是按颜色识别时的一种实现选择，挨在一起的积木可能被并成一个区域。更值得关注的是背后的机制：模型能把自己的理解变成可执行的操作，再交回一个可以检查的结果。

Bailey 说，Flash Lite 跑这次乐高任务，花费远不到一美分。她还提到，同一个工具也能用来做分割掩码，或者数出指定的物体。Gemini 3 Flash 最后也得出了同样的答案；Bailey 说它用时更长、花费略高，但仍不到一美分。这些观察只针对演示的这两次运行，两个模型都开了代码执行。

把屏幕、语音和摄像头放在同一段对话里

Gemini Live 能在动态对话中接收屏幕共享、视频和音频，还支持自定义函数调用、自动函数响应和 Google Search grounding。Bailey 打开搜索、共享屏幕，问模型看到了什么。模型描述了屏幕上的 Google 乐高积木图片搜索结果，连右侧那张较大的图也讲到了：上面有红、黄、蓝、绿四色积木。

接着她请一位会说意大利语的观众帮忙，让 Gemini 用意大利语把刚才的描述再说一遍，顺便问问伦敦当天的天气。Gemini 用意大利语讲了乐高画面，又报了天气：多云，可能有雨。那位观众认可了这段意大利语。Bailey 又让它用得州口音，就同一个屏幕写首诗。模型换了说话方式，内容还是围绕画面。语言、任务和说话风格，都能在同一段对话里随时切换。

放到实际产品里，可以是银行门口的自助机：访客用什么语言开口，它就用什么语言回应。如果产品要求固定的语言、方言、口音、风格或语气，Bailey 建议写进 system instructions（系统指令）。对话里的请求提供灵活性，系统指令则规定应用该有的行为。Get Code 会导出 Live 的配置，包括媒体分辨率和压缩设置。

然后她切到摄像头输入。Gemini 认出她竖起了两根手指；手势一变，又认出是竖大拇指。Bailey 拿这种一体化交互，对比另行拼装语音转文字、LLM、文字转语音和视频处理的做法，并说 Live 成本更低。架构上的好处在于：这些输入和响应都发生在同一段持续的交互里，开发者不必逐个环节自己协调。

要一个带认证和存储的书架目录应用

AI Studio Build 把模型实验推进到应用。Bailey 拿它跟 v0 和 Lovable 类比：创建、编辑、分享、部署一个应用，支持数据库和 Google 登录，还能安全保管自定义 API 密钥。Gallery 里有 Guillaume 的 Lyria Studio、几个 Nano Banana 示例，还有一个靠摄像头追踪手部来操控的 MediaPipe 游戏。每个应用的源码都能查看。

新建应用时，她选了 Firestore 和 Firebase Google 身份验证，然后用麦克风口述需求：

1. 让用户上传一张书架照片，书脊要拍得清楚。 2. 识别书名和作者，用 Google Search grounding 补上简介和分类。 3. 要求用户用 Google 账号登录。 4. 把这位用户的书目存进数据库，持久保存。

这个应用要把视觉识别、外部信息补充、身份认证和持久存储组合到一起。

需求里的数据可以写成一个小小的 TypeScript 契约。把所有者和书籍元数据分开，“按用户保存”这条要求就一目了然：

```typescript type Book = { title: string; author: string; description: string; category: string; };

type Catalog = { ownerId: string; books: Book[]; };

function createCatalog(ownerId: string, books: Book[]): Catalog { if (!ownerId.trim()) { throw new Error("A signed-in user is required"); } return { ownerId, books: books.map((book) => ({ ...book })), }; } ```

这段代码描述的是要交给持久层的数据；要真正保证数据归属，还得靠数据库的访问规则。演示到这一步，书目和持久化都还只是提出的需求，应用并没有建完。

Bailey 感叹，放在几年前，光这个需求就够撑起一家创业公司。说完她点了 Build。Gemini 3.1 Pro Preview 开始规划应用、数据库和身份验证的搭建。她去演示其他模型时，这些工作在后台继续跑；需要她处理时，会响起提示音。

在一个以像素生成的世界中漫游

趁应用还在构建，Bailey 打开了 Project Genie。用户先用文字描述环境和角色，然后开始探索；它背后的 Genie 3 世界模型会随之动态生成画面。WASD 控制移动，方向键调整视角，空格键执行其他动作。Bailey 强调，这套体验底下没有传统的 Unity、Unreal 或物理引擎。

预览里出现了乐高岩层，鸵鸟还多长了一双肌肉发达的胳膊。Bailey 创建了这个世界，操控角色在岩石间穿行，切换视角，朝一处峡谷走去，希望能找到一条河。探索结束时，她想跳过峡谷，没能跳成。她还提到一位没具名的同事做过的例子：一条鱼想从厨房里逃出去。据她说，在这场工作坊举办时，Genie 3 还没有公开 API，团队正在考虑推出受信任测试者计划；通过 Ultra 订阅使用，也只限部分国家。

在你周围的系统中把规划与行动分开

结尾的机器人示例把一条架构边界讲得很清楚。Bailey 介绍了 Pupper：一款基于 Raspberry Pi 的开源机器人，零件可以自己打印，用 Gemini 识别物体、对周围环境作出反应。Stanford Pupper 控制代码仓库介绍了这一系列机器人的背景。按她描述的架构，Gemini Live 负责理解灵活的指令、制定计划，再调用机器人本地的模型去执行动作，比如捡起一样东西。机器人的动作并不由它直接控制。
