New Ways of Working with Codex

Dominik Kundel and Charlie Guo connect Codex to the places where work already happens. Their demos follow context from Slack to a spreadsheet, turn a web preview into a place to give feedback, and hand video footage to a remote editor that returns a new cut for review.

01

Where the Codex harness runs

The first version of Codex checked out a repository in its own cloud environment and did the work there. At CODE Summit 2026, OpenAI’s Charlie Guo and Dominik Kundel returned to the practical question behind that setup. Where should a task run if it needs to keep going after you close your laptop? The options they showed included steering Codex on another machine you control and provisioning an environment in Codex Cloud.

The Codex harness is the runtime behind the agent. Guo credited its integration with ChatGPT Work with making long-running agents available to tens of millions more people. The same harness also powered the CLI, the ChatGPT integration in Slack, Dots, and the Agents API. A connection made in one of those interfaces can matter in another, as the first examples show.

02

Give Codex somewhere to look when the request is short

OpenAI’s monorepo gave Codex an early problem. Before the agent could make a change, it had to find the right code in a large repository and learn how that repository worked. A repo can carry its coding conventions in AGENTS.md, linters, and other tools. Kundel’s idea of “vague prompting” builds on that ability to look things up. A short request can leave details implicit when the agent has access to the context a colleague would use.

A plugin bundles MCP servers, skills, and other resources for a workflow. Most marketplace plugins Kundel described used remote MCP servers, so the service connection could follow the user across Codex interfaces. Connect Slack in ChatGPT on the web, for example, and Codex on the dev box or the @ChatGPT integration in Slack can draw on that connection. Teams can also share plugins internally or publish their own marketplace on GitHub.

In one request, Kundel left the Slack channel and the person’s identity implicit. Codex had a place to look for the conversation where he’d been tagged. It also had a Google Drive connection that could open the spreadsheet shared in that conversation. The example shows what the two connections made available. The outcome of that particular request is unknown.

A midnight documentation release put those connections to work against a deadline. Kundel prepared the pull request with Codex and asked it to pursue approval and watch the launch channel for late changes. If the plan held, it was to start deployment 20 minutes before midnight, the lead time the deployment needed then, and check that the update was live. The day before, a coworker asked about the changes and the preview URL. Codex replied on Kundel’s behalf, and the coworker said it looked good. Four minutes after midnight, Codex reported that the site update was live.

03

Put a design-system component into the prompt

Plugin extensions give people a place to work with connected context. An extension can add a sidebar entry, side panel, or full page. It can also extend the file viewer or composer. Some of the built-in Codex pages, including Sites and Code Review, use the same extension mechanisms.

Kundel gave Codex the company design system and asked it to build a component browser in a single prompt. What goes into a draft when you pick a component? In the demo, he chose the actions dropdown and clicked Add to composer. The draft gained the context for that component, so the next request could refer to the dropdown he had chosen. Design-system demo at 11:19

The composer offers a second route. Mention the design system, open its search control, and pick a component while drafting. The same extension point can offer autocomplete for Figma files.

04

Capture an app, operate it, or recall earlier work

An Appshot pairs a screenshot with information from the app’s accessibility tree. Press both Command keys on macOS or both Alt keys on Windows. The first capture may ask for permissions. What comes through beyond the pixels? In the demo, View text revealed values and text alongside the image. That payload can include items outside the visible viewport when the app exposes them in its accessibility tree. Appshot demo at 14:13

Computer use lets Codex operate an interface when a task calls for more than a capture. On macOS, it can run in the background with its own cursor. The example showed it operating an iOS simulator as part of app testing. For work inside the browser, the Chrome extension can use the browser’s signed-in context in the background on Windows, Linux, and macOS while you keep working in other tabs.

Computer history, available on macOS at the time of the talk, starts building a record after you enable it in settings. It draws heavily on Mac event streams, which take less time and fewer tokens to process than screenshots. Codex can use the record to find a document you had open earlier or pick up a habit over time. Kundel used his shift from drafting blog posts in Google Docs for review to drafting in ChatGPT Space as an example of a changing habit that can inform Codex memories.

You can pause history before opening a sensitive document, clear a recent stretch of activity after opening it, or exclude an app or website entirely. Private browsing was already excluded in the setup Kundel described.

05

Keep a plan editable in ChatGPT Space

A feature plan might draw on a product brief in Docs or Notion, architecture diagrams in a repository, and customer feedback in a spreadsheet. Once Codex drafts the plan, checking it into the repo gives teammates a pull request to review. Copy the plan into a Google Doc for easier editing and the team has another version to reconcile with the repo.

Codex can turn the draft into an editable rich-text page in ChatGPT Space. A reviewer can tag ChatGPT to ask whether the plan should use an existing database structure. A teammate can respond on the page or bring in their own ChatGPT or Dot. An agent’s cursor can appear as it edits, and the same page can hold embedded visualizations.

An on-call runbook gives page-level assistant instructions a concrete job. When a command changes, the instructions tell the agent how to maintain the page when it edits. With auto-update enabled, they can also guide a regularly scheduled update. Kundel compared them to an AGENTS.md for an individual page.

06

Iterate on the music page with Ultrafast and annotations

A faster model turn pays off when you need to see an edit before you know what to ask for next. Kundel described Ultrafast as eight times as fast at six times the cost. The gain in total turnaround depends on where the time goes. An iOS build, a game compile, or an end-to-end test can still dominate the wait. For small web edits, he used light reasoning and a hot-reloading dev server so that changes would appear in the preview as soon as the code was saved.

In the in-app browser, you can annotate an element to give Codex a target or use the settings control to try a tweak directly in the live page. Kundel began by asking Codex to remove a header and its button from a music site. A first turn can take a little longer while Codex reads files to get oriented. He then asked for the remaining header to go full screen and narrowed the request to full width with normal sizing elsewhere. Music-page demo at 23:23

The next requests added background animation and made the LP look more like vinyl and spin. Kundel called out a five-second restore and another turn that took about ten seconds. Seeing the record spin prompted one more idea. Could you scratch it with the cursor? The preview showed that you could. He also pointed at text and asked Codex to make it more readable. The annotation supplies the location that a phrase like “all of these” leaves implicit.

The night before DevDay, Kundel used the same approach on a ChatGPT Space documentation page. He wanted the feature explanations to be more engaging and worked out what that meant by queuing small changes and looking at each result. The finished feature demos rendered directly in the page as HTML.

By default, the browser uses the DOM, the page’s element tree, to decide what it can select on hover. The annotations API lets an app define its own targets. A Storybook gallery could make individual components selectable while leaving the surrounding frame out. The ModRetro plugin used the API to let people mark up content inside the emulated game while keeping the emulator interface outside the selectable area.

07

Set up Codex Cloud with a web repo and a mobile repo

A task that runs for hours or days needs a host that stays up after you close your laptop. A Mac mini, an old laptop, or a rented VPS can do the job. Each needs updates, disk space, and enough capacity for the tasks you run together. In Connections, Kundel showed how a phone could control a linked dev machine through a ChatGPT subscription. He also described SSH for setups using API keys or machines already on the same network.

In the revamped Codex Cloud, you start in the composer and choose one or more GitHub repositories for a personal or shared environment. A hosted VM clones them. A setup task inspects the projects to identify dependencies, credentials the project may need, and commands to run a dev server or verify tests. You can edit the resulting configuration.

Kundel chose Blossom Music and Blossom Music mobile. While setup ran, he opened an earlier result for the same pair. What could a Linux VM do with an iOS repository? Setup flagged that it could neither build nor launch the iOS app and kept the checkout for reference. That fit Kundel’s intended task. Codex could read a feature’s mobile implementation when adding it to the web player. Running the iOS app would still require a suitable host. Support for bringing your own hardware was in development. Blossom Music setup at 32:57

Back in the live run, Codex had begun writing an install script. A snapshot gives later tasks a prepared environment to start from, even after hours of inactivity. On a separate background cadence, Codex can refresh dependencies and pull branch updates from a branch such as main.

08

Connect private services and reach a headless dev box

Environment settings let you control web access and attach a shared secret or ask each user to supply a key. Kundel described two ways to give a cloud environment access to private resources.

- OIDC for cloud identity. The environment can use OIDC with a cloud provider that supports it. - Tailscale for network access. Configure the environment’s connection with a Tailscale key. Its tasks can then reach HTTP services over the private Tailscale network.

On a host you operate yourself, the Codex CLI’s remote-control start command launches the app server. Your phone then connects to the harness on that dev box or cloud host. The machine doing the work can run headless with just the CLI installed.

09

Send footage to Codex and get a new cut back

Cutroom, the developer experience team’s internal ChatGPT Site, takes over after filming. What does a reviewer send to the editor? The team or videographer uploads the footage. Reviewers can watch it, leave comments, and add screen recordings or B-roll. Marking the submission ready for review hands those inputs to a remote Codex agent. Cutroom at 37:38

The agent uses DaVinci Resolve and video-editing skills to make a new cut, uploads it to Cutroom, and tells the team it’s ready. The team can review the new version where it left feedback. Guo recalled that Astra handled the full edit on several secondary launch videos through this workflow.

ChatGPT Sites supplies D1 for the database, R2 for files and objects, and Sign in with ChatGPT for authentication and user management. Sites also supports secrets, plugins, and analytics. An app can use the signed-in identity to decide who can open the site or which features a user can access. A team can give different audiences different views of the same work.

The team was working on a version of Cutroom that would also cover a step before filming. A Google Calendar plugin would let people book the filming space on a shared calendar. Guo also described using Linear from a site to show open work or create and assign tasks. A team that wants its own version can remix a site by copying and adapting it.

The social team used a site as an iPhone-style viewer for published posts. As a reader scrolled through the posts, they could see each one’s analytics alongside it. Other teams used the format for an eight-bit launch recap and a set of book-like volumes about merging architectures.

Where does each part of a Cutroom revision happen? Submission starts the editing job and supplies the media and notes. The new cut returns to the site, while the notification tells the team when to look again. - Video team — Reviews footage, leaves comments, and supplies supporting clips. - Cutroom — Collects the submission and receives the returned cut. - Remote Codex agent — Edits the footage using the review inputs. - Editing tools — DaVinci Resolve and video-editing skills. - Video team → Cutroom (Adds material and marks it ready) - Cutroom → Remote Codex agent (Starts the job with footage and review inputs) - Remote Codex agent → Editing tools (Uses to edit the footage) - Remote Codex agent → Cutroom (Uploads the revised cut) - Remote Codex agent → Video team (Notifies the team that the cut is ready)

10

Race from Frida Kahlo to Rubik’s Cube

Guo built a wiki race to try Astra’s computer use. Both racers start on one Wikipedia article and try to reach the goal article by following links. His ChatGPT Site called the Agents API with an API key in the background and gave Astra computer use for navigation. The starting page was Frida Kahlo. The finish was Rubik’s Cube.

What connection gives each racer a way toward the cube? Guo, on the right in orange, tried to get to Christmas and find a route through toys. Astra picked up on the Hungarian connection before Guo did and won the race. Across informal playtests, Guo estimated that he won about half the time. Wiki race at 42:37

11

Start an agent review from a pull request

With GitHub connected, the Code Review tab lists pull requests you opened or were assigned to review. In the example, the author included screenshots of the proposed change, including mobile views. The reviewer can inspect how the change looks, open the code diff, and follow links back to GitHub from the same view.

Review with Codex opens a separate thread with a prewritten prompt you can customize to focus the review. A sub-agent checks the pull request and is meant to return its findings in that thread. Guo started a review and left it running while he moved to the Voice demo.

12

Use Voice to steer work across threads

Guo uses Codex Voice as a “control plane” for the app. One conversation can check an existing task, pull information from another app through computer use, or start a separate thread. When the room couldn’t hear the first response, he switched to the laptop’s built-in audio. He then asked Codex to check the pull request review, find the latest from a colleague in Slack, and start a new thread to critique the presentation slides. He wanted the slide thread pinned after the critique.

Codex came back with a question about the Slack request. Several people had the same first name, so it asked which person Guo meant. The demo moved on before any of the three results came back. In everyday work, Guo sometimes keeps Voice active to direct the app and lets edits and delegated tasks continue in the background while he carries on with his work.

13

Delegate through Dots or embed the harness in an app

Dots felt awkward to Guo at first. He was used to starting tasks himself in Codex, and he found uses for Dots in the work already coming at him during the day.

- Proactive alerts. The presenters’ Dots flagged a bug in a pull request, a merge conflict, and a calendar overlap. One Dot also spotted that a discussion in a Slack channel Guo was absent from had made his pull request out of date and prompted Kundel to tell him. - Forwarded tasks. Guo forwards Slack messages to his Dot with a short instruction to look into something or create a to-do. The forwarded message carries the context into the task. - Phone and messaging. The team aimed to make Dots reachable across ChatGPT, Slack, and Teams, as well as through calls and messaging services such as iMessage or RCS.

The Agents API brings the harness into applications such as the wiki race. The API was in beta at the time of the talk. Guo described it as a way for an application to create hundreds or thousands of short-lived sessions with access to capabilities such as sandboxes and plugins.

14

Match reasoning effort and delegation to the work

Kundel used light reasoning when he wanted fast turns on the web preview and suggested high reasoning as a starting point for general work. When a new model comes out, he tries tasks that used to need extra-high effort at high. Extra effort can bring diminishing returns and make a simple job take longer.

One configuration puts Sol on medium in charge of the main task. A skill can tell it to ask Astra on high for help when it gets stuck or send tedious work that can be split up to Luna sub-agents on high. The main model still has to decide when to bring in help. It can choose poorly, so delegation can cost more or produce a worse result.

Peer sub-agents can work in parallel when some decisions still need to move between assignments. In Kundel’s example, one agent builds the web app, including its frontend and backend, while another builds the mobile app. The web agent can tell its peer about a backend change that affects the mobile client. The mobile agent can send back a decision that requires a backend change. Those exchanges let both agents keep implementing while the details are still changing. Codex has to identify which decisions the peers need to share.

Sub-agents belong to a main session. Codex or a Dot can also start independent chats that you can open and steer directly. That lets you launch several tasks from one coordinating thread and continue each one in its own conversation.

15

Switch tasks from the CLI and revisit old workarounds

In the CLI, the left arrow opens the agents view so you can switch sessions. That comes in handy over SSH when several tasks are running on the same dev box. The CLI also supports Voice. In the desktop app, you can set custom shortcuts and use global hotkeys to start Voice or dictate into another app without switching windows.

Kundel also pointed to Daybreak Blue as a program for securing your own applications. He described individual access as requiring a hardware security key such as a YubiKey.

Kundel’s last tip was to give a new model a familiar task with a simpler setup. Put back the instructions and workflow steps when you find the problems they used to solve. If the model can now handle a step on its own, that’s one less thing to maintain.

要点总结

  • A short prompt shifts some of the work to finding context. The Slack and Drive example shows how references can cross tools. The Voice demo shows what happens when the available context still leaves the person ambiguous.
  • Shorten the part of the wait that matters. Hot reload brings a fast model turn straight into the web preview. A prepared cloud snapshot saves environment setup on later tasks. An iOS build still needs a host that can run it.
